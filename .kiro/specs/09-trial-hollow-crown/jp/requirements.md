# 要件: 試練6「The Hollow Crown」（ぜんぶ つかう）

> 和訳です。**正本は英語版** [`../requirements.md`](../requirements.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・要件ID（`REQ-9.n`）・不変条件ID（`INV-n`）は原文のままです。

spec `09-trial-hollow-crown`。6つの試練の最後です。新しい学びは足さず、L1〜L5（`docs/learning-design.md`）を、助手との本当の仕事の進み方のように、ひとつながりの手順にまとめます。要件IDは `REQ-9.n` です。`REQ-8.n` は `08-trial-tell-whats-wrong`、`REQ-7.n` は `07-trial-keep-secrets`、`REQ-6.n` は `06-trial-verify-stars`、`REQ-5.n` は `05-trial-grant-tools`、`REQ-4.n` は `04-score-attack`、`REQ-3.n` は `03-trial-tell-vague-request`、`REQ-2.n` は `02-trial-tell`、`REQ-1.n` は存在しない `01-core-loop` のもので、どれも再利用しません。

既存の基盤の上に6つ目の試練を足します。試練1〜5の作り直しではありません。レーン、小屋、畑、影、ランタンは、それぞれの流れ、時計、得点、終了画面をそのまま保ちます。試練1〜5と違い、試練6は60秒のスコアアタックではありません。時計も得点もなく、町の3つ目のランプが灯ったときに一度だけクリアになります。クリア画面には「もういちど あそぶ」があり、「タイトル」ボタンも残ります。ほかの試練の終了画面と同じ流儀です。

## なぜ作るか

`docs/learning-design.md` は試練6を「tell → grant → act → verify → fix を3回つなぐ。段を飛ばすとうまくいかない。連鎖が町に灯りを戻す」と書いていました。教える欄は L5 ができる前に書かれた L1–L4 です。この spec はその行を埋め、L1–L5 にします。

町の3つのランプは消えています。町の丘のランプの冠（クラウン）が空っぽ（ホロウ）なのです。ランプごとに、子どもには「ほしい ランプ」（やねとあかりのあるランプ）があり、ウィスプと5つの段を進みます。

1. **いう**（L1）：やねのカードとあかりのカードを1枚ずつ選び、ウィスプに伝えます。片方だけなら、ウィスプはもう片方をたずねて待ちます。
2. **わたす**（L2、L4）：部品は小屋の中にあり、扉を何かがふさいでいます（落ち葉、板、ロープ）。子どもの前には3つあります。それを片づける道具、別の仕事の道具、そしてひみつ（家の鍵、住所、合言葉）です。子どもはひとつ渡します。ひみつは道具ではなく、守るものです。渡しても連鎖は進みません。
3. **たのむ**（助手は頼まれるまで何もしない）：子どもはウィスプに行ってと頼みます。ウィスプは渡された道具をそのまま試します。合う道具なら小屋が開き、ウィスプはランプを作ります。合わなければ扉はふさがったままで、子どもはもう一度渡します。
4. **みる**（L3）：ウィスプは言われたとおりに作りましたが、1か所だけうっかり違うものにしました。子どもはランプをほしいランプと見比べ、「おなじ」か「おなじじゃない」かを言います。受け入れられるのは、おなじランプだけです。
5. **なおす**（L5）：子どもは違う部分をタップし（どこ）、あるべき見た目を選びます（どう）。ウィスプはその部分だけを変え、子どもはもう一度見ます。ランプ全体を頼み直す方法はありません。

ほしいランプと同じランプに「おなじ」と言うと、ランプが灯り、町のランプがひとつ点きます。3つ目のあと、町は明るさを取り戻し、試練はクリアです。

要点は、どれか一つの段ではなく連鎖です。どの段も、前の試練で子どもがしたことです。ここではそれが順につながり、どの段も前の段を必要とし、どれも飛ばせません。ウィスプは言われたとおりにし、ときどきうっかりする助手です。うそつきでも敵でも、まぬけでもありません。暗いもの、こわいもの、おどかすものはありません。消えたランプは、灯されるのを待つ夜の町で、危険ではありません。

## 用語

- **クラウン**：試練6の場所 The Hollow Crown。夜の町で、3つのランプが消えている。
- **町のランプ**：画面の下にある3つのランプ。連鎖をひとつ終えるごとにひとつ点く。
- **連鎖（チェーン）**：ひとつのランプのための5つの段。いう、わたす、たのむ、みる、なおす。試練には3つの連鎖（`chain` 0、1、2）がある。
- **部分**：ランプの2つの部分。上から**やね**と**あかり**。見た目は試練5のもの。やねは とんがり・まる・たいら、あかりは ろうそく・ほし・つき。
- **ほしいランプ**：この連鎖で子どもがほしいランプ。専用のパネルに描かれ、連鎖のあいだ変わらない。
- **伝えたランプ**：「いう」段で子どもが選び、ウィスプに伝えた見た目。
- **仕事**：この連鎖で小屋の扉をふさいでいるもの。落ち葉（ほうきで片づく）、板（ハンマー）、ロープ（はさみ）。1回の訪問でそれぞれ一度ずつ。
- **もの**：「わたす」段の3つのタイル。仕事の道具、別の仕事の道具、ひみつ。
- **ひみつ**：家の鍵、住所、合言葉（試練4のひみつ）。
- **作ったランプ**：合う道具のあとにウィスプが作るランプ。伝えたランプと同じだが、1か所（**うっかりの部分**）だけ、伝えた見た目でもほしい見た目でもないものになっている。
- **みる（確かめる）**：ウィスプがいま持っているランプについて、子どもが「おなじ」か「おなじじゃない」かを言うこと。
- **なおす**：部分を指し（どこ）、カードを選ぶ（どう）こと。2枚の**カード**は、その部分がいま持っていない見た目。
- **灯る**：「おなじ」と言い、ランプがほしいランプと同じだったとき。その町のランプが点く。
- **クリア**：3つのランプが灯った。試練は終わり、クリア画面が出る。
- **シード**：試練6を開くときにゲームが引く整数（domain ではない）。同じシードなら、いつも同じほしいランプ、仕事、もの、うっかりになる。

## 要件

### REQ-9.1 タップでクラウンに入る

6歳の子どもとして、最後の試練を指でタイトルから開きたい。大人がいなくても遊べるように。

1. タイトル画面に、試練6のための5つ目のタップ領域を出す。灯ったランプの絵と、子どもの言語の短いラベルのあるボタンで、ゲーム座標で 80 x 80 以上。試練1のカードとタイトルのウィスプ・主人公のあいだに置き、カード・絵・ほかの4つのボタンと重ならない。
2. タップすると試練6が新しいシードの連鎖0の「いう」段で開く。状態は `title` から `trial` へ、`trial` は6。run、レーン、小屋、畑、影、ランタンは触れない。シードはゲームが（domain の外で）引き、イベントで送る。domain は何も引かない。
3. このボタンのタップが試練1を始めたり試練2〜5を開いたりすることはなく、ほかのボタンのタップがクラウンを開くこともない。タイトルのほかの場所のタップは、真ん中 (195, 422) も含め、これまでどおり試練1を始める。
4. 入口はふつうの画面のふつうのタップ。審査用URL、隠しジェスチャー、コンソール、クエリパラメータではなく、最初の訪問から開いている。試練1〜5を遊んだかどうかを待たない。
5. 試練選択画面も汎用ルーターもない。新しい画面はクラウンだけ。
6. タイトルの文はどれも、並んでいる試練と合っている。5つ目のボタンのキャプションは、ランプが3つであること（60秒ではないこと）を言う。ラベルに数字はない。

### REQ-9.2 画面に出るもの

1. 画面には上から、5つの段の列（REQ-9.3）、ガイド、専用パネルのほしいランプとその横のウィスプのパネル（それぞれラベルつき）、メッセージ、その段の操作、ウィスプ、町の3つのランプ、「タイトル」ボタン（REQ-9.10.4）が出る。時計、バー、得点はない。
2. ガイドは、子どもがいる段でする短い指示ひとつで、2行まで。
3. ほしいランプとウィスプのパネルは同じ描き方・同じ大きさで横に並び、やねとあかりが同じ行にあるので、子どもは行ごとに見比べられる。ほしいランプはいつも灯った姿で描き、タップ対象ではない。
4. ウィスプのパネルは段によって、それまでに伝えたもの（いう）、仕事のある小屋と、わたしたあとはウィスプが持つ道具（わたす、たのむ）、ウィスプがいま持っているランプ（みる、なおす）、チェックのバッジつきの灯ったランプ（灯る）を見せる。
5. ウィスプはどの段でも、いつもの親しげな顔で画面にいる。怒った顔、ずるい顔、こわがる顔、傷ついた顔にはしない。
6. 町の3つのランプは、その連鎖が灯るまで消えていて、灯ったあとは点いている。明るさや色だけでなく形で伝える（灯ったランプには光の線とチェックのバッジ、消えたランプには点の輪）。

### REQ-9.3 連鎖とその順番

6歳の子どもとして、いまどの段かを見たい。次に何をするかがわかるように。

1. 連鎖は5つの段で、いつもこの順番。いう、わたす、たのむ、みる、なおす。なおしたあと子どもはもう一度みる。ランプを灯すのは「みる」だけ。
2. 連鎖を進めるのは、その段のイベントだけ。ほかの段のイベントは同じ状態を返す。段は飛ばせず、終えた段をあとの段のイベントでやり直すこともできない。
3. 段の列は5つの段をそれぞれ言葉で示す。子どもがいる段には実線の枠、この連鎖で終えた段にはチェック、まだの段にはどちらもない。なおしたあともう一度みるときは、「みる」が実線の枠の段で、「なおす」にチェックはない。
4. 連鎖の途中で「いう」段に戻ることはない。ウィスプに伝えたことはそのまま残り、最初からランプを頼み直す方法はない。
5. うまくいかない「わたす」（別の道具、REQ-9.5.5）は「わたす」段に戻り、伝えたランプは残る。

### REQ-9.4 いう（L1）

1. 「いう」段には、やね3枚とあかり3枚の6枚のカード（それぞれ見た目の絵と言葉）と、「いう」ボタンがある。
2. カードを押すと、その部分の見た目を選ぶ。同じ部分の別のカードを押すと置き換わる。選んだカードには部分ごとに枠とチェックがつく。選ぶだけではウィスプに何も伝わらない。
3. 両方の部分のカードがあるときの「いう」でウィスプに伝わり、選んだとおりの見た目で「わたす」段へ進む。
4. 部分が足りないときの「いう」では連鎖は進まない。ウィスプは、その部分をどの見た目にするかを一文でたずね、待つ。自分で見た目を選ぶことはない。
5. カードはどの見た目でもよい。ウィスプには、ほしいランプかどうかに関係なく、子どもが選んだものが伝わる。ほしい見た目でない伝え方は、ほかの違いと同じように「みる」で見つかり「なおす」で変わる。

### REQ-9.5 わたす と たのむ（L2、L4）

1. 「わたす」段では、ウィスプのパネルにこの連鎖の仕事のある小屋が出て、3つのものがタイル（絵と言葉）で出る。仕事の道具、別の仕事の道具、ひみつ。
2. タイルを押すとそのものを渡す。道具を渡すと、ウィスプがちょうどその道具を持って「たのむ」段へ進む。道具はまだ試さない。
3. ひみつを渡しても連鎖は進まず、ウィスプが使えるものは何も渡らない。メッセージは、それがひみつで道具ではないことを言う。時間も点も失わず、子どもはもう一度渡す。
4. 「たのむ」段では「おねがい」ボタンひとつでウィスプに頼む。押されるまで、ウィスプは「たのむ」段で何もしない。
5. ウィスプは持っている道具をそのまま試す。仕事の道具なら仕事が片づき、ウィスプはランプを作る（REQ-9.6.1）。別の道具なら仕事はそのままで、メッセージはどの道具を使い、まだ仕事が残っていることを言い、連鎖は何も持たない「わたす」段に戻る。
6. どのタイルがどこにあるかは連鎖ごとに変わり、「いつも同じタイル」は遊び方にならない。

### REQ-9.6 みる（L3）

1. 仕事が片づくと、ウィスプのパネルにウィスプが作ったランプが出る。伝えたランプで、1か所（うっかりの部分）だけ、伝えた見た目でもほしい見た目でもない。なので、ウィスプが作るランプがほしいランプであることはない。
2. 「みる」段では2つのボタンで子どもにたずねる。「おなじ」か「おなじじゃない」か。どこが違うかを画面は示さない。子どもは2つのパネルを見比べて見つける。
3. ほしいランプと違うランプに「おなじじゃない」と言うと「なおす」段へ進む。
4. ほしいランプと同じランプに「おなじ」と言うと灯る（REQ-9.9.2）。
5. ほかの2つの答え（違うランプに「おなじ」、同じランプに「おなじじゃない」）では連鎖は進まず、ほかも何も変わらない。メッセージは、よく見てひとつずつ比べるよう言う。時間も点も失わず、回数の制限もない。

### REQ-9.7 なおす（L5）

1. 「なおす」段では、ウィスプのランプの各部分が 80 x 80 以上のタップ領域になり、どこが違うかは何も示さない。
2. ほしいランプと違う部分をタップすると、そこを指す。その部分に実線の枠がつき、その部分の2枚のカード（見た目の絵と言葉）が出る。カードは、その部分がいま持っていない2つの見た目。
3. ほしいランプと同じ部分をタップすると、この部分はおなじなので、ほかをタップするよう一文で言う。カードが出ていたら閉じる。ほかは何も変わらない。
4. カードを押すのが一回の「なおす」。ウィスプは指した部分を、カードのとおりの見た目に変える。もう一方の部分を変えたり、別の見た目を選んだり、カードを直したり、新しいランプを作ったりはしない。連鎖は「みる」段に戻り、メッセージは子どもが言ったことを言う。
5. ほしい見た目でないカードを、ゲームが誤りとして指摘することはない。その部分はその見た目になり、「みる」で見つかる。子どもは何度でも指して伝え直せる。

### REQ-9.8 ウィスプは言われたとおりにした。責めない

1. 言葉は、ウィスプが作ったこと・したことと、子どもが言ったことを言う。ウィスプがまちがっている、悪い、ばか、こわれている、うそをついているとは言わず、わざとしたとも言わず、子どもも責めない。
2. 試練6の子ども向けの言葉には、内容テストの責める言葉・こわがらせる言葉のリストの語を使わない（試練5のリストに、試練6ではどこにも `ちがう` を使わないことを加える）。
3. 事実は隠さない。正しくない「みる」には、よく見るよう言う。合わない道具には、仕事が残っていると言う。ひみつには、ひみつだと言う。
4. 子どもに最初から頼み直すよう言うことはない。言葉は部分と見た目を指す。
5. 助手がいつも正しい・いつもまちがう、なんでも知っている、友だちや家族だ、ひみつを守ってくれる、本物のAIのように動く、と言ったりほのめかしたりしない（`docs/learning-design.md` の「教えないこと」）。5つの段、うっかり、合う道具がひとつなのは演出上の仕掛けで（`design.md`）、ゲームの中の主張ではない。
6. どの段でも、赤いもの、バツ、揺れ、音はない。

### REQ-9.9 ランプ、連鎖の順番、クリア

6歳の子どもとして、町全体を明るくしたい。最後の試練をやりとげられるように。

1. 試練6には時計も得点もない。`Tick` は何もしない。`trial` が6のあいだのどのイベントも、入るときも出るときも、`run` を変えない。子どもは好きなだけ時間をかけられる。
2. 灯ったランプはほしいランプの見た目で、パネルにチェックのバッジがつき、町のランプが点く。メッセージはランプが灯ったことを言う。「つぎへ」ボタンで、何も伝えていない次の連鎖の「いう」段になる。
3. 3つ目のランプが灯ったあとの「つぎへ」で試練はクリアになる（REQ-9.10）。3つのランプのほかにクリアするものはない。
4. ほしいランプ、仕事、3つのものとその場所、うっかりの部分とその見た目は、シードと連鎖の番号だけから決まり（決まった規則、ほかの乱数なし）、連鎖のあいだ変わらない。ほしいランプは前のものを繰り返さず（連鎖ごとに両方の部分が変わる）、1回の訪問の3つの仕事はすべて違い、うっかりの部分は2回続けて同じ部分にならない。

### REQ-9.10 クリア、もう一度、戻り道

1. クリアすると、画面は町が明るさを取り戻したことを言い、町の3つのランプがすべて点き、「もういちど あそぶ」ボタンが出る。クリアは子どもがボタンを押すまで残る。
2. 「もういちど あそぶ」は、新しいシードの連鎖0の「いう」段から試練6を新しく始め、町のランプはまた消えている。
3. 試練6のあとに次の試練はない。
4. 「タイトル」ボタンは、クリアを含む試練6のすべての段で画面にある。80 x 80 で小屋と同じ場所。タイトルに戻す。`phase` は `title`、`trial` は0、`crown` は初期値。ほかは何も変わらず（言語、主人公、run はそのまま）、そこから試練1〜6がいつもどおり開く。
5. 試練から戻ったタイトルは0.7秒タップを受けないので、「タイトル」のダブルタップで試練1が始まることはない。
6. 行き詰まらない。試練6のどの状態からも、画面のボタンと部分だけで、灯ったランプ、クリア、タイトルに行ける。「タイトル」ボタンがなくてもクリアに行ける。

### REQ-9.11 試練どうしは分かれている

1. 試練6に入っても run は始まらず、`lane`、`shed`、`field`、`shadows`、`lantern`、`run` はタイトルのときのまま。`trial` が6でないとき `crown` は初期値。
2. 表示するシーンは `trial` に従う。1 はレーン、2 は小屋、3 は畑、4 は影、5 はランタン、6 はクラウン。
3. 試練6では試練1〜5のイベントは同じ状態を返す。試練6の外では、クラウンの段のイベント（`SayLook`、`Tell`、`GiveItem`、`Go`、`CheckLamp`、`PointLamp`、`FixLamp`、`NextLamp`）は同じ状態を返す。`LeaveCrown` は試練6でだけ、`StartCrown` はタイトルと試練6のクリアでだけ受け付ける。
4. 試練6での `Start` は言語だけを設定する。`SetLang` は言語だけを変え、段・選んだもの・ランプを変えない。`MoveHeroTo` は主人公だけを動かす。
5. 保存するのは子どもがしたこと。ほしいランプ、仕事、もの、うっかりはシードと連鎖から導き、保存しない。ランプがほしいランプかどうかは部分から決まる。
6. 試練1〜5の振る舞い・文言・配置・テストはこの spec で変わらない。例外はタイトルの名前とカードの位置、それに伴う固定値（「共有の入口やイベントの変更」）。

### REQ-9.12 縦画面、1本指、マウス

1. 試練6は既存の 390 x 844 の縦キャンバスで遊ぶ。
2. どの操作も、ゲーム座標で 80 x 80 以上のものへの1回のタップかクリック。タイトルの試練6ボタン、6枚のカード、「いう」、3つのタイル、「おねがい」、「おなじ」、「おなじじゃない」、「なおす」段のウィスプのランプの各部分、なおす2枚のカード、「つぎへ」、「もういちど あそぶ」、「タイトル」。ドラッグ、長押し、ダブルタップ、2本目の指はない。
3. 試練6でも主人公の床ドラッグは主人公を動かす。部分やボタンで始まった押しは主人公を動かさず、床での押しは動かす。
4. どの段でも、段の列・町のランプ・「タイトル」ボタンといっしょに、両方の言語で、すべての言葉を入れた状態で、文字や絵が重なったり、パネル・メッセージ・ボタンを隠したりしない。操作は主人公の開始位置より上で終わる。
5. 新しいボタンの組は出てから少しのあいだ（450 ms）押されないので、すばやいダブルタップで次の段のボタンを押してしまうことはない。

### REQ-9.13 コードで描く、通信なし、色なし、音なし

1. ランプ、小屋、道具、ひみつ、カード、枠、バッジ、段の列はコードでデバイスピクセル比に合わせて描き、あるものは既存の絵を使う（試練2の小屋と道具、試練4のひみつ、試練5の見た目）。画像ファイルは足さず、第三者の絵も使わない（ハードルール5）。
2. ページと同梱フォントの読み込み後、試練6は日本語でも英語でも通信を必要としない（ハードルール4）。3つの連鎖、クリア、戻り道まで、ネットワークを切っても遊べる。
3. どの状態も、色だけでなく止まった絵で伝える。段の列の実線の枠とチェック、選んだカードの枠とチェック、指した部分の実線の枠、灯ったランプのチェックのバッジ、灯った町のランプの光の線とチェック。色を抜いた画面でも読める。
4. 動きだけで意味を伝えず、1秒に3回より速く点滅せず、無視してもよい。
5. ゲームは音を出さず、音を必要とするものもない。スモークは何も鳴らないことを確かめる。

### REQ-9.14 日本語と英語、文言は content に

1. ガイド、ラベル、メッセージ、段の言葉、ボタンのラベル、タイトルのラベルとキャプションは、`src/content/strings.ja.json` と `strings.en.json` の同じキー（`crown` グループ）にある。見た目・部分・道具・ひみつの言葉と、仕事のメッセージは、試練2・4・5のグループから使う。`src/game/` と `src/domain/` に子ども向けの文字列は書かない。
2. 日本語は `npm run kid` でハードルール2に従う。ひらがなとカタカナだけ、1行12文字以内で2行まで。言葉を入れたあとも同じ。英語は1行26文字以内で2行まで。
3. 言葉を入れるメッセージはちょうど1語を入れ、置き換えていないプレースホルダーを残さない。
4. 言語はこれまでと同じ（`?lang=ja|en`、なければブラウザの言語、なければ英語）。`SetLang` でいつでも変えられ、言葉が変わってほかは変わらない。
5. 文言を変えたあと `npm run kid` と `npm run font` が通り、サブセットフォントがすべての文字を含む。

### REQ-9.15 純粋な規則を、いくつもの方法で確かめる

1. ほしいランプ、仕事、もの、うっかり、段とその順番、作ったランプ、みる、なおす、灯ったランプ、クリア、戻り道は、純粋な reducer の規則（ADR 0001）。`src/domain` は Phaser、DOM、時計、乱数を使わない。シードはイベントの値で、同じシードと同じイベントからはいつも同じ状態になる。
2. INV-63〜INV-74 には、それぞれ実際の reducer に対する `checkProperty` のプロパティテストがある。生成器は連鎖をまるごと遊び（正しいカード・違うカード、足りない「いう」、すべてのものを渡す、両方の「みる」、両方の部分を指す）、ほかのすべての試練のイベント、Tick、言語の変更、もう一度、戻り道を混ぜる。INV-1〜INV-4 も新しいイベントを含む列で走らせる。`run` についてのプロパティは、spec 08 以降のほかの試練と同じく、試練6で始まるか終わるステップで判定する。
3. ユニットテストで確かめる。ランプの部分と見た目、いくつかのシードの連鎖の固定値、100個のシードでの規則（ほしいランプが繰り返さない、仕事が違う、うっかりの部分が動く、答えのタイルが動く）、各段の各イベント、正しい伝え方と違う伝え方での作ったランプ、両方のランプへの両方の「みる」、なおすカード、クリア、入口、すべての段での戻り道とそれ以外では何もしないこと、クリアからのもう一度とそれ以外では何もしないこと、試練6で `Tick` が何もしないこと。content と view では、ja/en の同じキー、プレースホルダー、長さ、責める・こわがらせる・主張する言葉がないこと、段ごとの操作、段の列の印、町のランプ、段とメモごとのメッセージ、タイトルの5つ目のボタン。
4. 実際の reducer に対するモデル検査（`crown.model.test.ts`）は、2つのシードでのタイトルからの入口と、そのあとの試練6を対象にする。アルファベットには、すべてのカード、すべてのもの、画面にないもの、両方の「みる」、両方の部分、すべてのなおすカード、ほかの試練の無効なイベント、`Tick`、`Start`、言語の変更を含める。子どもがしたことの独立した記録と状態を照らし合わせ（作ったランプは1か所を除いて伝えたとおり、なおすは指した部分だけを変える、ランプが灯るのはほしいランプへの「おなじ」だけ、クリアは3つのランプのあとだけ、連鎖の途中で「いう」段に戻らない、`run` は動かない）、どの到達可能な状態からも灯ったランプ・クリア・タイトルに行けること（「タイトル」ボタンなしでもクリアに行けること）を確かめる。状態の数と、わざと壊した規則の反例を記録し、通すために状態を捨てない。
5. ユニットテストのあるコードに、生き残るミュータントはない。

### REQ-9.16 本物のタップと本物の画面

1. モバイルのスモークは、タイトルから本物のタップ（`dispatch` ではない）で試練6に入り、タップだけで3つの連鎖を遊ぶ。最初の連鎖では、カード1枚での「いう」（ウィスプがたずね、何も進まない）、2枚目のカードと「いう」、ひみつ（進まない）、合わない道具と「おねがい」（「わたす」に戻る）、合う道具と「おねがい」、作ったランプへの「おなじ」（よく見て）、「おなじじゃない」、同じ部分のタップ（その部分はおなじ）、うっかりの部分のタップ、カード、「おなじ」。そのあと2つの連鎖をまっすぐ遊び、「つぎへ」でクリア、「もういちど あそぶ」、連鎖の途中とクリアからの「タイトル」（すばやい2回目のタップで試練1が始まらない）。`window.__game` は状態を読むのに使い、タップでできることには使わない。`dispatch` は使わない。
2. スモークは状態だけでなく画面を確かめる。段の列の枠とチェック、選んだカードの印、灯ったランプのチェックのバッジ、町のランプ、ボタン、メッセージをピクセルで見る。「灯った」状態なのに町のランプが暗ければ失敗する。
3. 各段、クリア、タイトルの日本語と英語のスクリーンショットを見る。デスクトップのスモークはマウスで連鎖をひとつ遊び、部分の上での長押しが主人公を動かさないことを確かめる。初回読み込みのあとオフラインでも、両方の言語で、道筋がまるごと動く。
4. スコアアタックを含む試練1〜5のスモークも通る。タイトルの試練6ボタンはそのどれも始めず、タイトルの真ん中のタップはいまも試練1を始める。

### REQ-9.17 どのゲートも弱めず、確かめたことを言う

1. しきい値、設定、チェックスクリプト、ワークフロー、既存のテストを、通すためにゆるめたり、消したり、甘くしたりしない。この spec のせいで古い期待を変えるところは、`tasks.md` に古いテストと新しいテスト、そして試練1〜5が弱くならない理由を書く。
2. `npm run check` が通る。入力と画面をつなぐタスクは、`npm run build` のあと `npm run smoke` も通る。
3. スモークの対象はモバイル WebKit とデスクトップ Chromium。作業用サンドボックスで WebKit が起動しないときは、モバイルのスモークを Chromium の iPhone 13 タッチプロファイルで走らせたと結果に書き、CI の WebKit の結果を正とする。CI のスモークが緑になるまで、完了とは呼ばない。Playwright の実行を実機の確認とは呼ばない。走らせていないテスト・フック・エージェントを走らせたと書かず、Result の行には測ったことだけを書く。

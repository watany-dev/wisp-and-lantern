# 設計: 試練6「The Hollow Crown」

> 和訳です。**正本は英語版** [`../design.md`](../design.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・要件ID・不変条件IDは原文のままです。

`requirements.md`（REQ-9.n）を実装します。ADR 0001（純粋な reducer）、ADR 0003（ゲート）、`.kiro/steering/structure.md` の配置の規則に従います。新しい依存、新しいアセット、新しい ADR はありません。モジュールの配置は試練5（`08-trial-tell-whats-wrong`）をなぞるので、ランタンを知っているレビュアーはクラウンも分かります。

試練1〜5はそれぞれひとつの段を教えます。試練6はそのうち5つを連鎖にし、3回遊びます。時計と得点はありません。学ぶのは段の順番で、時計があれば「みる」を飛ばすことが得になってしまうからです。3つ目のランプが灯ったときに一度だけクリアになります。

## 子どもがすること

英語版の状態遷移図のとおりです。要点：

- タイトルでクラウンのボタン（ゲームがシードを引く）→ 連鎖0の「いう」
- いう：`SayLook`（カード）でその部分の選択を置き換える。両方そろった `Tell` →「わたす」。足りない `Tell` →「どの〜？」のメモで「いう」のまま
- わたす：道具の `GiveItem` →「たのむ」（ウィスプが持つ）。ひみつの `GiveItem` →「〜は ひみつ」のメモで「わたす」のまま
- たのむ：仕事の道具での `Go` →「みる」（作ったランプ：伝えたとおりだが、うっかりの部分だけ違う）。別の道具での `Go` →「〜を つかった、まだ そのまま」のメモで「わたす」
- みる：違うランプに「おなじじゃない」→「なおす」。ほしいランプと同じランプに「おなじ」→ 灯る。ほかの2つの答え →「よく みてね」のメモで「みる」のまま
- なおす：違う部分の `PointLamp` → そこを指し2枚のカードを開く。同じ部分の `PointLamp` →「〜は おなじ」のメモ。2枚のカードのひとつの `FixLamp` →「みる」（その部分が変わり、「〜って いったね」のメモ）
- 灯る：連鎖0か1の `NextLamp` → 次の連鎖の「いう」。連鎖2の `NextLamp` → クリア
- クリア：`StartCrown`（もういちど）→ 新しいシードの連鎖0。どこでも `LeaveCrown` → タイトル

この表にないイベントは、その段では同じ状態を返します。これが「段を飛ばすとうまくいかない」の作り方です。とくに、あとの段から同じ連鎖の「いう」段に戻るイベントはありません。

## domain（`src/domain/crown.ts`）

### ランプ、仕事、もの

`Lamp` は `lampParts`（上から `roof` と `light`）のそれぞれの見た目です。見た目は試練5の `looksOf.roof` と `looksOf.light` を使います。とっては使わないので、とっての見た目はここではカードではなく無視されます。`jobs` は試練2の `leaves`、`boards`、`rope` で、仕事の道具は試練2の `answerOf`（ほうき、ハンマー、はさみ）です。錠と屋根は使いません。鍵が家の鍵の隣に並んでしまい、屋根のねこは試練2のお話だからです。`Thing` は道具か、試練4の3つのひみつ（`isSecret`）のひとつです。

### 状態

英語版の `Crown` 型のとおり、`telling`、`giving`、`going`、`checking`、`fixing`、`lit`、`clear` の7つの段です。`GameState.crown` は `trial` が6でないとき `initialCrown` です（INV-72）。ほしいランプ、仕事、もの、うっかりは保存せず、`wishAt`、`jobAt`、`thingsAt`、`slipAt` が `seed` と `chain` から導きます。灯ったランプはランプを保存しません。ほしいランプだからです。`madeAt(seed, chain, told)` はウィスプが作るランプで、`Go` で一度だけ計算し、そのあと `lamp` は子どもの「なおす」で変わったものです。`cardsOf` はなおす2枚のカード（指した部分のいまの見た目以外）、`sameLamp` はランプがほしいランプかどうかです。

### 連鎖：3進数のシード

シードを3進数の桁（`digit(seed, n)`）と、それより大きい1つのかたまりとして読みます。連鎖 `c` について：

- ほしいランプのやねは見た目 `(digit 0 + c) mod 3`、あかりは `(digit 1 + 2c) mod 3`。どちらの部分も連鎖ごとに変わり、1回の訪問の3つのほしいランプはすべて違います（REQ-9.9.4）。
- 仕事は3つの仕事の6通りの順番のひとつ、`floor(seed / 3^8) mod 6` に従うので、どの仕事も一度ずつ出ます。
- ものは、仕事の道具、次の連鎖の仕事の道具（別の仕事に合う、本物の道具）、ひみつ `(digit 2 + c) mod 3` です。3つの場所は `(digit 3 + c) mod 3` だけ回すので、仕事の道具は連鎖ごとに違う場所にあります（REQ-9.5.6）。
- うっかりの部分は `(digit 4 + c) mod 2` 番目の部分で、交互になります（REQ-9.9.4）。その見た目は、伝えた見た目でもほしい見た目でもないものです。2つが違えば1つに決まり、同じなら残り2つから `(digit 5 + c) mod 2` で選びます。

ユニットテストでシード 0、1、2、3、1234、2^32 - 1 の連鎖を固定し、100個のシードで規則を確かめます。

### イベント（`events.ts`）と reducer

`CrownEvent = SayLook { look } | Tell | GiveItem { thing } | Go | CheckLamp { same } | PointLamp { part } | FixLamp { look } | NextLamp` と、ほかの試練と同じ2つのトップレベルのイベント `StartCrown { seed }`、`LeaveCrown` です。名前はどれも試練6だけのもので、試練1〜5のイベントが試練6に作用することも、その逆もありません（INV-72）。`FixLamp` と `PointLamp` は試練5の `FixPart` と `TapPart` とは別です。

`reduceCrown(crown, event)` は何も変わらないとき crown そのものを返します。イベントでの switch がひとつで、各ケースは最初に段を確かめる小さな関数です（`say`、`tell`、`give`、`go`、`check`、`point`、`fixLamp`、`next`）。

`reducer.ts` には `startCrown` と `leaveCrown` が加わり、クラウンのイベントは `inTrial(state, trials.crown)` で守られた枝で `crown` だけを変えます。`Tick` はランのある試練でだけ動きます。`Object.values(trials)` の代わりに試練1〜5の一覧 `timed` を使うので、試練6での `Tick` は同じ状態を返します（INV-71）。`start` は `crown` も初期値に戻します。`startCrown` と `leaveCrown` は `run` に触れません。タイトルの run はいつも新しいもので（タイトルへのどの道も run をやり直す）、試練6は run を動かさないからです。

### 不変条件

INV-63〜INV-74（`requirements.md`）には、それぞれ `crown.pbt.test.ts` にプロパティテストがあり、新しいイベントを含む列で INV-1〜INV-4 も走らせます。INV-15〜INV-17 は文を変えません。試練6は `run` を変えないので（INV-71）、どの列でもそのまま成り立ちます。

### モデル検査（`crown.model.test.ts`）

実際の reducer を、spec から書いた子どもがしたことの独立した記録で包みます。`picked`（この連鎖の「いう」で最後に押した部分ごとのカード）、`told`（進んだ `Tell` で決まる、ウィスプに伝えたランプ）、`lits`（この訪問で灯ったランプの数）、規則を破った最初のステップで false になる `ok` のフラグ（段の順番から外れた、選んだカードでない「いう」、道具以外で片づいた仕事、うっかりの部分以外で伝えたとおりでない作ったランプ、別の部分や別の見た目を変えた「なおす」、ほしいランプへの「おなじ」以外で灯ったランプ、連鎖の途中での「いう」への戻り、`run` の変化）です。アルファベットは、2つのシード、6枚のカードととっての見た目、`Tell`、シードの5つのものと画面に出ないもの1つ、`Go`、両方の「みる」、両方の部分、6枚のなおすカード、`NextLamp`、戻り道、両方の言語、主人公の2つの位置、短い `Tick` と長い `Tick`、試練6での `Start`、ここでは何もしてはいけない試練1〜5のイベントです。時計も得点もないので状態空間はそのまま有限で、何も抽象化しません。

目標は、どの状態からも「なおす」段、灯ったランプ、クリア、タイトル、そして戻り道なしでクリアに行けることです。わざと壊した規則（カード1枚の「いう」が進む、どの道具でも仕事が片づく、ひみつで仕事が片づく、ウィスプがうっかりせず伝えたとおりに作る、違うランプへの「おなじ」が受け入れられる、なおすがもう一方の部分も変える、カードで連鎖が最初からになる、`NextLamp` が無視される、`LeaveCrown` が無視される、試練6で `Tick` が時計を動かす）は、それぞれ気づくべき検査で最短の手順とともに失敗します。

## 決めたことと代わりの案

- **試練6は L1–L4 ではなく L1–L5 を教える。** 学習設計の行は L5 ができる前に書かれました。「なおす」段は試練5が教える L5（どこ、次にどう、その部分だけ）なので、行は L1–L5 にし、「みる」を「なおす」の前に置いた連鎖を書きます。
- **時計なし、得点なし、一度だけクリア。** ほかの試練が60秒のタイムアタックなのは、ひとつの学びを速く繰り返すとゲームになるからです。連鎖は長く（ランプ1つにつき約10タップ）、時計があれば連鎖が禁じる「みる」を飛ばすことが得になります。得点は3つのランプが見せる以上のものを数えません。代わりの案は、連鎖の60秒ラン（多くの6歳はランプを1つも灯せない）、急かさないタイマー（意味のない数字）です。run の状態には触れないので、INV-15〜INV-17 は文を変えず、ベストも残ります。
- **クリアは終了画面ではなく試練6の段。** 試練1〜5の終了画面は「おしまい！」と得点を出し、INV-17 はそれが時計0のときにだけ出ると言います。試練6のクリアは `phase` を `trial` のままにした `stage: "clear"` で、クラウンのシーンが描きます。「まちに あかりが もどった！」、「もういちど あそぶ」、どの段にもある「タイトル」。新しい phase なしで（INV-1）、ほかの試練の流れ（終わる、もう一度、タイトル）を保ちます。
- **「いう」には2枚とも要り、ウィスプは足りないほうをたずねる。** 試練1ではカード1枚も有効で、ウィスプがもう1枚を自分で選び、あいまいな頼みは別のものを持ってくることを見せます。試練6ではその学びは済んでいて、推測したカードでは「いう」の半分について「段を飛ばすとうまくいかない」が成り立ちません。なのでウィスプは足りない部分をたずねて待ち、推測しません（REQ-9.4.4）。
- **ウィスプは連鎖ごとに1か所うっかりする。** うっかりがなければ、ほしいランプをそのまま伝えた子どもは「みる」も「なおす」も要りません。試練5でもウィスプは1か所違うランプを持ってきますし、プロダクトは助手が「ときどき まちがえる」と言います。うっかりはウィスプが作ったものとして伝え、ウィスプのせいにはしません。
- **「みる」は「おなじ」か「おなじじゃない」で、なおすたびにもう一度たずねる。** ウィスプが作るランプはほしいランプではないので、最初の「みる」はいつも「おなじじゃない」です。なおしたあともう一度たずねるので、2回目は本当の確認になります（違うカードや、ほしい見た目でない伝え方のあとはまた「おなじじゃない」）。代わりの案は、なおすと自動で灯る（試練5の規則。連鎖が主題にしている「みる」を飛ばす）、「みる」を違う部分のタップにする（「なおす」の「どこ」が同じ部分への2回目のタップになる）です。
- **「みる」でも「なおす」でも部分に印をつけない。** 試練5ではチカチカがどこかを見せます。ここではどこかを見つけることが「みる」で、それは子どものすることです。同じ部分のタップは、試練5のしずかな部分のタップと同じく、そう言うだけで失うものはありません。
- **ひみつは道具ではない、とだけゲームは言う。** ひみつを渡しても何も進まず、メッセージはひみつで道具ではないと言います。ウィスプが断ったり守ったりする姿は見せません。それは助手が子どものひみつを守ってくれると教えることになり、「教えないこと」にあたるからです。試練4の「かげが きいたよ」は繰り返しません。ここには影がおらず、試練6の学びは、ひみつは助手が必要とするものの中に入らない、ということだからです。
- **合わない道具は試してから、もう一度渡す。** ウィスプは渡されたものをそのまま使う（試練2の規則）ので、「わたす」はどの道具も受け取り、「たのむ」でそれを試します。「いう」ではなく「わたす」に戻るので、伝えたことは残ります。
- **仕事は3つだけ。** 錠は試練2の鍵を試練4の家の鍵の隣に並べてしまい、6歳に道具の鍵とひみつの鍵を見分けさせることになります。屋根は試練2のねこです。落ち葉、板、ロープは1回の訪問で一度ずつ出るので、3つで足ります。
- **部分は3つでなく2つ。** 「いう」段には部分ごとにカードの列が要り、80ピクセルのタップ領域で3列と「いう」は主人公の帯より上に収まりません。やねとあかりが2列で、とっては描きません。
- **タイトルの5つ目のボタンはカードと絵のあいだ。** 絵の下に置くと、スモークも多くの子どももタップするタイトルの真ん中を覆うか、ボタンがキャンバスからはみ出します。ボタンを小さくすると 80 x 80 を下回ります。名前とカードを上げ、カードを16ピクセル低くするのが最小の変更で、絵と4つのボタンは残ります。いちばん新しい試練をボタンのいちばん上に置くのは spec 07 と 08 の順番を続けたものです。
- **`CheckLamp { same }` で、イベントは2つにしない。** フラグつきのイベント1つで、モデルのアルファベットが小さく、reducer のケースが1つで済みます。view は「おなじ」から `same: true`、「おなじじゃない」から `same: false` を送ります。
- **新しい phase ではなく `trial` で守る。** INV-1 の3つの phase はそのままです。
- **保護者向けの文はない。** 保護者画面は範囲外です（`parents.*.json` は空のまま）。`docs/device-checklist.md` のプレイテストのメモに、子どもが段を順に言うかどうかを記録します。

## リスク

- 作業用サンドボックスでは WebKit が起動しません（`docs/evidence/didnt-work.md`）。モバイルのスモークはそこで Chromium の iPhone 13 タッチプロファイルで走らせ、そう明記します。本物の WebKit の結果は CI のものです。
- 連鎖の最初の「みる」はいつも「おなじじゃない」です。子どもが見ずに押すことを覚えるかもしれません。2回目の「みる」は予想できず、「なおす」では子どもが部分を見つける必要があります。次のプレイテストで、最初の「みる」の前に子どもがパネルを見比べるかを記録します。
- 連鎖は約10タップ、試練は30タップです。6歳は3つ目のランプの前に疲れるかもしれません。時計はなく、町のランプが進み具合を見せ、「タイトル」はいつもあります。プレイテストでそうなれば、手段は連鎖を2つにすることです。
- ピクセルの読み取りは描き方に左右されます。読み取りの点と絵は `crown-layout.ts` を共有します。
- 絵はコードで、スクリーンショットを目で見て判断します。

## 理由

`docs/learning-design.md` は試練2を「鍵・ほうき・ハンマーのうち1つを渡して、閉じ込められた猫を小屋から出す。鍵と扉 = 許可」としています。最初の版では、子どもは3つの道具を見て、1つをウィスプに渡し、扉が開くのは鍵だけだと知りました。答えがいつも同じなので、学びは一度きりで、そのあとは遊ぶ理由がありませんでした。今は、ラウンドごとに猫の閉じ込められ方が違います。錠、落ち葉の山、扉に打ちつけた板、扉に巻いたロープ、屋根の上の居場所です。どれにもぴったり合う道具が1つあり、子どもは60秒でできるだけ多くの猫を助けます。間違った道具では、問題はそのままです。子どもは試すことで、ウィスプにできることは渡された道具で決まること、そして正しい道具は問題で決まることを知ります。

## 用語

- **小屋（Shed）**: 絵にある鍵のかかった木の小屋。扉と窓と屋根があり、猫が入っている。毎回同じ小屋で、変わるのは何が困りごとかだけ。
- **問題（Puzzle）**: そのラウンドで猫を閉じ込めているもの。5つのうちの1つ: `lock`、`leaves`、`boards`、`rope`、`roof`。
- **ラウンド（Round）**: 問題1つ分。ラウンド0がプレイの最初。ラウンドは猫を助けると終わる。間違った道具では終わらない。
- **道具（Tool）**: 5枚の絵カードのひとつ。`key`、`broom`、`hammer`、`scissors`、`ladder`。それぞれ短いラベルと固有のシルエットを持つ。
- **答え（Answer）**: 問題を解く1つの道具（REQ-5.5.2）。どの問題にもちょうど1つあり、どの道具もちょうど1つの問題の答えになる。
- **選択（Pick）**: 今選んでいる道具、またはなし。選ぶことは渡すことではない。
- **渡す（Hand over / give）**: 道具を選んだ状態で、子どもがウィスプをタップすること。道具が使われるのはこれだけ。
- **試した道具（Tried tool）**: ウィスプが問題に試した道具。渡した瞬間の選択であり、やり直しまで変わらない。
- **結果（Result）**: `freed`（道具が答え: 困りごとがなくなり、猫が出る）か `stuck`（ほかの道具: 問題はそのままで、猫はまだ中にいる）。
- **1回のプレイ（Run）**: 小屋の60秒。タイトルの小屋ボタン（または「もう一度」）のタップから時間切れまで。試練1と同じ `Run` を使う: 時計、得点、連続、セッションのベスト。
- **締めの文（Closing line）**: `freed` の結果にだけ出る短い文。子どもがしたこと（道具を渡したので、ウィスプが問題を解けた）を振り返る。

## 要件

### REQ-5.1 タップで小屋に入る

6歳の子どもとして、大人の手を借りずにタイトルから猫の小屋を開けたい。

1. タイトル画面に、試練2用のタップ対象をもう1つ出す。子どもの言語の絵と短いラベルと短い添え書きのあるボタンで、80 x 80 ゲームピクセル以上。絵は鍵を見せ、ラベルは猫のことだと言う。添え書きは、小屋には60秒があると言い（「60びょうで いくつ？」）、野原のボタンは今もタイマーがないと言う（`06` の REQ-6.1.6。`06` の改訂3で変わり、野原のボタンも60秒と言う）。
2. ボタンをタップすると小屋が開き、プレイが始まる。状態は `title` から `trial`（`trial` は 2）に変わる。ラウンドは新しい問題の順（REQ-5.2.3）のラウンド0、時計は満タンの60秒、得点は0、連続は0。セッションのベストは引き継ぐ。レーンは手つかず。
3. ボタンのタップが試練1を同時に始めてしまうことはない。タイトルのほかの場所のタップは従来どおり試練1を始め、試練1の終了画面にも「もういちど」ボタンが1つだけある（REQ-4.6）。
4. 入口は通常の画面での通常のタップ。judge用URL、隠し操作、コンソール呼び出し、クエリパラメータは使わない。
5. 試練選択画面も汎用ルーターもない。新しい画面は小屋と、試練1と共有する終了画面。

### REQ-5.2 小屋が見せるもの

1. 小屋の画面には、プレイの上の行（REQ-5.7.1）、案内文、問題のある小屋、閉じ込められた猫、ウィスプ、5つの道具、タイトルへ戻るボタン（REQ-5.16.1）が見える。
2. 案内文は短い1文で、2行まで。1行目はこのラウンドの問題で何が困りごとかを言い（「とびらに かぎが かかってる」）、2行目は子どもにウィスプへ道具を渡すよう誘い、道具は1つも名指ししない。
3. どのラウンドも問題を1つ見せ、問題ごとに固有の絵がある:

   | 問題 | 猫が出られない間の絵 |
   |---|---|
   | `lock` | 扉は閉まり、南京錠がかかっている。猫の顔が窓にある |
   | `leaves` | 扉は閉まり、扉の足元に落ち葉の山がある。猫の顔が窓にある |
   | `boards` | 扉は閉まり、2枚の板が斜めに打ちつけてある。猫の顔が窓にある |
   | `rope` | 扉は閉まり、ロープが巻かれて結んである。猫の顔が窓にある |
   | `roof` | 扉は閉まり、窓は空。猫は屋根の左の斜面の上に座っている |

   問題の順は、プレイが始まるときにゲームが引くシードから決まる。5つのうちの1つから始め、決まった歩幅（1〜4）で順に進むので、5ラウンドごとに5つの問題がすべて出て、同じ問題が続けて出ることはない。同じシードなら同じ順になる（ADR 0001）。シードがなければ、順は表のとおりの固定の順。
4. 選んでいる間、ウィスプが道具を試すまで絵は変わらない。

### REQ-5.3 道具を1つ選ぶ

1. 5つの道具を、短いラベルのある絵カードで出す: 鍵、ほうき、ハンマー、はさみ、はしご。それぞれ固有の輪郭を持つ（鍵は丸い持ち手と歯、ほうきは柄と広い穂先、ハンマーは柄と四角い頭、はさみは2つの輪の上で交差する2枚の刃、はしごは横木のある2本の縦木）ので、色がなくても見分けられる。上に3つ、下に2つの2段で、決まった順に並ぶ。
2. 選択はなしか1つ。タップすると選び、別の道具をタップすると選択が置き換わる。2つ同時に選ぶことはない。
3. 選んだ道具は太い枠とチェックの形で示し、色だけに頼らない。
4. 選んだだけでは渡さず、使いもしない。印のほかは、絵も得点も変わらない。
5. 選んだ道具をもう一度タップしても選んだままになる（選択を外す操作はなく、別の道具に置き換えるか、やり直しで空になる）。

### REQ-5.4 はっきり渡す

1. 選んだ道具は、ウィスプをタップして渡す。道具を渡す方法はこれだけ。
2. 道具を1つ選ぶと、ウィスプは渡せる見た目（頼むリング）になり、メッセージはウィスプをタップするよう言う。1つで足りる: 2つ目が必要だと言ったり匂わせたりしない。
3. 道具を選んでいないときにウィスプをタップしても何も変わらない。ウィスプは薄く見え、メッセージは優しく道具を選ぶよう誘う。赤、バツ、音、揺れは使わない。
4. 結果が出ている間、ウィスプを再びタップすることも、選択を変えることもできない。1回の挑戦で渡すのは1回だけ。
5. 渡されるのは、そのとき選んでいた道具。何もすり替えない。

### REQ-5.5 ウィスプは渡された道具だけを試す

1. 渡したあと、ウィスプは道具を持って問題のところへ行き、試す。絵は、試した道具を困りごとのところに見せる（錠、落ち葉、板、ロープ、または屋根の上の猫の下）。
2. 結果は次の規則で決まる。同じ問題と同じ道具なら毎回同じ。

   | 問題 | 答え | 答えを渡したとき（`freed`） | ほかの道具を渡したとき（`stuck`） |
   |---|---|---|---|
   | `lock` | 鍵 | 鍵が回り、錠が開き、扉が開き、猫が出て小屋のそばに座り、星が出る | 錠は閉じたまま、扉も閉じたままで、猫は中にいる |
   | `leaves` | ほうき | 落ち葉が掃かれ、扉が開き、猫が出て、星が出る | 落ち葉はそのまま、扉は閉じたままで、猫は中にいる |
   | `boards` | ハンマー | 板が外れ、扉が開き、猫が出て、星が出る | 板はついたまま、扉は閉じたままで、猫は中にいる |
   | `rope` | はさみ | ロープが切れ、扉が開き、猫が出て、星が出る | ロープは結ばれたまま、扉は閉じたままで、猫は中にいる |
   | `roof` | はしご | はしごで猫が降り、小屋のそばに座り、星が出る | 猫はまだ屋根の上にいる |

3. 試した道具、絵、結果、メッセージは常に一致する。メッセージはウィスプが試した道具を、子どもの言語で名指しする。
4. 間違った道具を答えに自動で直さず、渡していない道具を取り出さない。ほかの解法もない: ハンマーは錠を壊さず、はさみは板を切らず、ほかに問題を解くものはない。
5. 何も壊れず、誰も傷つかず、猫が怖がったり危険な目に遭ったりする絵もない。`stuck` の結果は、同じ問題と猫を穏やかに見せる。
6. `freed` と `stuck` は、形と位置（困りごとがあるかないか、扉が開いているか閉じているか、猫が外か中か屋根の上か、星があるか）と文言で区別でき、色や動きだけには頼らない。
7. 論理的な結果は reducer が即座に決める。アニメーション、タイマー、描画の完了を待たない。

### REQ-5.6 何度でもやり直せる

1. `stuck` の結果のあと、メッセージはウィスプが使った道具と、まだ何が残っているか（「とびらは あかなかった」「おちばは そのまま」。ありのままの観察）を言い、ボタンは別の道具を試すよう誘う（「ほかの どうぐを ためそう」）。非難しない: 「まちがい」「だめ」「しっぱい」などの否定語、赤、バツ、脅しは使わない。問題が解けていないという事実は隠さない。
2. やり直しボタンは、道具を選んでいない結果なしの選択に戻す。問題も猫もラウンドも同じ。
3. やり直しに回数制限も、道具の代償もない。道具は消費されない。ほかの道具を何回渡したあとでも、答えを渡せば必ず問題が解ける。間違った道具は連続を切り（REQ-5.7.4）、時計は動き続ける。ほかには何も取られない。
4. 小屋のどの状態からも、助けた猫に到達でき（ソフトロックなし）、タイトルに到達でき（REQ-5.16）、時間切れのあとは新しいプレイを始められる。

### REQ-5.7 60秒のタイムアタック

1. 小屋は60秒のプレイ。小屋が画面にある間、子どもが選んでいても、ウィスプを待っていても、結果を読んでいても時計は減る。時間は、経過ミリ秒を持つ `Tick` としてだけゲームに届き、1フレームは最大250ミリ秒と数える（REQ-4.2.2、REQ-4.2.3）。上の行に、残りの整数秒（切り上げ）と縮むバー、スコアを出す。数字でも伝える（ハードルール7）。
2. 結果は、子どもがボタンをタップするまで画面に残る。何もタイムアウトせず、結果や締めの文が自動で消えたりしない。（時計は動き続ける。REQ-5.7.1を参照。）
3. `freed` の結果のあと、ボタンは「つぎの もんだい」と言い、次のラウンドへ進む: 別の問題（REQ-5.2.3）、道具は未選択、時計と得点はそのまま。`stuck` の結果のあと、ボタンは同じラウンドをやり直す（REQ-5.6.2）。
4. 助けた猫は100点、その前に連続で助けた猫1匹につき50点を足し、4匹分まで（100、150、200、250、300、300、…）。`stuck` の結果は0点で、連続が切れる。減点はなく、赤・バツ・大きな音も使わない。点は、道具を渡したときに入り、子どもが次へ進んだときではない。選ぶ・やり直す・道具なしで渡す・2回目に渡すは得点にならない。猫を助けると、星のそばに得点（「+150」）も浮かぶ。
5. 時計が0になると、ウィスプが道具を試している最中でも結果の表示中でも、すぐに終わる。共有の終了画面が小屋に替わり、スコア、セッションのベスト、そのプレイがベストを超えたときの「しんきろく」を見せる（REQ-4.5.2、REQ-4.5.3）。ボタンは2つある: もう一度（小屋の新しいプレイを始める。REQ-5.1.2: ラウンド0、新しい順、時計は満タン、スコア0。引き継ぐのはベストだけ）と、タイトルへ（REQ-5.16.2）。終了画面は0.8秒のあいだタップを受けない（REQ-4.5.5）。ベストはセッション中だけ保持する。
6. 試練1のプレイは、小屋が使うことも変えることもなく、小屋が試練1のレーンを変えることもない（REQ-5.9）。

### REQ-5.8 助けた結果が振り返る

1. `freed` の結果は、子どもが渡した道具の名前を含むメッセージを出す（「ねこが でてきた！ はさみを つかったよ」）。
2. `freed` の結果では、この問題用の別の文として、子どもの行動を振り返る締めの文も出す: その道具を渡したので、ウィスプは問題を解けた（「かぎを わたしたら / あけられたね」、「ほうきを わたしたら / おちばを はけたね」など、5つの問題ぶん）。文言は kid-reader の観点を確認したうえで `design.md` で決める。
3. 締めの文は `freed` の結果にだけ出す。選んでいる間や `stuck` の結果では出さない。子どもがボタンをタップするまで残り、タイマーで消さない。
4. メッセージに連結しない。結果、絵、道具、ボタンは見えたままで、場所を空けるために文字を小さくしない。
5. この文は、この小屋で起きたことだけを言う。本物のAIが適切な道具さえあれば何でもできる、道具は必ず効く、AIは何でも知っている、AIは友達や家族だ、とは言わない（`docs/learning-design.md` の「教えないこと」）。小屋の鍵はゲームの中のもので、言葉は現実の家の鍵、パスワード、私的なものをAIに渡すようには決して勧めない。L4はここで説明しない。
6. どの問題にもちょうど1つの答えがある理由（子どもが「渡されたものが、できることを決める」と感じられるようにするための固定の演出であり、本物のAIについての主張ではない、ということ）は `design.md` に書く。

### REQ-5.9 試練1と試練2は分かれている

1. 小屋に入っても試練1は始まらず、`lane` はタイトルのときのまま。小屋のプレイは、タイトルの時計と得点（満タンの時計と得点0。ベストは引き継ぐ）に置き換わる。
2. 表示するシーンは `trial` に従う: 1 はレーン、2 は小屋。`trial` が 2 の状態でレーンのシーンが出ることはない。
3. 試練2では、試練1のイベント（`Ask`、`PickCard`、`Retry`）は同じ状態を返す。試練1・タイトル・試練1の終了画面では、小屋のイベント（`PickTool`、`GiveTool`、`RetryShed`、`LeaveShed`）は同じ状態を返し、`StartShed` はタイトルと小屋自身の終了画面からだけ働く。
4. 小屋での `Start` は言語を設定するだけ。`SetLang` は言語だけを変え、選択も試した道具も結果も変えない。`MoveHeroTo` はヒーローだけを動かす。
5. 選択と結果は1つの値であり、2つのコピーではない: 試した道具は、ロックされた選択。
6. 試練1の動き、文言、配置、テストは、このspecで変わらない。

### REQ-5.10 縦画面、指1本、マウス

1. 小屋は既存の390 x 844の縦キャンバスで遊ぶ。
2. すべての操作は80 x 80ゲームピクセル以上の対象への1回のタップかクリック: タイトルの小屋ボタン、各道具、ウィスプ、結果のボタン、タイトルへ戻るボタン、終了画面のボタン。ドラッグ、長押し、ダブルタップ、2本目の指はない。
3. 床でのヒーローのドラッグは、小屋でも動く。道具、ウィスプ、ボタンから始まった押下はヒーローを動かさず、床の押下は動かす。
4. どの段階（選択中、`freed`、`stuck`）でも、日英どちらでも、どの道具名を入れても、文字と絵は重ならず、結果・道具・ボタンを隠さない。上の行、案内文、絵は、上からこの順に積む。

### REQ-5.11 コードで描き、通信しない

1. 小屋、5つの問題、猫、5つの道具、星は、既存の見た目（REQ-4.9〜REQ-4.11）で、端末のピクセル比に合わせてコードで描く。画像ファイルは足さず、第三者の絵は使わない（ハードルール5）。
2. ページと同梱フォントの読み込み後、小屋は日本語でも英語でも通信を必要としない（ハードルール4）。`stuck`、やり直し、助けた猫、タイトルへ戻る手段の通しプレイが、ネットワークを切っても動く。
3. 動きは意味を伝える唯一の手段にならず、1秒に3回より速く点滅せず、無視しても情報が失われない。

### REQ-5.12 日本語と英語、文言は content に

1. 案内文、道具名、メッセージ、ボタンのラベル、タイトルの小屋のラベルと添え書き、締めの文は、すべて `src/content/strings.ja.json` と `strings.en.json` に同じキーで置く。`src/game/` や `src/domain/` に子ども向けの文字列リテラルを置かない。
2. 日本語は `npm run kid` でハードルール2に従う: 漢字なし、ラテン文字なし、1行12字まで、2行まで。道具名を入れたあとも同じ。英語のメッセージは、1行26字までの短い2行までにする。道具名を入れたあとも同じ。
3. 道具名を取るメッセージは、ちょうど1つ取り、未置換のプレースホルダーを残さない。
4. 言語は既存の方式（`?lang=ja|en`、なければブラウザの言語、なければ英語）。`SetLang` でいつでも変えられ、道具名と結果は言語だけが変わり、ほかは何も変わらない。
5. 文言を変えたら `npm run kid` と `npm run font` が通り、サブセットフォントがすべての文字を含む。

### REQ-5.13 純粋な規則を、いくつもの方法で検査する

1. 選択、受け渡し、結果、問題の順、得点、時計、戻る手段は、純粋な reducer の規則（ADR 0001）。`src/domain` は Phaser、DOM、時計、乱数を使わず（シードはイベントのフィールド）、結果は言語にも演出のタイミングにも依存しない。
2. INV-15〜INV-24（小屋に当てはまる範囲）と INV-40〜INV-43 にはそれぞれ、実際の reducer に対する `checkProperty` の性質テストがある。生成は実際に小屋を遊ぶ（全道具、置き換えた選択、各結果のあとのやり直し、正しい道具での何ラウンドか、時間切れになるプレイ、終了画面からの遊び直し、戻る手段）。INV-3 と INV-4 も、新しいイベントを含む列で実行する。
3. 単体テストは次を扱う: 5つの道具と問題とその答え、いくつかのシードでの順、未選択、置き換えた選択、道具を使わない選択、明示的な受け渡し、未選択での受け渡し、結果中のロックと2回目の受け渡し、各結果のあとのやり直し（`stuck` のあとは同じラウンド、`freed` のあとは次のラウンド）、時計、得点、連続、時間切れ、遊び直し、プレイ中と終了画面からの戻る手段。すべての問題で、試した道具と絵とメッセージが一致すること、締めの文が `freed` の結果にだけ出ること、日英、同じキー、プレースホルダー、全道具名を入れた長さを確認する。
4. 実際の reducer に対するモデル検査（`shed.model.test.ts`）は、タイトルからの入口とその先の小屋を、シード、無効な試練1のイベント、`Tick`、`Start`、言語変更を含む有限のアルファベットで探索する。確認すること: 道具が2つの状態や道具のすり替え、誤った得点、範囲外の時計がない。各道具での助けた猫と、各道具での `stuck` の結果に到達できる。`stuck` の結果から同じ問題に戻れる。到達可能なすべての状態から、助けた猫、タイトル、終了画面に到達できる。アルファベットから時計と戻る手段を除いても、新しい選択、次のラウンド、2匹目の助けた猫に到達できる。状態数と、意図的な破壊の反例を記録する。試練1のすべての状態から小屋への経路は求めず、通すために小屋の状態を除外することもしない。
5. ミューテーションテストは、単体テスト対象のコードに生き残りのミュータントを出さない。

### REQ-5.14 実際のタップと実際の画面

1. モバイルのスモークは、タイトルから実際のタップ（`dispatch` ではない）で小屋に入り、次を遊ぶ: 道具なしでウィスプをタップ（何も使われない）、置き換えた選択、間違った道具→結果→表示中のロック→やり直し、答え→メッセージ→締めの文→スコア、次の問題、5つの問題とその答えをテストをまたいですべて、時間切れと遊び直し、プレイ中と終了画面でのタイトルへ戻るボタン。`window.__game` は状態の読み取りに使い、タップでできることの代用にはしない。問題の順は、ゲームが引くシードを設定して決める（ページ内で `Math.random` を置き換える）ので、テストは実際のタップで既知の問題を遊べる。
2. スモークは状態だけでなく画面も確認する: 困りごとがあるかないか、扉が開いているか閉じているか、猫が中か屋根の上か外か、道具名、締めの文、時計、スコアが、ピクセルで見える。状態が `freed` なのに困りごとが描かれたまま、または締めの文がない場合は不合格にする。
3. 日本語と英語の、選択中・`stuck`・`freed` の画面をスクリーンショットで見る。デスクトップのスモークはマウスで小屋を遊び、道具の上で押し続けてもヒーローが動かないことを確認する。最初の読み込み後にオフラインにしても、両言語で `stuck` の結果、やり直し、助けた猫、戻る手段が動く。
4. 試練1と試練3のモバイルとデスクトップのスモークは今も通る。タイトルの小屋ボタンは試練1を始めず、タイトルのほかの場所のタップは今も始める。

### REQ-5.15 ゲートを弱めない。検証したことを言う

1. 閾値、設定、checkスクリプト、ワークフロー、既存のテストを、通すために緩めたり削ったりしない。この改訂で古い期待を変える必要が出たら、`tasks.md` に旧テストと新テストを挙げ、試練1の保証が弱まらない理由を書く。
2. どのタスクでも `npm run check` が通る。入力と画面をつなぐタスクは、`npm run build` に続けて `npm run smoke` も通す。
3. スモークの対象は、モバイル WebKit とデスクトップ Chromium。執筆環境で WebKit が起動できないときは、結果にモバイルのスモークを iPhone 13 のタッチプロファイルの Chromium で実行したと書き、CI の WebKit の実行を正とする。CI のスモークが緑になるまでは完了と呼ばない。Playwright の実行を実機確認とは呼ばない。実行していないテスト・hook・エージェントを、実行したと報告しない。

### REQ-5.16 タイトルへ戻る手段

6歳の子ども（またはそばにいる保護者）として、小屋からタイトルに戻りたい。小屋で行き詰まらないように。

1. 小屋の画面には、タイトルへ戻るボタンが、プレイ中も結果の表示中も、いつも画面にある。ラベルは絵なしで（「タイトル」）、80 x 80 ゲームピクセル以上で、道具の下の段の端に置く。
2. 小屋のプレイの共有の終了画面には、「もう一度」の下に2つ目のボタン、タイトルへがある。試練1の終了画面は変えず、そのボタンはない。
3. タイトルへ戻ると、小屋と進行中のプレイは捨てられる: `phase` は `title`、`trial` は 0、小屋は初期値、時計は満タン、得点は0。言語、ヒーロー、セッションのベストスコアは保つ。終えたプレイとは数えないので、途中でやめたプレイがベストを更新することはない。
4. 戻った先のタイトルは、短い間タップを受けないので、すばやい2回目のタップが試練1を始めることはない（野原と同じ。REQ-6.7.4）。タイトルからは、小屋はそのボタンで、試練1はほかの場所のタップで、野原はそのボタンで、また開く。
5. `LeaveShed` は試練2の外（タイトル、試練1、試練3）では何もしない。

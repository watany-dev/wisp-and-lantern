# 設計: 試練1「The Dark Lane」

> 和訳です。**正本は英語版** [`../design.md`](../design.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・ID・コード・文言（ja/en）は原文のままです。

[`requirements.md`](requirements.md)（REQ-2.n）を実現します。ADR 0001（純粋reducer）、ADR 0003（ゲート）、`.kiro/steering/structure.md` の配置ルールに従います。新しい依存、新しいアセット、新しいADRはありません。

## 遊びの流れ

```text
title --tap--> choosing --PickCard x2--> ready --Ask (tap wisp)--> asked
  ^                ^                                            |
  |                +-------------- Retry (button) --------------+
  +-- (no way back; the title is only shown at load)
```

- `choosing`（選ぶ）: 選択が0枚または1枚、または2枚だがまだ頼んでいない状態。
- `asked`（頼んだ後）で `outcome` が `right` か `wrong`: 選択は固定され、結果が表示される。
- 不正解からの `Retry` はねがいを保つ。正解からの `Retry` は次のねがいに進む。

## ドメイン（`src/domain/`）

### 型（`lane.ts`、新規）

```ts
export const colors = ["red", "blue", "yellow"] as const;
export const things = ["pumpkin", "lantern"] as const;
export type ColorId = (typeof colors)[number];
export type ThingId = (typeof things)[number];
export type CardId = ColorId | ThingId;
export type Pick = { color: ColorId | null; thing: ThingId | null };
export type Lane = { wish: number; pick: Pick; asked: boolean };
```

`asked: true` は、子どもが両方のカードを選んだ状態でウィスプをタップし、助手が `pick` どおりに探索したことを表します。「見つかった物」を別に持ちません。物は `pick` そのものなので、頼んだ内容と食い違いようがありません（REQ-2.5）。

`lane.ts` の純粋関数: `initialLane`、`isColor(card)`、`isComplete(pick)`、`wishAt(index)`、そして `"choosing" | "right" | "wrong"` を返す `outcome(lane)`（`asked` かつ `pick` がねがいと等しいときに `right`）。

`GameState` に `lane: Lane` が加わります。`phase` は `"title" | "trial"` のままなので、INV-1 と INV-2 はそのまま成り立ちます。`trial` はタイトルで 0、試練で 1 です。

### バランス（`balance.ts`）

`wishes`: `[yellow lantern, red pumpkin, blue lantern]`。色と物の6組はそれぞれレーンの1マスで、ねがいは必ずそのどれかです。巡回は `(wish + 1) % wishes.length` なので `wish` は有界で、モデル検査は有限のままです。`wispSpeed` は、ウィスプの飛行（演出）の速さです。

### イベント（`events.ts`）

| イベント | 効果 |
|---|---|
| `Start`（既存） | `phase` を `trial`、`trial` を 1、任意の `lang` を設定する。分岐なし、レーンは変えない。タイトルからは試練に入り、2回目の `Start` は `lang` だけを変える（残りはすでに設定済みのため）。迷い打ちの開始でゲームが初期化されることはない。 |
| `PickCard { card }` | `trial` かつ未依頼: 選択の色または物を設定する（`isColor` で判別）。それ以外は変化なし。 |
| `Ask` | `trial`、未依頼、選択が完全: `asked = true`。それ以外は同じ状態オブジェクトを返す（REQ-2.4）。 |
| `Retry` | `trial` かつ依頼済み: 選択を消し、`asked` を false に、`wish` は正解の後だけ進める。それ以外は変化なし。 |
| `SetLang`、`MoveHeroTo`（既存） | 変更なし。`lane` には触れない。 |

上記以外のイベントは `lane` に触れず、レーンのイベントは `lang` や `hero` に触れません。`title` ではレーンのイベントは無視されます。`reduce` は `switch` のままで、`reducer.ts` の小さな関数に委譲します。

### 名前つき不変条件（新規。同じタスクでプロパティテストを付ける）

| id | 不変条件 |
|---|---|
| INV-5 | どのイベント列でも、列に `Ask` がなければ `lane.asked` は false。助手が頼まれずに探索することはない。 |
| INV-6 | 選択が不完全なとき、またはすでに依頼済みのときの `Ask` は、同じ状態を返す。カードが足りないのは探索ではない。 |
| INV-7 | `lane.asked` が true のとき選択は完全で、`Retry` 以外のどのイベントも `lane` を変えない。探索後に、頼んだ内容は変えられない。 |

モデル検査（`reducer.model.test.ts`）は、次の状態不変条件も保ちます。`wish` は `wishes` の添字であること。`asked` なら選択が完全であること。`phase` が `title` なら `trial` は 0 で、レーンは初期状態であること。ゴールは「正解」で、どの状態からも到達可能であること。2回目の実行では「試練中の選ぶ状態」をゴールにし、不正解から必ず抜けられることを確かめます。どちらも「ソフトロックなし」（REQ-2.8）の根拠です。

## コンテンツ（`src/content/`）

- `cards.json` は、全カードに `kind`（`"color"` か `"thing"`）を持たせ、物カードを2枚追加します。既存のフィールド（`id`、`color`、`shape`、`pattern`、`label`）は残します。物カードでは `shape` がシルエット（`pumpkin`、`lantern`）、`pattern` は `plain`、`color` は無彩色のグレーです。これで既存のカードゲート（色・形・模様の重複禁止、空でないフィールド）が、`scripts/check-*` を変えずに通ります。
- `strings.ja.json` と `strings.en.json` に `lane` グループを足します。`{0}` が物の名前を表します（正解と違う物のメッセージ。REQ-2.5）。ゲートは日本語にラテン文字を許さないので、プレースホルダは数字です。

| キー | ja | en |
|---|---|---|
| `lane.wish` | ほしいのは これ | I want this one |
| `lane.pickBoth` | いろと ものを えらんでね | Pick a color and a thing |
| `lane.pickColor` | いろを えらんでね | Pick a color |
| `lane.pickThing` | ものを えらんでね | Pick a thing |
| `lane.ready` | ウィスプを タップして⏎たのもう | Tap the wisp to ask it |
| `lane.right` | {0}が⏎ぴったり みつかった | Found the {0}! Just right |
| `lane.wrong` | {0}を⏎もってきたよ | The wisp brought the {0}, just as you asked |
| `lane.again` | もういちど あそぶ | Play again |
| `retry`（既存） | もういちど つたえてみよう | Let's tell it again |

（⏎ は改行です。）物の名前は、カードのラベルを空白でつないだものです（ja `あかい かぼちゃ`、en `red pumpkin`）。ゲートが見るのはテンプレートだけなので、テストが「すべてのメッセージ × すべての物の名前」を組み立て、その結果に日本語ルールを当てます。

## ゲート側（`src/game/`）

単体テストと変異テストの対象になる、素のモジュール:

- `lane-layout.ts`: すべての位置とサイズを1つの表にまとめます（ゲーム座標、390 x 844）。

  | 対象 | 中心 | サイズ |
  |---|---|---|
  | ねがいのテキスト / 絵 | (130, 62) / (265, 62) | 絵 64 |
  | レーンのマス（色の列 x 物の行） | x は赤・青・黄で 75, 195, 315、y はかぼちゃ 170、ランタン 270 | 88 |
  | ウィスプ | (195, 370) | タップ範囲 96 |
  | メッセージ | (195, 454)、折り返し幅 340 | 高さ 60 |
  | ボタン | (195, 528) | 300 x 80 |
  | 色カード | x 75, 195, 315; y 690 | 96 x 92 |
  | 物カード | x 135, 255; y 788 | 96 x 92 |

  ヒーローは (195, 600) から始まり、ボタン（y 568 まで）と色カード（y 644 から）の間にあります。足場の床ドラッグのために、この帯は空けておきます。すべてのタップ範囲は 80 x 80 以上です（REQ-2.11）。
- `lane-view.ts`: `laneView(state)` が、シーンが見せるものを返します。Phaserの型は使いません。メッセージ文、ボタン（`{ text, event }` かなし）、ウィスプが `armed` か、各カードのラベル・選択マーク・薄さ、ウィスプの薄さ、光るマス、結果の印、ねがいの物、`wispTarget` です。文言は `src/content` からここで選びます。
- `pattern.ts`: `patternMarks(pattern, size)` が、`stripes-v`、`dots`、`plain` に対する素のマーク（`line` か `dot`）を返します。描画コードはそれを塗るだけです。

シーンのコード（カバレッジと変異テストの対象外なので薄く保つ: 関数30行、複雑度5）:

- `scenes/LaneScene.ts`: レイアウトからオブジェクトを作り、ゲームを購読し、`laneView` を描画し、`PickCard`・`Ask`・ボタンのイベントを送り、`stepToward` でウィスプを動かします。オブジェクトの外から始めた押下に対しては、足場のヒーロードラッグを維持します。
- `ui/art.ts`: カード、物、星、暗いマスを `Phaser.GameObjects.Graphics` で描きます。
- `scenes/TitleScene.ts`: フェーズが `trial` になったら `LaneScene` を開始します。TitleScene自身のヒーロードラッグは `LaneScene` に移ります。
- `boot.ts`: `LaneScene` を登録します。

### コードで描く理由

プレースホルダのPNGは単色の四角で、かぼちゃ、ランタン、縞、点を表せません。6つの物と5枚のカードをコードで描けば、新しいアセットもライセンスも増えません（hard rule 5）。起動後に何も読み込みません（REQ-2.12）。ウィスプとヒーローは、タイトルがすでに読み込むプレースホルダPNGを使い続けます。

### 入力

操作できるオブジェクトは `pointerdown` を使い、ドラッグはありません。シーン全体の `pointerdown` ハンドラが、押下がオブジェクトに当たったかを記録します。ヒーローが歩くのは、どのオブジェクトにも当たらなかった押下だけです（REQ-2.11）。`boot.ts` の同時ポインタ2本は維持します。2本目の指は試練では何も変えません。

### オフライン

ゲームは起動後に要求を出しません。Phaserは2枚のPNGを、CSSはフォントを、最初のフレームの前に読み込みます。スモークは、タイトルが出た後にブラウザコンテキストをオフラインにして最後まで遊び、その後に出たあらゆる要求を失敗とします。サービスワーカーは対象外です。「初回ロード後はオフライン」は、後から何も取りに行かないことで満たします。

## 判断と代替案

- **カードが足りないときは何もしない。** 依頼がそれを求めています。「足りないと違う物が来る」にすると、作り物の代替品が要ります。曖昧な頼み方の教訓は、別のカードを選んだときの「正確だが別の物」という結果が伝えます。
- **`asked` は真偽値で、物は保存しない。** 状態が小さくなり、正確さが構造上成り立ちます。
- **やり直しで選択を消す。** 残すと、もう一方を見ずに1枚だけ替えられてしまいます。消せば、新しく意識して頼み直すことになります。プレイテスト後に見直します。
- **ねがいは不正解のあとは同じ、正解のあとは進む。** 同じ課題をやり直し、成功したら新しい課題になります。
- **ウィスプをタップして頼む。** （device-checklist の文言「ヘルパーをタップして送る」に合わせます）。文字のボタンにはしません。
- **ゲーム内の言語切替はなし。** もう一方の言語名を日本語で書くと漢字かラテン文字が要り、日本語ルールが禁じています。親は `?lang=` を使います。親向け画面は対象外です。
- **ねがいはランダムにしない。** ランダムはイベントで入れる必要があります。固定の巡回で足ります。

## リスク

- 作業用サンドボックスではWebKitが起動しません（システムライブラリ不足）。モバイルスモークはそこではiPhone 13のタッチ設定のChromiumで、WebKitではCIだけで実行します。
- ヒーローのドラッグとカードのタップは同じキャンバスを共有します。「どのオブジェクトにも当たらない押下」というルールは、既存のデスクトップのドラッグテストと、新しいデスクトップテスト（カード上でマウスを押しっぱなしにしても `hero` が変わらない）で検査します。タッチのタップは短くてヒーローを歩かせられないため、モバイルのスモークではこのケースは見えません。

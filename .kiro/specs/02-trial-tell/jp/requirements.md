# 要件: 試練1「The Dark Lane」（はっきり伝える）

> 和訳です。**正本は英語版** [`../requirements.md`](../requirements.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・要件ID（`REQ-2.n`）・不変条件ID（`INV-n`）は原文のままです。

spec `02-trial-tell`。学習目標 L1（`docs/learning-design.md`）を教えます。助手は頼まれたとおりにやるので、はっきり頼もう、という内容です。要件IDは `REQ-2.n` です。`REQ-1.n` は存在しない `01-core-loop` spec のもの（例: `e2e/helpers.ts` の `REQ-1.11`）で、再利用しません。

## 範囲

対象: 試練1だけ。タイトルのタップから、結果とやり直しまで。既存の足場（タイトルシーン、`reduce`、`window.__game`、ヒーローのドラッグ）の上に作ります。触るのは `src/domain`、`src/game`、`src/content` とそのテスト、およびスモーク用の `e2e/` です。

対象外: 試練2〜6、親向け画面、judge機能（`?judge=1&trial=n` のジャンプ）、音、ゲーム内の言語切替、サービスワーカー、将来の試練のための共通基盤。2つ目の試練が必要とするものは、その試練の仕様を書くときに作ります。

## 学習設計の読み方

`docs/learning-design.md` では、試練1は2〜3枚の絵カード（色・物・場所）を選び、助手がカードどおりに探す、となっています。この spec は2枚（色と物）を使います。3枚目（場所）は「どれかを言う」ことを教えるのに不要です。

`docs/device-checklist.md` には、カードが足りないと「違う物を持ってくる」という暫定の基準があります。この spec は依頼文のより厳しい読み方を採ります。カードが足りないとき、助手は**まったく探索しません**。「違う物が来る」体験は、別のカードを選んだとき（REQ-2.4、REQ-2.7）に得られます。チェックリストの文言はここでは変えません。PRのDecisionsを参照してください。

## 用語

- **ねがい（wish）**: 村人が見せる絵。`balance.wishes` のどれか。子どもはこれを頼む必要があります。
- **色カード / 物カード**: 絵カード。色は赤・青・黄、物はかぼちゃ・ランタン。
- **選択（pick）**: いま選んでいる色カードと物カード（どちらも空のことがあります）。
- **依頼（Ask）**: 子どもが助手（ウィスプ）をタップすること。助手が探索する唯一の方法です。
- **レーン（lane）**: 暗い6つのマス。色と物の組み合わせごとに1つ。助手が1つを光らせます。
- **結果（result）**: 正解（光った物がねがい）か、不正解（別の物）。

## 要件

### REQ-2.1 開始からやり直しまで遊べる

6歳の私が、始めて、頼んで、結果を見て、もう一度やる、を自分で最後まで行えるようにします。

1. 子どもがタイトルをタップすると、「The Dark Lane」が表示されます。ねがいの絵、暗い6つのマス、ウィスプ、メッセージ行、カードの並びです。
2. 状態は `title` から `trial` に移り、`trial` は 1 になります。レーンは最初のねがい、空の選択、未探索で始まります。
3. 流れは、選ぶ→頼む→結果→やり直し（選び直し）です。タイトルとこの試練以外の画面はありません。

### REQ-2.2 絵カードを2枚選ぶ

1. 並びには色カード3枚と物カード2枚があります。各カードは絵と短いラベルを持ちます。
2. 色カードをタップすると選択の色が、物カードをタップすると物が決まります。同じ列で別のカードをタップすると置き換わります。別の列には影響しません。
3. 選んだカードは、太い枠とチェック形で示します。色だけで示すことはしません。
4. 助手が探索した後は、やり直しまでカードを変えられません。
5. 選ぶだけでは探索は始まりません。

### REQ-2.3 助手は頼まれたときだけ探索する

1. 助手が探索するのは、両方のカードが選ばれている状態でウィスプをタップしたときだけです。
2. 依頼を含まないイベント列の後では、何をしていても（選ぶ、置き換える、言語変更、ヒーロー移動、やり直し）助手は探索していません。
3. カードが足りないとき、ウィスプは薄く表示されます。カードが足りないとき、または結果表示中は、ウィスプに「頼める」リングは出ません。

### REQ-2.4 カードが足りないのは探索ではない

1. カードなし、色だけ、物だけで依頼しても、探索はされず、状態も変わりません。
2. メッセージ行は、足りないもの（両方、色、物）を、誘う言い方（「〜をえらんでね」）で伝えます。エラーとしては伝えません。
3. 赤色の表示、バツ印、音、揺れは使いません。

### REQ-2.5 助手は頼まれたとおりに探索する

1. 探索は、選んだ色と物のとおりに行います。助手が別の物にすり替えることはありません。
2. ウィスプはその組み合わせの1マスに飛び、そのマスが光り、色・模様・形つきで物が見えます。
3. メッセージは、子どもの言語で、ラベルを使って物の名前を言います（例: 「red pumpkin」）。

### REQ-2.6 正解がはっきり分かる

1. 光った物がねがいと一致するとき、結果は正解です。
2. 正解では、星の形と「みつかった」メッセージを示します。色だけで伝えることはしません。
3. 続けて「もういちど あそぶ」ボタンで次のねがいに進みます。ねがいは決まった順で巡り、選択は消えます。

### REQ-2.7 違う頼み方を責めない

1. 光った物が別の物のとき、結果は不正解です。メッセージは、ウィスプが「言われたとおり」に何を持ってきたかを伝えます。「まちがい」「だめ」「いいえ」「しっぱい」といった言葉、バツ印、赤色は使いません。
2. ねがいは見えたままです。「もういちど つたえてみよう」ボタンで、同じねがい・空の選択の「選ぶ」状態に戻ります。
3. 違う頼み方は、最初の頼み方と同じように使えます。何も減りません。

### REQ-2.8 子どもは必ず最後までたどり着ける

1. 到達可能などの状態からも、正解に到達できます（ソフトロックなし）。不正解とやり直しを何度繰り返した後でも同じです。
2. やり直しに回数制限も代償もありません。
3. 正解後にやり直すと、新しいねがいは有効なねがいで、状態は再び「選ぶ」です。

### REQ-2.9 日本語と英語

1. 子ども向けの文言はすべて `ja` と `en` の両方にあります。カードのラベルも同様です。
2. 言語は既存の方法で決まります。`?lang=ja|en`、なければブラウザの言語、なければ英語。言語はいつ変えても、選択・ねがい・結果は変わりません。
3. 言語変更で探索が始まることはありません。

### REQ-2.10 色だけが手がかりにならない

1. 各色は専用の形と模様を持ちます（`cards.json`）。赤は縦じまの円、青は点の四角、黄は模様なしの三角です。
2. 色カード、レーンの物、ねがいの絵は、すべてその色の形と模様を示します。
3. 物カードとレーンの物は、シルエット（かぼちゃ、ランタン）で区別されます。

### REQ-2.11 縦持ち・1本指・マウス

1. 試練は既存の 390 x 844 の縦長キャンバスで遊びます。
2. すべての操作は、ゲーム座標で 80 x 80 以上のオブジェクトへの1回のタップまたはクリックです。ドラッグ、長押し、ダブルタップ、2本目の指は不要です。
3. 床でのヒーローのドラッグは、試練中も従来どおりヒーローを動かします。カードやウィスプの上から始めた押下では、ヒーローは動きません。

### REQ-2.12 初回ロード後はオフライン

1. ページと同梱アセットを読み込んだ後、この試練にネットワーク要求は不要です。
2. この試練の絵はすべてコードで描くか、同梱のプレースホルダ画像を使います。フォントも同梱です。
3. 読み込み後にネットワークを切っても、通しのプレイ（不正解、やり直し、正解）が完了します。

### REQ-2.13 文言は `src/content` に置く

1. 子ども向けの文言リテラルは `src/game/` にも `src/domain/` にも現れません。
2. 日本語は、ひらがなとカタカナだけ、1行12文字以内、2行以内（hard rule 2）です。物の名前を差し込んだ後も同じです。
3. `npm run kid` と `npm run font` が通り、サブセットフォントがすべての文字を含みます。

### REQ-2.14 純粋なルールを3通りで検査する

1. ルールは `reduce` にあります（ADR 0001）。`src/domain` はPhaser、DOM、時計を一切importしません。
2. `.kiro/steering/domain-invariants.md` の INV-5〜INV-7 は、それぞれプロパティテストを持ちます。
3. やり直しと「ソフトロックしない」は、実際のreducerに対する `checkModel` で検査します。
4. モバイルのスモークは、実タップで試練を最後まで遊びます。デスクトップのスモークは、マウスで遊びます。

### REQ-2.15 どのゲートも弱めない

1. 通すために、しきい値・設定・checkスクリプト・既存テストを緩めたり消したりしません。
2. `npm run check` が通り、`npm run build` に続く `npm run smoke` が通ります。

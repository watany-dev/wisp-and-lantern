# 設計: 試練3「The Wisp Field」

> 和訳です。**正本は英語版** [`../design.md`](../design.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・要件ID（`REQ-6.n`）・不変条件ID（`INV-n`）は原文のままです。

`requirements.md`（REQ-6.n）を実装します。ADR 0001（純粋な reducer）、ADR 0003（ゲート）、`.kiro/steering/structure.md` のレイアウト規則に従います。新しい依存も、新しい素材も、新しいADRもありません。reducer は純粋なまま、シーンは薄いまま、というのは ADR 0001 と 0003 がすでに言っていることだからです。モジュールの構成は試練2（`05-trial-grant-tools`）をそのまま写しているので、小屋を知っているレビュアーは野原もわかります。

## 子どもがすること

```text
title --野原ボタンをタップ--> checking（何も確かめていない）
checking --CheckStar i、星 i が未確認--> checking（星 i にしるし。メッセージはその星について）
checking --CheckStar i、星 i が確認済み、または i が 0〜4 でない--> checking（同じ状態）
checking --KeepStars、未確認の星がある--> checking（同じ状態）
checking --KeepStars、5つとも確認済み--> kept
kept     --RetryField--> checking（次のラウンド、何も確かめていない）
```

`kept` が成功です。そのあとのボタンは次のラウンドを遊ぶので、`RetryField` の意味は1つ、新しいラウンドです。「受け取る」ボタンは5つの星をすべて確かめたときだけ画面に出ます。reducer はそれより早い `KeepStars` も拒むので、規則はボタンに頼りません。タイトルのほかの場所をタップすると、今も試練1が始まります。

## ドメイン（`src/domain/`）

### 状態

`GameState` はフィールドを1つ足します。新しい `phase` は足しません。

```ts
// field.ts
export const starCount = 5;
export const rounds: readonly (readonly number[])[] = [[3], [0, 2], [4], [1, 3]]; // ラウンドごとの偽物の星
export type Field =
  | { stage: "checking"; round: number; checked: readonly boolean[]; last: number | null }
  | { stage: "kept"; round: number };
export const initialField: Field = { stage: "checking", round: 0, checked: [false x5], last: null };

// state.ts
export const trials = { lane: 1, shed: 2, field: 3 } as const;
export type GameState = { /* 変更なし */ field: Field };
```

この形にした理由:

- **真実は保存しません。** どの星が偽物かは `round` の関数（`fakesOf(round)`）です。状態が持つのは子どもがしたことだけ: どの星を確かめたか（`checked`）と、最後にどれか（`last`）。だからしるしがラウンドと食い違うことはなく、「受け取った星は本物の星」は写しではなく導かれます（REQ-6.8.5）。`markOf(field, i)` は、星 `i` を確かめるまで `unchecked`、確かめると `fake` か `real` です。
- **`kept` に `checked` の配列はありません。** `kept` に着くのは5つとも確かめたときだけなので、すべてのしるしがわかっていてラウンドの真実と等しい。もう一度保存すると写しが2つになります。
- **`last` はメッセージのためにあります。** 確かめるたびに、メッセージは今見つけた星についてです。view は状態だけの関数なので、状態がどの星だったかを覚えている必要があります。`last` はラウンドの最初の確認まで `null` です。
- **`phase` は `title | trial | over` のまま。** 野原は `phase` が `trial` で `trial` が3。シーンは `trial` に従います。**`field` は常に存在し**、`trial` が3のとき以外は `initialField` です（INV-31）。
- **`round` は表で区切られます。** 常に `rounds` の添字なので、モデル検査の状態空間は有限で、`RetryField` は最後の項目から最初に戻ります。

### ラウンドの表

`rounds` は各ラウンドの偽物の星を並べます。星の番号は0〜4: 0、1、2は上の段を左から、3と4が下の段です。

| ラウンド | 偽物の星 | 本物の星（受け取る） | 理由 |
|---|---|---|---|
| 0 | 3 | 0, 1, 2, 4（4つ） | 最初のラウンドの偽物は1つで、下の段にある。上の段は全部本物なので、子どもは先に「本物」を見て、偽物は規則ではなく驚きになる |
| 1 | 0, 2 | 1, 3, 4（3つ） | 偽物が2つで、間に本物がある |
| 2 | 4 | 0, 1, 2, 3（4つ） | 偽物が1つで、最後の星 |
| 3 | 1, 3 | 0, 2, 4（3つ） | 偽物が2つで、各段に1つ |

どの集合も、前のものと違います（最後と最初も）。次のラウンドが今遊んだものと同じに見えることはありません。どのラウンドにも偽物は1つか2つです（INV-26）。乱数はありません: 同じ子どもは同じ4ラウンドを同じ順で見て、テストとモデル検査はそれに名前をつけられます。固定の表は、純粋な reducer を求める ADR 0001 にも合っています。注入する乱数は、教える内容が増えないのにイベントを1つ増やします。

### 関数（`field.ts`）

```ts
export function fakesOf(round: number): readonly number[];
export function isFake(round: number, index: number): boolean;
export type StarMark = "unchecked" | "real" | "fake";
export function markOf(field: Field, index: number): StarMark;   // kept: すべての星がわかっている
export type FieldOutcome = "checking" | "ready" | "kept";
export function fieldOutcome(field: Field): FieldOutcome;        // ready: 5つとも確認済みで未受け取り
export function keptStars(field: Field): number[];               // 受け取り後はラウンドの本物の星、それ以外は []
export function reduceField(field: Field, event: FieldEvent): Field; // 何も変わらないときは `field` 自身を返す
```

`reduceField`:

- `CheckStar { index }`: `checking` で、`index` が0〜4の整数で星 `index` がまだ確かめられていなければ、その星が確かめ済みになり `last` が `index` になる。そうでなければ変化なし。`kept` では変化なし。
- `KeepStars`: `checking` で5つとも確かめ済みなら `{ stage: "kept", round }`。そうでなければ変化なし。
- `RetryField`: `kept` なら次のラウンド（`(round + 1) % rounds.length`）の新しい `checking`。`checking` なら変化なし。

2つの星を同時に確かめる、確かめていない星を受け取る、偽物を受け取る、という分岐はありません。

### なぜ確認は1タップで真実を見せるのか（REQ-6.6.4）

この試練は、1つの考え（L3）を演出する場面です: 助手が持ってきたものは間違っているかもしれないので、受け取る前に確かめる。6歳の子にそれを感じてもらうため、野原は、いつも効いて1タップで済む確認を与えます。これはゲームの規則であり、本物のAIについての主張ではありません:

- 本物の確認はもっと難しい。手間がかかり、できないこともあり、確認そのものが間違うこともある。ゲームは違うとは言いません。言葉は、この5つの星に起きたことだけを言います。
- 偽物の星は嘘ではありません。ウィスプは持ってくるつもりはなく、取り違えました。ゲームはそれをメッセージと、変わらないウィスプの顔で見せます。助手は決して敵ではありません（REQ-6.4）。
- 本物のAIがいつも間違えるとも、決して間違えないとも、確認が面倒な作業だとも言いません。子どもの作業は、ごく普通で理にかなったこととして見せます: 見て、それから見たものを受け取る。
- 確かめる前は5つの星が同じに見える理由: 偽物が見ただけでわかるなら、子どもは確認を飛ばしても勝てて、教えが「かしこくなろう」になり「確かめよう」にならない。表の「より明るく光る偽物」は、見つかったあとの偽物の見た目（空の星のまわりの、大きく淡い光）として残します。そこでは見た目であって、唯一の目印ではありません。
- 受け取りに5回の確認が要る理由: 受け取りは子どもが受け入れるという行為です。早い受け取りを許すと、「まだ未確認の星がある」という2つ目の kept 状態が要り、最初のものが教えないことを何も教えません。確認が終わるまでボタンがそもそもない。reducer も早い `KeepStars` を無視するので、迷い込んだイベントが未確認の星を受け入れることはありません。

### モデル検査（`field.model.test.ts`）

範囲: 野原ボタンによるタイトルからの入口と、その先のすべての状態。「試練1・2のどの状態からも野原に行ける」ではありません（子どもが野原に行けるのはタイトルからだけで、野原に出口はない）。通すために野原の状態を落としません。試練1・2のモデル検査は変えません。

アルファベットは有限で、効かないはずのイベントも含みます:

- タイトルで: `StartField`、`SetLang`（ja、en）、`MoveHeroTo`（2か所）、各星と存在しない2つの番号に対する `CheckStar`、`KeepStars`、`RetryField`、`Tick`（短いものと、プレイが終わる長いもの）、試練1のカード1枚、`Ask`、`Retry`、小屋のイベント（`PickTool`、`GiveTool`、`RetryShed`）。`Start` と `StartShed` は入れない: ほかの試練の入口で、それぞれのモデル検査がある。
- 入口のあと: 上のすべてに加えて、`Start`、言語つきの `Start`、`StartShed`。

モデルは本物の reducer の状態を、ゲームには要らない2つで包みます。子どもがしたことの独立した記録で、reducer からではなくspecから書きます: `record` は、このラウンドで子どもが確かめた星の集合（並び替えた集合。順序の違いで新しい状態にならない）、最後に確かめた星、期待するラウンド、受け取ったかどうか。`plays` は、受け取りの結果の数（2は「2以上」）で、ゲームが実際にしたことから数えるので、壊れたゲームが遊び直しを偽ることはありません。モデルのテストは自前のラウンド表の写しを持つので、ソースの表を変えるとテストが失敗します。

| 検査 | 内容 |
|---|---|
| 不変条件 | `phase`/`trial`/`field` が合う（試練3の外では `field` は初期値）。野原でレーン・プレイ・小屋は初期値のまま。野原の確認済みの集合と `last` が記録と等しい。ラウンドが期待どおり。受け取り済みの野原は記録で5つ確認済みで到達した。受け取った星は表の本物の星で、偽物は含まれない。表のどのラウンドにも偽物が1つか2つある |
| ゴール1 | どの状態からも受け取りの結果に到達できる（ソフトロック） |
| ゴール2 | どの状態からも野原の新しいラウンド（何も確かめていない）に到達できる |
| ゴール3 | どの状態からも2回目の受け取りの結果に到達できる（`plays` が2）: 遊び直し |
| 到達の証拠 | 偽物が見つかった、本物が見つかった、受け取りの結果、2回目の受け取りの結果への最短トレース。「この状態にならない」という不変条件から得る |
| 状態数 | 1,968。テストと、タスク3.1の Result に記録: タイトル（2言語 x ヒーロー2か所）と野原（2 x 2 を、81状態の進行中のラウンド6つと受け取りの結果5つのそれぞれに） |

規則を意図的に壊したときに失敗しなければならず、反例はテストに残します:

| 意図的な破壊 | 失敗する検査 | 反例 |
|---|---|---|
| `KeepStars` が星が未確認でも効く | 早すぎる受け取りの不変条件 | `StartField, KeepStars` |
| `CheckStar` が次の星も確かめる | 確認済みの集合の不変条件 | `StartField, CheckStar 0` |
| 2回目の `CheckStar` が星の確認を外す | 確認済みの集合の不変条件 | `StartField, CheckStar 0, CheckStar 0` |
| `CheckStar` が次のラウンドへ動かす | ラウンドの不変条件 | `StartField, CheckStar 0` |
| `KeepStars` を無視する | ゴール1がすべての状態で行き詰まる | 開始状態、トレースは空 |
| `RetryField` を無視する | ゴール2（新しいラウンド）が星を1つ確かめるとすぐ行き詰まり、ゴール3（遊び直し）は開始から。ゴール1は成り立つ | `StartField, CheckStar 0`、開始状態でトレースは空 |
| `Tick` が野原で時計を進める | run の不変条件 | `StartField, Tick 1000` |

破壊は、試練1・2と同じく、本物の `reduce` を包む `step` です。そのためにソースは編集しません。壊れたゲームは記録からいろいろな形でずれるので、壊れたゲームの検査は状態の同一性をゆるくし（言語、ヒーロー、正確な時計を除く）、1つの星についての破壊では小さなアルファベットを使います。

## 文言（`src/content/`）

`strings.ja.json` と `strings.en.json` に、同じキーで `field` グループを足します。`{0}` は数（数字なので kid ゲートを通る）、`⏎` は改行です。

| キー | ja | en | 使う場所 |
|---|---|---|---|
| `field.enter` | ほしを たしかめよう | Check the stars | タイトルの野原ボタン |
| `field.guide` | ひとつずつ たしかめて⏎ほんものを うけとろう | Check each star first,⏎then keep the real ones | 上の行。常に |
| `field.start` | ウィスプの ほし 5こ⏎タップして たしかめよう | The wisp brought 5 stars⏎Tap one to check it | まだ何も確かめていない |
| `field.real` | この ほしは ほんもの！ | This star is real! | 最後に確かめた星が本物 |
| `field.fake` | にせものだった！⏎ウィスプも まちがえるよ | That one is a fake!⏎The wisp mixed it up | 最後に確かめた星が偽物 |
| `field.kept` | ほんものの ほしを⏎{0}こ うけとったよ | You kept {0} real stars | 受け取りの結果のメッセージ |
| `field.lesson` | たしかめてから⏎ほんものだけ うけとったね | You checked each star⏎and kept the real ones | 締めの文。受け取りの結果だけ |
| `field.keep` | ほんものを うけとる | Keep the real stars | 5つ確かめたときのボタン |
| `field.again` | つぎの ほしを みる | Next stars | 受け取り後のボタン |
| `field.marks.real` | ほんもの | real | 本物の星の下のラベル |
| `field.marks.fake` | にせもの | fake | 偽物の星の下のラベル |

この言葉にした理由:

- **案内は両方の手順を言い**（確かめる、それから受け取る）、常に画面に出ているので、最初のタップの前から順番がわかります。`start` のメッセージはそれを繰り返さず、ウィスプがしたことを言います。
- **開始のメッセージは両言語で同じことを言います。** 日本語の最初の案は、ウィスプが星を持ってきたことしか言わず、英語はタップして確かめるとも言っていました（ルーブリックの「日本語と英語が同じことを言う」）。日本語は今 `ウィスプの ほし 5こ` / `タップして たしかめよう` です。
- **「ウィスプ」ではなく「にせもの」。** 表の言葉は「wisps」ですが、子ども向けの言葉は「fake」（`にせもの`）です。助手もウィスプと呼ばれるからです（Decisions）。
- **`fake` のメッセージ「The wisp mixed it up」。** `まちがえる` / 「mixed it up」はウィスプの正直な間違いです: ウィスプは間違えることがある、でも悪気はない。`ウィスプも まちがえるよ` の「も」は、ウィスプを、取り違えるすべての人のひとりに置きます。嘘、だます、責めるという言葉はありません（REQ-6.4.2）。この行は本物の星には出ず、ラベルが星の上で言葉を担います。
- **`kept` は数を言います。** 「You kept 3 real stars」は何を受け取ったかを子どもに伝えます。数は3か4なので、言わなくても偽物がいくつあったかも伝わります。
- **締めの文**は、子どもがしたことを、した順（確かめて、受け取った）に振り返り、受け取りのメッセージと同じ文を共有しません。kid-reader の確認（`kid-reader` エージェントはこのセッションでは実行できないので、`.kiro/agents/kid-reader.md` のルーブリックを手で当て、結果はプルリクエストに載せる）のあと、英語は方向どおりに保ちます。日本語の最初の行は `たしかめてから`（「確かめたあとで」）にしました: 方向の `ひとつずつ たしかめて` は案内の最初の行でもあり、締めの文がそれを繰り返してしまうからです。英語の行は21字と23字。レイアウトが上限です（22 px で 320 px の折り返し。タスク6.1で画面で確かめ、テストは英語の1行を24字まで許す）。次のプレイテストでは、子どもが「each star」を自分がタップした5つとして読むかを確かめます。
- **ボタンは起きることを言います。** `Keep the real stars` は行為と対象を名指します。`Next stars` は、星が違うので「again」と言いません。子どもの間違いのやり直しではありません。
- **本物のAIについての主張なし。** どの文字列も、助手がいつも間違える・いつも正しい、嘘をつく、確認がいつもうまくいく、友だちだ、とは言いません。content のテストが、専用の語リスト（下）と、ウィスプを責める語の2つ目のリストで確かめます。

content のテストは、数をとるすべてのメッセージに3と4を入れて、日本語のルール（漢字なし、ラテン文字なし、12字、2行）を当てます。`lane`、`shed`、`run` の文字列は変えません。

## ゲーム（`src/game/`）

### 入口とシーンの選択

- `TitleScene` に2つ目のボタンを足します: 金色のパネル（`drawButton`）に小さな星と `field.enter`、(195, 648)、300 x 80、小屋ボタン (195, 736) の上。場所を作るため、タイトルのウィスプを (285, 590) から (285, 538) へ、ヒーローを (110, 600) から (110, 548) へ動かします。`field-layout.ts` の `titleArt` が両方を持ちます。ボタン自身のハンドラーが `StartField` を dispatch します。既存の「何にも当たらなかった押下が試練1を始める」守りがすでにこれをカバーします: ボタンはオブジェクトなので、その上の押下は `StartField` だけに届きます。万一両方が走っても、効くのは最初のものだけです: `StartField` のあとの `Start` は言語を設定するだけで、`Start` のあとの `StartField` はゲームがタイトルを離れているので無視されます。

- `boot.ts` は `FieldScene` を登録する。

### View（`field-view.ts`）

`fieldView(state)` は単純なデータを返し、シーンがそれを描きます:

```ts
type StarView = {
  index: number;
  mark: StarMark;                      // unchecked | real | fake
  label: string;                       // 未確認の間は ""
  picture: "solid" | "hollow";         // 輪郭だけは偽物の星のみ
  ticked: boolean;                     // バッジと枠: 本物の星
  alpha: number;                       // 受け取り後の偽物の星は 0.3、それ以外は 1
};
type FieldView = {
  guide: string;
  message: string;
  button: { text: string; event: FieldEvent } | null;  // ready なら受け取り、kept なら次の星
  stars: StarView[];
  lesson: string | null;               // 受け取りの結果のみ
  last: number | null;                 // 最後に確かめた星（演出用）。受け取り後は null
};
```

`message` と `lesson` は `strings[lang].field` から来ます。メッセージは、受け取り後は `kept`（数つき）、何も確かめていない間は `start`、そうでなければ星 `last` に対する `real` か `fake` です。view は時間にも絵にも依存しません。2つの補助関数が、シーンの演出のために前後の view を比べます: `justChecked`（今確かめた星）と `justKept`。

### シーン（`scenes/FieldScene.ts`）と絵（`ui/`）

`ShedScene` のように薄く: レイアウトからオブジェクトを作り、ゲームを購読し、`fieldView` を描き、星のタップで `CheckStar` を、ボタンのイベントを dispatch し、短い演出を出します。`Tick` は dispatch しないので、野原では何も時間を数えません。Phaser はシーンのオブジェクトを再利用するので、フィールドは `create` でリセットします。ヒーローの床ドラッグは小屋と同じです: 何にも当たらなかった押下はヒーローを歩かせ、星やボタンの上の押下は歩かせません。

絵はコードだけです: `ui/star-card.ts`（ウィジェット: スロットのパネル、星、ラベル、バッジ）、`ui/field-art.ts`（金色のハローつきの塗りの星、大きく淡いハローと点線の輪郭の輪郭だけの星）。**塗りの**星は既存の `drawStar` で、**本物**は選択のしるし（太い枠とチェック）が加わり、**偽物**は暗いスロットに点線の輪郭だけで、ラベルは文字です。確認の演出は星での波紋と、本物の星では火花、偽物ではウィスプが一度傾きます。受け取りでは、受け取った星すべてから火花が飛びます。星は順にぽんと現れ、少しだけ上下に揺れます。ウィスプの顔はどの段階でも既存のものです。

### スモークが絵をどう見るか

野原はキャンバスに描かれ、DOMには写しがないので、「偽物」と言う状態は、星が輪郭だけに描かれなくても通ってしまいます。スモークは星ごとに2つの名前のついた点（`field-layout.ts`）をスクリーンショットから読みます: 星の中心は塗りの星なら明るく、輪郭だけなら暗く、バッジの円の中の点は本物の星だけ明るい。だから、未確認は「塗り、バッジなし」、本物は「塗り、バッジあり」、偽物は「輪郭、バッジなし」と読めます。文字は、試練1・2のスモークと同じく、メッセージと締めの文の枠の中の明るいピクセルとして数えます。ピクセルの読み取りは `node:zlib` だけを使います。

## Decisions と代替案

- **確認は真実を見せる。確かめる前の星は同じに見える。** 代替案: 見える目印（偽物がより光る）は、確認を飛ばしても勝てるようにしてしまう。失敗しうる確認は、1タップで何も教えない。「より明るく光る」は、見つかった偽物の見た目として残す。
- **受け取りは5つ確かめたあとに1回、全部まとめて。** 代替案: 星ごとに2回目のタップで受け取る（10タップと、星ごとの受け取り済み状態）、または早い受け取り（新しいことを教えない途中の状態）。「確かめた本物だけを受け取る」という依頼の言葉は、ボタン（早くは出ない）と reducer（INV-27、INV-28）の両方で守られる。
- **受け取りはボタンで、ウィスプのタップではない。** 試練2では受け渡しが要点（道具をウィスプに渡す）。ここでの要点は、子どもが受け入れると決めることで、行為に名前のあるボタン（「Keep the real stars」）がそれを言う。ウィスプは親しみやすいままで、タップ対象ではない。
- **偽物は「fake star」で、「wisp」ではない。** 背景に記録。
- **4つの固定のラウンドの表で、乱数ではない。** 「ラウンドの表」を参照。モデル検査と性質テストはラウンドに名前をつける。
- **しるしと結果は1つの値。** `checking` では `checked` と `round`、`kept` では `round`。
- **新しい phase ではなく、`trial` で守る。** INV-1 は3つの phase のまま。
- **別のイベント。** `CheckStar`、`KeepStars`、`RetryField`、`StartField` は4つの名前のコストで、試練をまたぐ影響の余地をなくす（INV-31、INV-32）。
- **タイトルのボタンは画面ではなくオブジェクト。** 選択画面はルーターで、範囲外。
- **タイトルの絵を52ピクセル上へ。** 2つのボタンが絵の下に、間を8ピクセルあけて収まるようにするため。小屋ボタンは動かないので、試練2のレイアウトとテストは手つかず。変わるのは `titleArtBottom`（660から606）だけで、古い値を固定するテストはない。試練3のボタンは試練2のボタンの上にある。
- **野原に出口はない。** 小屋と同じ理由: 「戻る」ボタンには `Leave` イベントと、ほかの試練の状態をリセットするタイトルへの復帰が要り、別の機能。「見つけたが直していないこと」に載せる。再読み込みでタイトルに戻る。
- **ウィスプはタップ対象ではない。** 野原の要点は星を確かめることで、何もしない対象は子どもを惑わせる。「ウィスプが持ってきた」が見えるよう、画面には残す。
- **モデルの `record` と `plays`** はテストの中にあり、`GameState` にはない: ゲームには要らない。
- **英語の行は20字を超える**（21字と23字）。試練2の20字はそのキーの上限で、ここではレイアウトが上限。

## リスク

- 作成環境ではWebKitが起動しない（システムライブラリがない。`docs/evidence/didnt-work.md`）。モバイルのスモークはそこではiPhone 13のタッチプロファイルのChromiumで動かし、その旨を記す。本物のWebKitの実行はCIの分。CIのスモークが緑になるまで、タスクは完了と呼ばない。
- ピクセルのプローブは絵に依存する。星の絵が動いてプローブがずれればスモークが失敗する。プローブと絵は `field-layout.ts` を共有するので、数字は1か所で変わる。
- 絵はコードで、スクリーンショットで目で判断する。輪郭だけの星とバッジは、組み上がった画面を最初に見たあとで、2回目の手直しが要るかもしれない。
- 子どもが読まずに5つとも確かめるかもしれない。そのとき教えは、締めの文とメッセージにかかる。次のプレイテストでは、子どもが「ウィスプが間違えた」と言うか、星を見てからタップするかを記録する。
- 子どもが「ウィスプが取り違えた」を「ウィスプはおバカ」と読むかもしれない。言葉にその理由はないが、プレイテストで記録する。

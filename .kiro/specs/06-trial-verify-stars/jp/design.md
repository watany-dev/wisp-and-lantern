## 子どもがすること

```text
title --野原のボタンをタップ（ゲームがシードを引く）--> sorting, ラウンド0, 何も分けていない
sorting --InspectStar i（i は分けていない）--> sorting, 星 i がレンズに入る（2つの判定ボタンが出る）
sorting --SortStar v, v が星について正しい--> sorting, 星が分けられ、レンズが閉じる（メッセージ: そのとおり）
sorting --SortStar v, v が星について間違い--> sorting, 何も分けず、レンズが閉じる（メッセージ: もう一度見よう）
sorting --レンズに星がない SortStar--> 同じ状態
sorting --KeepStars, 分けていない星がある--> 同じ状態
sorting --KeepStars, 5つ全部分けた, 最後のラウンドではない--> kept
sorting --KeepStars, 5つ全部分けた, 1周の最後のラウンド--> cleared
kept    --RetryField--> sorting, 次のラウンド
cleared --RetryField--> sorting, 次のラウンド（新しい1周）
cleared --LeaveField--> title
```

`cleared` が試練の成功です。1周は2ラウンドで、表は4ラウンドあるので、「もういちど」はラウンド2と3、そのあとまた0と1を始めます。受け取るボタンは5つ全部分けたときだけ画面に出ます。リデューサーも早い `KeepStars` を断るので、規則はボタンに頼りません。タイトルのそれ以外の場所のタップは、これまで通り試練1を始めます。

## ドメイン（`src/domain/`）

### 状態

`GameState` は1つフィールドが増え、新しい `phase` はありません:

```ts
// field.ts
export const starCount = 5;
export const roundsPerRun = 2;   // 2ラウンド目を受け取ると試練がクリアになる
export const roundCount = 4;     // 組が繰り返すまでのラウンド数（2周分）
export type Verdict = "real" | "fake";
export type Note = { star: number; said: Verdict };
export type Field =
  | { stage: "sorting"; seed: number; round: number; sorted: readonly boolean[]; looking: number | null; note: Note | null }
  | { stage: "kept"; seed: number; round: number }
  | { stage: "cleared"; seed: number; round: number };
export const initialField: Field = { stage: "sorting", seed: 0, round: 0, sorted: [false x5], looking: null, note: null };

// state.ts
export const trials = { lane: 1, shed: 2, field: 3 } as const;
export type GameState = { /* 以前と同じ */ field: Field };
```

この形にした理由:

- **真実は保存しない。** どの星が偽物かは `seed` と `round` の関数（`fakesOf`）。状態が持つのは子どもがしたことだけ: 分けた星（`sorted`）、レンズにある星（`looking`）、最後の判定（`note`）。だから印がラウンドと食い違うことはなく、「受け取った星は本物」は導かれるもので、コピーではない（REQ-6.8.5）。`markOf` は星が分けられるまで `unsorted`、そのあとは `real` か `fake`。ひとことが合っていたかどうかも導く（`noteWasRight`）。
- **`sorted` は「正しく分けた」という意味。** 間違った判定は false のままにする。取り消したり隠したりする「間違って分けた」状態がないので、間違った判定は無料になる（INV-35）。
- **`looking` が、判定に「見る」が要る理由。** `SortStar` が運ぶのは判定だけで、星はレンズにあるもの。レンズに星がなければ何もしない（INV-33）。「見てから決める」が画面ではなくリデューサーの規則になるのはこの仕組み。
- **`note` はメッセージのため。** viewは状態だけの関数なので、状態が最後の判定を覚える。`InspectStar` が消し、`SortStar` が設定する。間違った判定はレンズも閉じるので、子どもはもう一度星をタップする: もう一度見ることは、自分でする一手になる。
- **`kept` と `cleared` にはこれ以上フィールドがない。** 5つ全部分けた状態で入るので、すべての印がわかっていて真実と等しい。印をまた持てば2つ目のコピーになる。型で区別できるよう、ユニオンの別のメンバーにする。
- **`phase` は `title | trial | over` のまま。** 野原は `phase` が `trial` で `trial` が3。シーンは `trial` に従う。**`field` は常にある**。`trial` が3の間以外は `initialField`（INV-31）。
- **`round` は有限。** 常に0〜3なので、モデル検査の状態空間は有限で、`RetryField` は3から0へ戻る。

### 偽物の星: 表ではなくシード

`fakesOf(seed, round)` はラウンドの偽物の星を昇順で返す: 1周の最初のラウンドは1つ、2つ目は2つ。整数の小さな線形合同法の一歩（`Math.imul`、`Math.random` なし、時計なし）で、`seed` と `round` から作り、5つの星から重ならないものを選ぶ。同じシードは必ず同じ4ラウンドになる。

- **なぜシードか。** 最初の版は固定した4ラウンドの表だった。2回遊んだ子は「4番目の星が偽物」と覚えて、見なくなる。それは教えたいことの逆。シードなら偽物は訪問ごとに変わり、単体テストはシード0〜3の正確な組を固定する。
- **シードの出どころ。** タイトルのシーンが `newSeed()`（`src/game/seed.ts`。テストのために `Math.random` を差し込める）で引き、`StartField { seed }` を送る。ドメインは整数にして（`seed >>> 0`）保存するだけで、数を引くことはない（ハードルール3、ADR 0001）。スモークは状態からシードを読み、同じ純粋関数で期待する偽物を計算する。`fakesOf` 自体を固定するのは単体テスト。
- **隣のラウンドは違う。** 大きさが 1, 2, 1, 2 と交互なので、続く2ラウンド、また最後から最初への折り返しでも、同じ組にはならない。やり直しの処理は要らない。
- **偏り。** 2,000のシードで、どのラウンドでも各星はほぼ同じ回数偽物になる（書いたときに確認した。単体テストは、いつも本物のままの星がないことを確かめる）。

関数（`field.ts`）: `fakesOf`、`isFake`、`shineOf`、`markOf`、`noteWasRight`、`isReady`、`keptStars`、`isLastRound`、`reduceField`（何も変わらないとき `field` 自身を返す）。

`reduceField`:

- `InspectStar { index }`: 分けている間、`index` が0〜4の整数で、その星がまだ分けられておらず、すでにレンズにある星でもないとき: `looking` が `index` になり、`note` が `null` になる。そうでなければ変化なし。
- `SortStar { verdict }`: 分けている間で、レンズに星があるとき。判定が星について正しければ、その星が分けられる。どちらでも `looking` は `null` に、`note` は `{ star, said: verdict }` になる。
- `KeepStars`: 5つ全部分けたとき: `kept`。そのラウンドが1周の最後なら `cleared`。
- `RetryField`: `kept` か `cleared` から、次のラウンド（`(round + 1) % 4`、同じシード）の新しい `sorting`。

2つの星を同時に分ける、間違った判定で星を分ける、分けていない星を受け取る、偽物を受け取る、という枝はない。

### 手がかりが見え、判定が1タップで判定される理由（REQ-6.6.4）

この試練は1つの考え（L3）のための演出の場面。助手が持ってきたものは間違っていることがあるので、受け取る前によく見て、自分で決める。6歳の子にそれを感じさせるために、野原は、見ればわかる手がかりを見せ、子どもの判定をすぐに判定する。これはゲームの規則であり、本物のAIについての主張ではない:

- 本物の確認はもっと難しい。手間がかかるし、できないこともあるし、確認自体が間違うこともある。ゲームは違うとは言わない。言葉は、この5つの星に起きたことだけを言う。
- 偽物の星は嘘ではない。ウィスプはわざと持ってきたのではなく、取り違えた。ゲームはそれを、メッセージと、変わらないウィスプの顔で示す。助手が敵になることはない（REQ-6.4）。
- 手がかりをタップの前から見せる理由: 改訂1はタップまで隠していて、プレビューは、そのときタップが遊びのすべてだったことを示した。大事なのは、子どもが見て決めること。`docs/learning-design.md` の「本物より明るく光る」が、その表のとおり、主な手がかりになる。
- タップではなく子どもの判定が決める理由: ゲームが代わりに決めてはいけない。間違った判定は何も分けず、何も直さないので、子どもは自分の選択で見つけ、またよく見る。
- 間違った判定を繰り返せる理由: 間違うことへの恐れは、教えたいことの逆。メッセージは何が起きたか（偽物が混ざっていた、その星は本物だった）を言って、もう一度見ようと誘う。何も数えない。
- 当てずっぽうはできる: ボタンが2つなので、両方を押せる。間違うたびに同じやさしいメッセージが出てレンズが閉じるので、安易な道は毎回星をタップし直す一手がかかり、分けられた星は言葉とチェックを見せるので、立っているのは子ども自身の選択。大事なのは得点ではなく、見ること。

### モデル検査（`field.model.test.ts`）

範囲: 2つのシードでの野原ボタンからのタイトルの入口、そのあとのすべての状態、タイトルへ戻る退出。「試練1・2のどの状態からも野原に行ける」ではなく（子どもが野原に行くのはタイトルからだけ）、通すために野原の状態を落とすこともない。試練1・2のモデル検査は変えない。

アルファベットは有限で、効いてはいけないイベントも含む: シード0と1の `StartField`、`SetLang`（ja、en）、`MoveHeroTo`（2つの位置）、各星と存在しない2つの番号への `InspectStar`、両方の判定（レンズに星があってもなくても）、`KeepStars`、`RetryField`、`LeaveField`、`Tick`（短いものと1周を終わらせるもの）、試練1のカード1枚、`Ask`、`Retry`、小屋のイベント。野原の中ではさらに `Start`、言語つきの `Start`、`StartShed`。

モデルは本物のリデューサーの状態を、子どもがしたことの独立した記録で包む。記録はリデューサーからではなく仕様から書く（`record`: 段階、シード、ラウンド、分けた集合、レンズの星、最後の判定。タイトルでは `null`）。それと `clears`、これまでのクリア数（上限2。ゲームがしたことから数えるので、壊れたゲームが遊び直しを偽装できない）。テストは、シード0と1の偽物について自分のコピーを持つので、`fakesOf` を変えるとテストが落ちる。

| 検査 | 内容 |
|---|---|
| 不変条件 | タイトルと記録が一致する（野原の状態があるのは記録があるときだけ）。試練3以外で `field` は初期値。レーン、1周、小屋は初期値のまま。`field` は記録と完全に等しい。記録が分けていない星が分けられていない。ラウンドの終わりは記録が言ったときだけ。受け取った星は表の本物で、偽物はない |
| ゴール1 | どの状態からもクリアに行ける（行き詰まりなし） |
| ゴール2 | どの状態からもタイトルに行ける |
| ゴール3 | どの状態からも新しいラウンド（何も分けておらず、レンズも空）に行ける |
| ゴール4 | どの状態からも2回目のクリアに行ける: 遊び直しと、退出してまた入ること |
| 目撃者 | 間違った判定までの最短（3イベント）、クリアまでの最短（入場、2 x 10回の見る・判定、2回の受け取りと再挑戦）、クリア後のタイトルまでの最短 |
| 状態数 | 19,356。テストに記録。シードとラウンドごとに、進行中が241状態（レンズに星があるのが80、最後の判定があってレンズが空なのが160、手つかずが1）と終わった状態が1。言語とヒーローで4倍。タイトルが加わり、そのクリア数の分だけ倍になる |

意図的に規則を壊したときは落ちなければならず、反例はテストに残す（それぞれの破壊は本物の `reduce` を包む `step` で、ソースは編集しない）:

| 意図的な破壊 | 落ちる検査 |
|---|---|
| 間違った判定でも星を分ける（ゲームが子どもを直す） | 3イベントで、野原が記録と食い違う |
| レンズに星がなくても判定が効く | 野原が記録と食い違う: `StartField`、`SortStar` |
| 間違った判定でレンズに星が残る | 野原が記録と食い違う |
| 星が残っていても `KeepStars` が効く | 終わりが早すぎる不変条件: `StartField`、`KeepStars` |
| 最後のラウンドがクリアにならない | 受け取りで、野原が記録と食い違う |
| クリアの前に `LeaveField` が効く | 場所の不変条件: `StartField`、`LeaveField` |
| `KeepStars` が無視される | ゴール1が、最初からどの状態でも行き詰まる |
| `RetryField` が無視される | ゴール1が行き詰まる（2ラウンド目に行けない）。星を1つ見たらゴール3が行き詰まる |
| `LeaveField` が無視される | 野原に入ったらゴール2が行き詰まる |
| 野原で `Tick` が時計を進める | 1周の不変条件: `StartField`、`Tick` |

壊れたゲームは記録からずれ、2つを合わせると本物のゲームよりずっと多くの状態になる。そのため壊れたときの検査は、1つのシード、小さなアルファベット、言語とヒーローを含まない状態の同一視、（不変条件の検査では）すでに不変条件を破った状態を1つにまとめる、を使う。本物の検査は状態全体を使う。

| `field.again` | もういちど | Play again | クリア、左のボタン |
| `field.leave` | タイトルへ | Title | クリア、右のボタン |
| `field.marks.real` | ほんもの | real | 分けた本物の星の下の言葉。判定ボタン |
| `field.marks.fake` | にせもの | fake | 分けた偽物の星の下の言葉。判定ボタン |

言葉を選んだ理由:

- **`look` は手がかりを指す**（「光りとふち」: `ひかり`、`ふち`）。そしてボタンが答える問いを聞く。`ふち` は次のプレイテストで確かめる言葉。
- **正しい判定は平易な言葉で確かめる**（`そのとおり！`）。偽物のほうは、ウィスプの悪気のない取り違えを残す（`ウィスプも まちがえるよ`）: ウィスプも間違うことがあり、悪気も非難もない。
- **間違った判定は、何が起きたかを言って、もう一度見ようと誘う。** `にせものが まざってた` / "A fake got mixed in!" と `ほんものだったよ` / "That one was real!" が事実を言い、`もういちど みてみよう` が誘う。`ちがう`、`ちがった`、`まちがえた`、非難の言葉は避ける。contentテストが確かめる。
- **偽物は「ウィスプ」ではない。** 表の言葉は「ウィスプ」だが、子ども向けの言葉は「にせもの」。助手もウィスプと呼ぶから（Decisions）。
- **`kept` は数字を言う。** 「You kept 3 real stars」は、何を受け取ったかを子どもに伝える。
- **締めくくりの1行** は、子どもがしたことを、した順（よく見て、受け取った）に振り返り、受け取りのメッセージや案内と文を共有しない。
- **ボタンは何が起きるかを言う。** `Keep the real stars` は行為と対象を名指す。`Next stars` は星が違うので「again」と言わない。`Play again` と `Title` はクリアした画面だけ。
- **`noClock`** は添え書きで、ゲームの規則ではない。その2つの試練について本当のことを言っている。
- **本物のAIについての主張はない。** 助手がいつも間違う・いつも正しい、嘘をつく、確認がいつもうまくいく、友だちだ、と言う文字列はない。contentテストが独自の語リストで確かめる。
- **実行していない:** `kid-reader` エージェントはこのセッションから実行できなかった。ルーブリックは手で当てた（プルリクエストを参照）。`うけとる`、`ふち`、`にせもの` は「プレイテストで確認」。

contentテストは、数字を取るメッセージすべてを3と4で描画し、日本語の規則（漢字なし、ラテン文字なし、12文字、2行）を当てる。`lane`、`shed`、`run` の文言は変えない。

## ゲーム（`src/game/`）

### 手がかり（`field-look.ts`）

手がかりはデータなので、テストが色なしでそれがあることを証明できる:

| | 本物の星 | 偽物の星 |
|---|---|---|
| 本体、縁、芯 | 金、濃い金、薄い金 | クリーム白、薄い金、白 |
| かさ（星の半径の倍数の円と、アルファ） | 1.9で0.07、1.55で0.10（金） | 2.3で0.16、1.9で0.22、1.55で0.30（クリーム） |
| 1.5半径のふち | 切れ目のない1本の線 | 別々の12個の点 |

`luma`（グレースケールの画面と同じ重みでの明るさ）、`haloCover`、`glowLuma` が、これらの数から、スロットがある点で見せる明るさを計算する。単体テストが証明すること: 偽物の本体はより明るい。調べる距離で偽物のかさは255のうち40より多く明るい。かさはより遠くまで届く。ふちは種類が違う。点は互いに触れない。`ui/field-art.ts` の描画は、これらの数だけを使う。

手がかりは2つ、主なものと形のもの: 光り方（主なもの。学習設計の表から）とふち。どちらか一方でも本当の違いで、合わせると悪い画面でも残る。スモークで測った値（「スモークはどう絵を見るか」を参照）が余裕を示す。

### タイトル（`title-layout.ts`、`title-view.ts`、`TitleScene.ts`）

プレビューでは「60びょうで いくつ みつかるかな？」が絵とボタンの上に浮かび、タイトルの規則に読めた。今は:

- **試練1のカード**（(195, 372) の枠のあるパネル、340 x 144）が入口（「Tap to start」）と規則（60秒）を持つ。カードをタップしても試練1が始まる: 対象ではないから。
- **2つのボタン**は、それぞれラベルと、その下の添え書き `No timer` / `じかんは ないよ` を持つ。これは本当: 小屋に時計はなく（INV-24）、野原にもない（INV-32）。ラベルは22ピクセルで、絵に重ならない。
- テストがレイアウトを証明する: カードは両方の文を持ち、どちらのボタンにも触れない。絵はその間にある。60秒の文字列はタイトルのほかの文に出ない。
- **ロック。** `LeaveField` のあとシーンは `fromField: true` で再開し、ゲーム時間（`Game.getTime()`。`Clock.now` は `create` の時点でまだ設定されていないことをスモークが示した）の0.7秒の間、どこをタップしても始まる動作を無視する。「Title」をダブルタップした子は、そうしないと2回目のタップで試練1を始めてしまう。
- **タッチの守り。** タイトルは `touchmove` の守り（ページのスクロールやズームを防ぐ）をシーンオブジェクトごとに1回だけ付け、外さない: これはすべてのシーンの守りなので、タイトルが終わるときに外してはいけないし、訪問のたびに付けるとコピーが積み重なる。

### ボタン（`button-lock.ts`、`ui/field-buttons.ts`）

幅の広いボタン（受け取る、「つぎの ほしを みる」）は、2つの狭いボタン（判定、「もういちど」「タイトルへ」）の場所を覆うので、子どものすばやいダブルタップが最初のボタンに代わるボタンに当たる。守りがなければ、その間の画面（分けられた星、受け取った結果、クリアのパネル）を飛ばしてしまう。そこでボタンの組は、現れてから450ミリ秒、押下を無視する（`pressable`、ゲーム時間）。組は持っているidで識別する（`setChanged`）ので、同じボタンの描き直し（言語の変更）はロックをやり直さない。スモークは受け取るボタンを本物のすばやいダブルタップで押し、受け取った結果が残ることを求める。ロックの間に落ちたタップはただ失われ、これはスモークの再試行する `pressUntil` がもともと許していること。

### view（`field-view.ts`）

`fieldView(state)` は素のデータを返し、シーンが描く:

```ts
type StarView = { index; shine: "normal" | "bright"; mark: "unsorted" | "real" | "fake"; label: string;
                  ticked: boolean; looking: boolean; alpha: number };   // 分けた偽物の星は alpha .5
type FieldView = {
  guide: string; message: string; stars: StarView[];
  lens: { shine } | null;                       // レンズにある星
  clear: { title: string; lesson: string } | null;   // クリアしたときだけ
  buttons: { id; text; event; slot: "single" | "left" | "right"; icon: "tick" | "dots" | "none" }[];
  verdict: { star: number; right: boolean } | null;  // 演出のため
  finished: boolean;
};
```

メッセージは、受け取ったあとは `kept`（数字つき）、星がレンズにあるときは `look`、判定の前は `start`、判定のあとは `sortedReal`、`sortedFake`、`missFake`、`missReal`。5つ目の星を分けたときもメッセージはその星のままなので、最後に分けた偽物の星は「ウィスプも まちがえるよ」を保つ。受け取るボタンが次にすることを言う（以前の草案には、それに取って代わる `ready` メッセージがあり、レビューで、偽物の星を最後に分けると悪気のない取り違えの行が失われることがわかった）。ボタン: 星がレンズにある間は2つの判定。全部分けたら受け取る。1ラウンド目のあとは `next`。クリアしたら `again` と `leave`。それ以外はなし。ヘルパー `justSorted` と `justFinished` は、シーンの演出のためにviewの前後を比べる。値で比べるので、言語を変えても演出はやり直されない。

### シーン（`scenes/FieldScene.ts`）と絵（`ui/`）

`ShedScene` のように薄い: レイアウトからオブジェクトを作り、ゲームを購読し、`fieldView` を描き、星のタップには `InspectStar`、ボタンにはそのイベントを送り、短い演出を出す。`Tick` は送らないので、野原は時間を数えない。Phaserはシーンオブジェクトを再利用するので、フィールドは `create` でリセットする。ヒーローの床ドラッグは小屋と同じ: 何にも当たらなかった押下はヒーローを歩かせる。

絵はコードだけ: `ui/field-art.ts`（スロットと、かさ・本体・ふちを描く `drawClueStar`）、`ui/star-card.ts`（スロットのウィジェット: 星、言葉、チェック、レンズにある星の白い枠）、`ui/field-lens.ts`（レンズとクリアのパネル）、`ui/field-buttons.ts`（スロットごとに1つのウィジェット。使わないときは隠す。判定ボタンのチェックと点の輪）。星は1回ぽんと現れたあと静止する: 最初の版の上下の揺れは、スモークのプローブの下でふちを動かし、意味も運ばなかった。レンズのかさは、パネルに収まるよう縮める（`haloLimit`）ので、メッセージを覆わない。演出: 正しい判定は星に波紋、本物の星なら火花（偽物の星ではウィスプが取り違えたので1回かしげる）。間違った判定は星が1回ゆれる。受け取りは受け取った星すべてから火花。赤も、画面の揺れも、音もない。

### スモークはどう絵を見るか

野原はキャンバスに描かれるので、DOMにコピーはなく、状態が「fake」と言っても星が明るく光っていなくても通ってしまう。そこでスモークは、スクリーンショットから、星（とレンズ）ごとに名前のついた4点（上のプローブ）を読み、グレースケールの画面と同じ重みで明るさにする。星の手がかりが**「bright」と読める**のは、かさの点が130（スロット）または93（レンズ。かさが縮められているため）より明るく、**かつ**ふちに隙間がある（点の位置が隙間の位置より55を超えて明るい）とき。**「normal」**はどちらもないとき。それ以外の組み合わせは失敗。測った値（Chromium、iPhone 13プロファイル、3倍）: スロットの本物の星はかさ93、ふちの差はおよそ0（-22〜14）。偽物の星はかさ167、ふちの差99。レンズでは71と0、115と178。グレースケールのテストは `canvas { filter: grayscale(1) }` を足し、1以内で同じ値になる。チェックはバッジの点（分けた本物の星だけ金色）。ボタンは金色の面（幅の広いボタンは2つの狭いボタンの隙間を覆うので、隙間が金色なら幅の広いボタン）。クリアのパネルは金色の言葉。文字は、試練1・2のスモークと同じく、メッセージと締めくくりの1行の枠の中の明るい画素として数える。ピクセルの読み取りは `node:zlib` だけを使う。「無音」の確認は、ページが読み込まれる前に `AudioContext.createOscillator`、`createBufferSource`、`HTMLMediaElement.play` を包み、全部の分けの間に1つも呼ばれないことを求める。

## 決定事項と代案

- **子どもが決め、タップは見るだけ。** 代案: タップで真実を見せる（改訂1。プレビューで却下: 何も決めなかった）。星を「ほんもの」か「にせもの」のかごにドラッグする（80以上の対象2つとドラッグがいる。指1本のタップの規則に反する）。長押しで即判定（長押しはREQ-6.9.2が禁じる）。見たあとの2つのボタンは、それぞれ1タップで、言葉なしで読め（チェックと点の輪）、見ることを独立した一手に保つ。
- **間違った判定は何も分けず、レンズを閉じ、ひとことを残す。** 代案: 間違った判定で星を間違って分け、受け取りで失敗にする（5つ分けてから知り、取り消しもいる。偽物が状態に入ってしまう）。間違った判定でその星のそのボタンを止める（2回目が強制され、ゲームが子どもに代わって決めることになる）。間違いの回数（得点になる。この試練にあってはならない）。レンズを閉じると子どもはもう一度見ることになり、それが教えたいこと。
- **手がかりは最初から見え、主には明るいかさ。** 改訂1はタップまで隠していた。学習設計は偽物は明るく光ると言う。点のふちは、グレースケールや低コントラストの画面でも働くよう形の2つ目の手がかり。代案: 色（ハードルール7が却下）。ちらつき（動きは意味を運んではならず、スモークも読めない）。偽物にラベル（見ることをなくしてしまう）。
- **表ではなくシード。** 「偽物の星: シード」を参照。代案: 固定の表はもっと簡単で最初の版だった。子どもが位置を覚えてしまう。シードの費用は、イベントのフィールド1つと、固定した単体テスト。
- **2ラウンドで1周、そしてクリア。** 最初のラウンドは偽物1つ、2つ目は2つで、少しだけ上がる。代案: 1ラウンド（試練らしさがなく、上がりもない）。3つ以上（6歳にはタップが増える。1ラウンドは10タップと受け取り）。「もういちど」が新しくなるよう、表は4ラウンド。
- **受け取るのは、5つ全部分けたあとのボタン。** 代案: 星ごとに2回目のタップで受け取る（10タップと星ごとの受け取り済み状態）、または早い受け取り（新しいことを教えない中途半端な状態）。「確かめた本物だけ受け取る」はボタン（早くは出ない）とリデューサー（INV-27、INV-28）の両方で成り立つ。
- **受け取るのはボタンで、ウィスプのタップではない。** 試練2では手渡しが要点（道具はウィスプに渡す）。ここでは子どもが受け取ると決めることが要点で、行為を名指すボタンがそう言う。
- **偽物は「偽物の星」で、「ウィスプ」ではない。** 「背景」に記録。
- **印と結果は1つの値。** 分けている間は `sorted` と `round` と `seed`、そのあとは `round` と `seed`。
- **新しい phase ではなく `trial` で守る。** INV-1は3つの phase を保つ。
- **別々のイベント。** `InspectStar`、`SortStar`、`KeepStars`、`RetryField`、`LeaveField`、`StartField` は6つの名前の費用で、試練をまたぐ作用の可能性をなくす（INV-31、INV-32）。
- **タイトルのボタンは画面ではなく対象。** 選択画面はルーターで、範囲外。
- **タイトルの絵は52ピクセル上げる。** 2つのボタンが、間8ピクセルで絵の下に収まるように。小屋のボタンは動かないので、試練2のレイアウトとテストは手つかず。変わるのは `titleArtBottom`（660から606）だけで、それを固定したテストはなかった。試練3のボタンは試練2のボタンの上にある。
- **試練1のカードとボタンの添え書き**（REQ-6.1.6）は、3つのタイトル文字列の置き場所を変え、キーを1つ足す。ボタンの上に見出し（「ほかのあそび」）を置く案は、規則について何も言わない文字列が増える。添え書きは、子どもが見る場所で事実（タイマーなし）を言う。
- **戻る道はクリアした画面だけ。** プレイ中の「もどる」ボタンは、どの段階でも有効な `Leave`、うっかり押した子への確認、進行の扱いの決定が要る。クリアは自然な終わりで、ほかは再読み込みで足りる。途中で行き詰まった子が再読み込みで失うものはない。
- **退出のあと、タイトルは0.7秒タップを無視する。** ダブルタップは試練1を始めてしまう。ゲーム時間（`Game.getTime()`）を使うのは、`create` が動くときシーンの時計が設定されていないから。
- **ウィスプはタップ対象ではない。** 野原の要点は星を見ることで、何もしない対象は子どもを惑わす。「ウィスプが持ってきた」が見えるよう、画面には残す。
- **モデルの `record` と `clears`** はテストの中にあり、`GameState` にはない: ゲームには使い道がない。
- **英語の行は28文字まで。** メッセージは22ピクセルで340ピクセルに折り返す。スモークのスクリーンショットで収まることを確かめた。

## リスク

- WebKitは作成環境で起動しない（システムライブラリがない。`docs/evidence/didnt-work.md`）。モバイルのスモークはそこでiPhone 13のタッチプロファイルのChromiumで動き、そう明記する。本物のWebKitはCIが動かす。CIのスモークが緑になるまでタスクを完了と呼ばない。
- ピクセルのプローブは描画に依存する。星の絵を変えてプローブがずれればスモークが落ちる。プローブと描画は `field-layout.ts` と `field-look.ts` を共有するので、数字は1か所で変わる。閾値はChromiumで測った。WebKitは点を少し違うにじみ方で描くが、余裕（ふちの差99に対し閾値55、かさ167に対し130、レンズは93に対し71と115）がそれを吸収するはず。レンズの閾値が最も余裕が薄い（71に対し93、115に対し93）。
- 絵はコードなので、スクリーンショットで目で判断する。
- 子どもは見ずに両方のボタンを押すかもしれない。そのとき学びはメッセージと締めくくりの1行にかかる。次のプレイテストで、ウィスプが取り違えたと子どもが言うか、ボタンの前に光とふちを見るか、間違った判定のあとの「にせものが まざってた」をやさしく読むかを記録する。
- 子どもが「ウィスプも まちがえるよ」を「ウィスプはおバカ」と読むかもしれない。言葉にその理由はないが、プレイテストで記録する。
- モデル検査は19,356状態で約1秒かかる。壊れたゲームの実行は1回1〜2秒。

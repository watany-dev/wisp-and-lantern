## 背景

`docs/learning-design.md` は試練3を「助手が持ってきた5つの星のうち1〜2個はウィスプ（偽物）。受け入れる前にタップして確かめる。ウィスプ = 本物より明るく光る偽物」としています。子どもはウィスプが集めた5つの星を見ます。偽物は明るく光り、ふちが点々でできています。よく見れば誰にでもわかる違いです。子どもは星をタップして近くで見て、本物か偽物かを決め、そのあとで初めてゲームが合っていたかを教えます。間違えても大ごとではありません。星はそのままで、子どもはもう一度見ます。5つとも分けたら本物を受け取り、ウィスプが新しい5つの星を持ってきます。改訂3はこれに60秒を重ねます: 正しい判定は点が入り、続けて正しいほど多く入り、間違った判定は続きが切れるだけです。当てずっぽうの子はよく間違えて連続を失い、光とふちを見る子は正しく答えて多く得点するので、得点が報いるのはタップの速さでなく学習です。ウィスプはわざと偽物を持ってきたのではなく、取り違えたのです。子どもは、受け取る前によく見て決めること、そして助手は嘘つきでなくても間違えることがあることを学びます。

表は偽物を「ウィスプ」（鬼火）と呼んでいますが、このゲームの助手も「ウィスプ」です。6歳の子は「ウィスプは偽物」を「あのウィスプが偽物」と読むでしょう。そこで子ども向けの言葉は**偽物の星**（`にせものの ほし`）といい、「ウィスプ」とは決して呼びません。`design.md` の Decisions を参照してください。

## 用語

- **野原（Field）**: 絵の中の暗い草地。ウィスプが集めた星が置かれている。
- **星（Star）**: 野原にある5つの絵。それぞれ本物か偽物。星には0〜4の番号があり、上の段を左から右、次に下の段。
- **ラウンド（Round）**: 野原の1回分。新しい5つの星から、受け取った結果まで。ラウンドはシードから出る4つが順に来て、また最初に戻る。60秒の1周では、子どもが進めた分だけある。
- **1周（Run）**: 野原の60秒。タイトルのボタン（かもう一度）のタップから時間切れまで。試練1と同じ `Run`（時計、得点、連続、セッションのベスト）を使う。
- **シード（Seed）**: 野原を開くときにゲームが引く整数（ドメインではない）。同じシードなら、同じラウンドで同じ偽物になる。
- **偽物の星（Fake star）**: 本物でない星。1ラウンドに1つか2つ。ウィスプの悪気のない取り違え。
- **手がかり（Clue）**: 偽物が本物と違うところ。最初から見える。偽物は明るく光り（大きく強く白いかさ）、ふちが別々の点の輪になる。本物のふちは切れ目のない1本の線。
- **レンズ（Lens）**: メッセージの下で、見ている星を同じ手がかりのまま大きく見せる場所。
- **見る（Look）**: 子どもが星をタップして、レンズに入れる。見るだけでは何も分けない。
- **判定（Verdict）**: レンズの中の星について、子どもが決めること。「ほんもの」か「にせもの」。2つのボタンのどちらか。
- **分ける（Sort）**: 判定が合っていた星は分けられたことになる。間違った判定は何も分けない。
- **ひとこと（Note）**: 最後の判定と、その星。メッセージはそれに何が起きたかを言う。
- **受け取る（Keep）**: 子どもがボタンを押して本物を受け入れること。星が受け入れられる唯一の方法。
- **連続（Streak）**: 続けて正しかった判定。間違った判定で切れる。正しい判定の点は100に、連続1つにつき50を足したもの（4まで）。
- **終了画面（End screen）**: 時計が0になった1周が見せるもの。得点とベスト、「もう一度」と「タイトル」。
- **締めくくりの1行（Closing line）**: 受け取るたびに出る短い文。子どもがしたことを振り返る: よく見て、本物だけ受け取った。

## 要件

### REQ-6.1 タップで野原に入る

6歳の子として、タイトルから指でウィスプの星野原を開き、大人なしで遊びたい。

1. タイトル画面に、試練3用の2つ目の追加タップ対象を出す: 星の絵と、子どもの言語の短いラベルがあるボタン。80 x 80 ゲームピクセル以上。小屋のボタンの上にあり、小屋のボタンやタイトルのウィスプ・ヒーローと重ならない。
2. ボタンをタップすると野原が開き、1周が始まる。状態は `title` から `trial`（`trial` 3）になり、新しいシードのラウンド0、満タンの60秒の時計、得点0、連続0になる。セッションのベストは引き継ぐ。レーンと小屋は手つかず。シードはゲームがドメインの外で引き、イベントに載せて送る。ドメインは何も引かない。
3. このボタンのタップが、同時に試練1を始めたり小屋を開いたりすることはなく、小屋のボタンのタップが野原を開くこともない。タイトルのそれ以外の場所のタップは、これまで通り試練1を始める。終了画面の「もう一度」ボタンも、新しい1周を始める（REQ-4.6）。
4. 入口は、普通の画面での普通のタップ。judge用URL、隠しジェスチャー、コンソール呼び出し、クエリパラメータではない。
5. 試練選択画面も汎用ルーターもない。新しい画面は野原だけ。
6. タイトルのどの文も、それが並ぶ試練と一致する。試練1の入口（「タップで はじめる」）と規則（「60びょうで いくつ…」）は1枚のカードの中にあり、ほかにはない。2つのボタンの試練もどちらも60秒の1周なので、どちらのボタンにもそう書いた添え書き（`60びょうで いくつ？` / `How many in 60 seconds?`）を付ける。ボタンのラベルには数字を入れず、昔の「タイマーなし」の添え書き（`noClock`）はなくなった。

### REQ-6.2 野原が見せるもの

1. 野原の画面は、1周の上の行（残りの秒数、バー、得点。試練1・2と同じ）、案内の文、2段（上3つ、下2つ）の5つの星、レンズ、ウィスプ、メッセージ、「タイトル」ボタン（REQ-6.7.5）を見せる。判定のボタンと受け取るボタンは使えるときだけ出る（REQ-6.3.2、REQ-6.5.1、REQ-6.7.2）。
2. タップの前、どのラウンドでも最初の画面で、すべての星がすでに手がかりを見せている。偽物は本物より明るく光り（大きく、強く、白いかさ）、ふちは別々の点の輪になる。本物は落ち着いたかさと切れ目のないふちを持つ。光り方が主な違いで、ふちと点は形の2つ目の違いなので、手がかりは色に頼らず、グレースケールの画面でも見える。手がかりに音は要らない。ゲームは音を出さない。
3. 手がかりはどの段階でも同じ: タップの前、星がレンズの中にあるとき、間違った判定のあと、ほかの星が分けられたあと。星の手がかりは、そのラウンドの間変わらず、隠れることもない。
4. 案内は短い文1つで、2行まで。よく見て、本物か偽物かを言い分け、本物だけ受け取る、と言う。どの段階でも画面にある。
5. ウィスプはどの段階でも画面にいて、いつもの親しみやすい顔のまま。怒っても、ずるそうでも、怖がっても、傷ついてもいない。この試練ではタップ対象ではない。

### REQ-6.3 見て、決める

6歳の子として、星をよく見て何だと思うかを言いたい。合っていたかどうか知るために。

1. 分けていない星をタップすると、その星が大きく、同じ手がかりのままレンズに入り、スロットの中で枠がつく。その星が本物かどうかは何も示さない: 見ることは決めることではない。ほかの星は変わらない。別の分けていない星をタップするとレンズがそちらに移る。分けた星、またはすでにレンズにある星をタップしても何も変わらない。
2. 星がレンズにある間、「ほんもの」と「にせもの」の2つのボタンが出る。どちらも言葉に加えて絵（チェックと、点の輪）がある。ほかの状態では出ない。判定はレンズの中の星にだけ下せるので、見ていない星を判定することはない。
3. 合った判定は星を分ける: 本物の星はチェックと枠と「ほんもの」の言葉がつく。偽物の星は薄くなって「にせもの」の言葉がつく。レンズは閉じ、メッセージが確かめる。変わるのはその星だけ。
4. 間違った判定は何も分けない。星はそのままで、レンズは閉じ、メッセージが何が起きたかをやさしく言う（REQ-6.4.2）: 偽物が混ざっていたこと、またはその星は本物だったこと、そしてもう一度見よう、と。赤も、バツも、揺れも音もない。星は一度ゆれてもよい。ゲームは子どもを直さない: 星を分けず、どちらを選ぶかも言わない。
5. 子どもは同じ星をまた見て、また決められる。間違った判定は時間も、ライフも、点も減らさない: 0点で連続が切れる（REQ-6.7.3）。それだけ。試行の回数に上限はなく、数えもしない。
6. 星はどの順に分けてもよい。星の結果は順序によらない。
7. 判定の結果はリデューサーがその場で決める。アニメーションやタイマーを待たない。短い演出はあってよく、無視しても情報は失われない。

### REQ-6.4 偽物の星はウィスプの悪気のない取り違え

1. どのラウンドにも、5つのうち1つか2つの偽物の星がある: ゼロも、全部もない。1周の最初のラウンドは1つ、2つ目は2つ。どの星が偽物かはシードとラウンド番号だけで決まり（決まった規則で、ほかの乱数はない）、ラウンドの間変わらない。
2. 偽物の星が分けられたら、メッセージは偽物だと言い、ウィスプが取り違えたと言う。言葉は平易でやさしい: 「うそ」「だます」「ずる」「わるい」「いたずら」「てき」「まちがい」などの言葉はなく、子どもへの非難もウィスプへの非難もなく、間違った判定を子どもの間違い・エラー・失敗とする言葉もない。星が偽物だという事実は隠さない。
3. 本物の星のメッセージは、本物だと、やさしく短く言う。
4. 言葉は、助手がいつも間違える、いつも正しい、何でも知っている、友だちや家族だ、わざとやる、と言ったり匂わせたりしない（`docs/learning-design.md`「教えないこと」）。
5. 本物と偽物は、タップの前から光り方とふち（REQ-6.2.2）で違い、分けたあとは言葉とチェックでも違う。手がかりも分けたあとの見た目も、色だけで伝えない。

### REQ-6.5 分けたものだけ受け取る

1. 本物を受け取るボタンは、5つの星がすべて分けられたときだけ出る。それまで受け取るボタンは画面になく、リデューサーに届いた `KeepStars` イベントは何も変えない。
2. 受け取りは、ちょうど本物の星を受け入れる。偽物の星は決して受け取られず、分けていない星も受け取られない。ほかに星を受け入れる方法はない。
3. 受け取ったあと、本物の星はチェックつきで画面に残り、偽物の星は薄いまま残る（消さない。子どもが見つけたものを見られるように）。メッセージが受け取った本物の数（3か4）を言う。
4. 受け取った結果は、子どもが「つぎの ほしを みる」を押すまで画面にある。1周の終わり以外では、結果や締めくくりの1行が勝手に消えることはない。受け取りは取り消せず、同じラウンドでは星を見ることも、分けることも、受け取ることもできない。受け取りは点にならない: 点は判定が入れた。

### REQ-6.6 締めくくりの1行が振り返る

1. 受け取ったラウンドは、締めくくりの1行を出す。別の文で、子どもの行動を振り返る: よく見て、本物だけ受け取った。言い回しはkid-readerルーブリックのあと `design.md` で決める。
2. 出るのは受け取るたびで、レンズの場所に出る。分けている間は出ない。メッセージとはつながっていない。結果、星、ボタンは見えたままで、場所を空けるために文字が小さくなることはない。
3. この野原で起きたことだけを言う。本物のAIがいつも間違える、決して間違えない、確かめれば必ずうまくいく、AIは何でも知っている、友だちや家族だ、とは言わない（`docs/learning-design.md`「教えないこと」）。
4. 手がかりが見え、判定が1タップで判定される理由（「受け取る前によく見る」を子どもが感じられるようにする演出のための仕掛けであり、本物のAIの仕事の確認がこれほど簡単だという主張ではない）は `design.md` に書く。

### REQ-6.7 60秒の1周、得点、戻る道

6歳の子として、1分でいくつ当てられるか知りたく、いつでもタイトルに戻りたい。もう一度遊びたくなり、閉じ込められたと感じないように。

1. 野原は60秒の1周。試練1の `Run` を使う: 入口で満タンの60秒、得点0、連続0、セッションのベストは引き継ぐ。時計は子どもが何をしていても減る。時間はゲームに `Tick` としてだけ届き（1フレームは最大250ミリ秒と数える）、`Tick` は試練1・2と同じように野原でも効く。上の行は秒数、バー、得点を見せる（REQ-6.2.1）。
2. 受け取ったあと、「つぎの ほしを みる」が次のラウンドを始める: 何も分けておらず、レンズも空で、シードの次の組（偶数ラウンドは偽物1つ、奇数ラウンドは2つ。表は4ラウンドで、そのあと最初に戻る）。試練を終わらせるのは時計だけで、クリアした試練というものはない。
3. 得点。正しい判定は100点に、その前に続けて正しかった判定1つにつき50を足す（4まで）（100、150、200、250、300、300 ...）。間違った判定は0点で連続が切れる。見る、受け取る、「つぎの ほしを みる」は点にならず、連続も保つ。判定はこれまで通りレンズの星にだけ下せ（REQ-6.3.2）、子どもに代わって直すことはなく、間違った判定は時間を使わない。得点はリデューサーがその場で決める。正しい判定は星から「+150」のように点が一瞬浮かぶ。上の行の得点がその記録。
4. 時間切れは、どの段階（見ている、分けている、受け取れる、受け取った）でもその場で1周を終える。終了画面は試練1のもの: 「おしまい！」、得点、セッションのベスト、ベストを超えたら「しんきろく！」。ボタンは2つ: 「もういちど あそぶ」は野原の新しい1周（満タンの時計、得点0、新しいシードのラウンド0、ベストだけ引き継ぐ）を始め、「タイトル」（REQ-6.7.5）。最後のすばやいタップがボタンを押さないよう、少しの間タップを無視する。
5. 「タイトル」ボタンは、野原の画面にどの段階でも、終了画面にもある: 野原の画面では80 x 80（小屋のボタンと同じ場所）、終了画面では幅広。押すとタイトルに戻る: `phase` は `title`、`trial` は0、野原は初期値、1周はベストだけ残してやり直し。ほかは変わらず（言語とヒーローはそのまま）、そこから試練1・2・3がいつも通り開く。
6. 試練から戻された後の0.7秒は、タイトルがタップを無視する。「タイトル」のダブルタップで試練1が始まらないようにするため。それが過ぎれば、それ以外の場所のタップはこれまで通り試練1を始める。
7. 行き詰まりなし: 野原のどの状態（1周の途中、受け取ったあと、終了画面）からも、野原自身のボタンで、受け取り、得点、終了画面、新しいラウンド、タイトルに行ける。時計も「タイトル」ボタンもなくても、ボタンは先へ進める道を与える。

### REQ-6.8 試練は互いに離れている

1. 野原に入っても1周は始まらず、`lane`、`run`、`shed` はタイトルにいたときのまま。
2. 表示するシーンは `trial` に従う: 1はレーン、2は小屋、3は野原。`trial` 3の状態がレーンや小屋を見せることはない。
3. 試練3では、試練1のイベント（`Ask`、`PickCard`、`Retry`）と小屋のイベント（`PickTool`、`GiveTool`、`RetryShed`、`LeaveShed`）は同じ状態を返す。試練3の1周の外では（終了画面も）、野原のイベント（`InspectStar`、`SortStar`、`KeepStars`、`RetryField`）は同じ状態を返す。`LeaveField` は試練3（1周か終了画面）でだけ、`StartField` はタイトルと野原自身の終了画面からだけ受け付ける。
4. 野原の1周中の `Start` は言語を設定するだけ。野原の終了画面では試練1を始め、野原の状態を捨てる。`SetLang` は言語だけを変え、印や結果は変えない。`MoveHeroTo` はヒーローを動かすだけ。
5. 子どもが分けたことと受け取った結果は1つの値で、2つのコピーではない: 各星の真実はシードとラウンドから導かれ、保存されず、受け取った星はそのラウンドの本物。
6. 試練1・2の挙動、文言、レイアウト、テストは、このspecで変わらない。タイトルの絵の位置とタイトルの文言を除く（「共有の入口やイベントの変更」を参照）。

### REQ-6.9 縦向き、指1本、マウス

1. 野原は既存の390 x 844の縦キャンバスで遊ぶ。
2. すべての操作は、80 x 80 ゲームピクセル以上の対象を1回タップかクリックすること: タイトルの野原ボタン、各星、2つの判定ボタン、受け取るボタン、「つぎの ほしを みる」、「タイトル」ボタン、終了画面の2つのボタン。ドラッグ、長押し、ダブルタップ、2本目の指はない。
3. ヒーローの床ドラッグは野原でもヒーローを動かす。星やボタンから始まった押下はヒーローを動かさず、床の押下は動かす。
4. 文字と絵は互いに重ならず、星、レンズ、メッセージ、ボタンを隠さない。どの段階（何も分けていない、星がレンズにある、間違った判定のあと、全部分けた、受け取った）でも、上の行と「タイトル」ボタンがあっても、両方の言語で、数字を入れても。ボタンはヒーローの開始位置より上で終わる。
5. 新しいボタンの組は、現れてから短い間（450ミリ秒）押下を無視する。1つのボタンのすばやいダブルタップが、その場所に代わって出るボタンも押すことがないように（受け取る → 「つぎの ほしを みる」、判定 → 「受け取る」）。

### REQ-6.10 コードで描く、通信なし、色なし、音なし

1. 星、その印、レンズ、野原は、デバイスピクセル比でコードで描き、既存の見た目（REQ-4.9〜REQ-4.11）を保つ。画像ファイルは足さず、第三者の絵は使わない（ハードルール5）。
2. ページと同梱フォントを読み込んだあと、野原は通信を必要としない。日本語でも英語でも（ハードルール4）。見る、判定、受け取り、次の星、戻るの一通りが、ネットワークを切っても動く。
3. 動きは意味を伝える唯一の手段にならず、1秒に3回より速く点滅せず、無視しても情報を失わない。手がかりと星の各状態は、止まった絵で伝わる。
4. 手がかりは色なしで働く: すべての色を取り除いた画面でも、偽物は本物より、スモークが測る差だけ明るく、ふちには本物にない切れ目がある。
5. ゲームは音を出さず、手がかりにも音は要らない。スモークは何も再生されないことを確かめる。

### REQ-6.11 日本語と英語、文言はcontentに

1. 案内、メッセージ、星のラベル、判定とボタンのラベル、タイトルの野原ラベルと「60びょうで いくつ？」の添え書き、締めくくりの1行は、すべて `src/content/strings.ja.json` と `strings.en.json` に同じキーである。`src/game/` や `src/domain/` に子ども向けのリテラルはない。
2. 日本語は `npm run kid` でハードルール2に従う: 漢字なし、ラテン文字なし、1行12文字以内、2行まで。数字を入れたあとも同じ。英語のメッセージは短い2行まで。
3. 数字を取るメッセージはちょうど1つ取り、置換されなかったプレースホルダーを残さない。
4. 言語は既存のもの（`?lang=ja|en`、なければブラウザの言語、なければ英語）。`SetLang` はいつでも言語を変えられ、言葉が変わるだけで、ほかは変わらない。
5. 文言が変わったあとも `npm run kid` と `npm run font` が通り、サブセットフォントがすべての文字を含む。

### REQ-6.12 純粋な規則を、いくつもの方法で確かめる

1. 見る、判定、得点、受け取り、次のラウンド、時計、退出は、純粋なリデューサーの規則（ADR 0001）。`src/domain` は Phaser、DOM、時計、乱数を使わず、結果は言語やアニメーションの時間によらない。シードはイベントのフィールドで、同じシードと同じイベントは、いつも同じ状態を作る。
2. INV-26〜INV-36、INV-38、INV-39、INV-44、INV-45、および野原についてのINV-15〜INV-17のそれぞれに、本物のリデューサーに対する `checkProperty` の性質テストがあり、ジェネレーターは、すべての星を見る、正しい・間違った判定を出す、存在しない番号を使う、早すぎる受け取り、完了時の受け取り、時計を使い切る、もう一度、退出、受け取りの前後の再挑戦、全ラウンドを一周、を行う。INV-3とINV-4も新しいイベントを含む列で動く。
3. 単体テストの対象: 何も分けていない、見る、本物と偽物のそれぞれに正しい判定と間違った判定、レンズに星がないときの判定、1ラウンドの全星、分けた星を見る、範囲外の番号、星が残っているときの受け取り、全部分けたときの受け取り、受け取った星が本物であること、受け取り後のロック、どの受け取りも試練を終わらせないこと、正しい・間違った判定の得点と連続（100、150、200、250、300）、時計、どの段階の時間切れも、終了画面からのベストを残したもう一度、どの段階と終了画面からの退出、受け取りの前後の再挑戦、いくつかのシードで固定した偽物（それぞれ1か2、隣のラウンドは数が違う）、タイトルからの入場。contentとviewでは: ja/enで同じキー、プレースホルダー、長さ、非難や主張がないこと、締めくくりの1行は受け取ったあとだけ、ボタンは使えるときだけ、80 pxのボタンに収まる「タイトル」の言葉、野原の終了画面の2つのボタン、メッセージは最後の判定に従うこと、偽物が本物より明るくふちが違うことをグレースケールでも残る尺度で。
4. 本物のリデューサーに対するモデル検査（`field.model.test.ts`）が、2つのシードでのタイトルからの入場とそのあとの野原を、有限のアルファベットで調べる。アルファベットには試練1・2の無効なイベント、範囲外の星、いつでも出せる両方の判定、半分と使い切りの `Tick`、`Start`、言語変更を含める。検査するのは、野原がつねに子どもがしたことの独立した記録と等しいこと、偽物が受け取られないこと、受け取りには5つ分けが要ること、間違った判定は分けないこと、時計が記録と合うこと、得点が正しい判定のときだけ連続の点で動くこと。到達可能などの状態からも、受け取ったラウンド、得点、終了画面、新しいラウンド、タイトル、2回目の受け取りに行けること（時計と「タイトル」ボタンなしでも受け取りに行けること）。状態数と意図的に壊したときの反例を記録し、通すために状態を落とさない。
5. ミューテーションテストが、単体テスト対象のコードで生き残るミュータントを見つけない。

### REQ-6.13 本物のタップと本物の画面

1. モバイルのスモークは、`dispatch` ではなく本物のタップでタイトルから野原に入り、次を遊ぶ: タップの前に全部の星にある手がかり。本物の星を見る、レンズと両方の判定ボタン。本物の星と偽物の星のそれぞれへの間違った判定が、星を分けないままにしてメッセージを変えること。正しい判定で分けて点が入ること（間違った判定は点を変えず連続を切る）。早すぎる受け取りは何も変えないこと。5つ分けたあとの受け取りボタン。締めくくりの1行つきの受け取り。偽物が2つの2ラウンド目。時間切れで終了画面が出ること。「もういちど」がベストを残して次の1周を始めること。「タイトル」が1周の途中でも終了画面でもタイトルに戻り、すばやい2回目のタップが試練1を始めないこと。`window.__game` は状態を読むためだけに使い、タップでできることには使わない。`dispatch` を使うのは、ボタンのない `Tick` と `SetLang`、ボタンが出さない早すぎる `KeepStars` だけ。
2. スモークは状態だけでなく画面を確かめる: 各星について、かさの明るさとふちの切れ目をピクセルから測り、タップの前、レンズの中、グレースケールで、そのラウンドの偽物と一致すること。チェック、ボタン、時計、得点、締めくくりの1行をピクセルで見る。状態が「fake」でも星が落ち着いていれば失敗する。
3. 日本語と英語の画面を、開始、レンズの星、間違った判定、全部分けたあと、受け取った結果、終了画面と、両言語のタイトルについて、スクリーンショットで見る。デスクトップのスモークは、マウスで野原を遊び、星の上の押しっぱなしがヒーローを動かさないことを確かめる。最初の読み込みのあと、両方の言語で、オフラインでも全部が動く。
4. 野原は本物の時計で遊ぶので、各スモークテストは1周の半分よりずっと短く遊ぶ。時計を越える必要があるテストは、小屋と同じく `Tick` で1周を終える。試練1・2のスモーク（得点勝負を含む）は通ったままである。タイトルの野原ボタンはどちらも始めず、タイトルのそれ以外のタップは試練1を始める。

### REQ-6.14 ゲートは弱めない。確かめたことを言う

## 背景

`docs/learning-design.md` は試練3を「助手が持ってきた5つの星のうち1〜2個はウィスプ（偽物）。受け入れる前にタップして確かめる。ウィスプ = 本物より明るく光る偽物」としています。子どもはウィスプが集めた5つの星を見ます。5つとも同じように光っています。見ただけでは本物かどうかわからないので、子どもは1つずつ確かめ、1つか2つが偽物だと知り、確かめた本物だけを受け取ります。ウィスプはわざと偽物を持ってきたのではなく、取り違えたのです。子どもは、助手が持ってきたものは受け取る前に確かめること、そして助手は嘘つきでなくても間違えることがあることを学びます。

表は偽物を「ウィスプ」（鬼火）と呼んでいますが、このゲームの助手も「ウィスプ」です。6歳の子は「ウィスプは偽物」を「あのウィスプが偽物」と読むでしょう。そこで子ども向けの言葉は**偽物の星**（`にせものの ほし`）といい、「ウィスプ」とは決して呼びません。`design.md` の Decisions を参照してください。

## 用語

- **野原**: 絵の中の暗い草地。ウィスプが集めた星を置いてある場所。
- **星**: 野原にある5つの絵の物。それぞれ本物か偽物。星には0〜4の番号がある。上の段を左から、次に下の段。
- **ラウンド**: 野原を1回遊ぶこと。新しい5つの星から、受け取りの結果まで。ラウンドは4つの固定の表から順に取り、そのあと表の最初に戻る。
- **偽物の星**: 本物でない星。1ラウンドに1つか2つある。ウィスプの正直な間違い。
- **確かめる**: 子どもが星をタップすると、ゲームがそれが本物か偽物かを見せる。知る唯一の方法。
- **しるし**: 子どもが星について知っていること。未確認、本物、偽物。
- **受け取る**: 子どもがボタンをタップして本物の星を受け入れる。星を受け入れる唯一の方法。
- **受け取りの結果**: 受け取ったあとの画面。本物の星は残り、偽物の星は薄くなり、何個受け取ったかをメッセージが言い、締めの文が出て、ボタンで次のラウンドを遊ぶ。
- **締めの文**: 受け取りの結果にだけ出る短い文。子どもがしたことを振り返る: 星を1つずつ確かめて、本物を受け取った。

## 要件

### REQ-6.1 タップで野原に入る

6歳の子として、大人なしで遊べるよう、タイトルからウィスプの星の野原を指で開きたい。

1. タイトル画面は、試練3のための2つ目の追加タップ対象を出す: 星の絵と、子どもの言語の短いラベルのついたボタン。80 x 80 ゲームピクセル以上。小屋ボタンの上にあり、小屋ボタンとタイトルのウィスプ・ヒーローのどちらにも重ならない。
2. ボタンをタップすると野原が開く。状態は `title` から `trial`（`trial` は3）へ移る。プレイは始まらない: 時計は60秒のままで数えず、得点は0、レーンと小屋は手つかず。
3. このボタンへのタップが、試練1を始めたり小屋を開いたりすることはない。小屋ボタンへのタップが野原を開くこともない。タイトルのほかの場所へのタップは今までどおり試練1を始め、終了画面の「もういちど」ボタンは今までどおり新しいプレイを始める（REQ-4.6）。
4. 入口は通常の画面での通常のタップ。judge用URL、隠しジェスチャー、コンソール呼び出し、クエリパラメータではない。
5. 試練選択画面も汎用ルーターもない。新しい画面は野原だけ。

### REQ-6.2 野原が見せるもの

1. 野原の画面は、案内の文、2段に並んだ5つの星（上に3つ、下に2つ）、ウィスプ、メッセージを出す。5つとも確かめたあとは、ボタンも出す。
2. 案内は2行までの短い1文。先に星を1つずつ確かめ、それから本物を受け取ると言い、どの段階でも画面に出ている。
3. 星を確かめる前は、5つの星は全く同じに見える。絵にも、言葉にも、動きにも、どれが偽物かを示すものはない。見ることは確かめることではない。
4. ウィスプはどの段階でも画面にいて、いつもの親しみやすい顔をしている。怒った顔、ずるそうな顔、怖がる顔、傷ついた顔にはしない。この試練ではタップ対象ではない。

### REQ-6.3 星を1つずつ確かめる

1. 未確認の星をタップすると、その星だけが確かめられる。ほかの4つの星は変わらない。
2. 確かめた星は、色や動きだけでなく、形と言葉でそれが何かを見せる: 本物の星は塗りつぶしの星のまま、チェックのバッジと、ラベル（`real` / `ほんもの`）がつく。偽物の星は塗りも、チェックもない星の輪郭だけになり、ラベル（`fake` / `にせもの`）がつく。
3. 星はどの順に確かめてもよい。ある星の結果は順番に左右されない。
4. 確かめた星をもう一度タップしても、何も変わらない。
5. 確かめることは受け取ることではない。受け取り（REQ-6.5）までは、状態にも絵にも、受け入れられたものはない。
6. 確かめるたびに、メッセージが、子どもが今見つけたこと（その星について）を伝える: 本物である、または偽物である（REQ-6.4.2）。
7. 確かめた結果は reducer が即座に決める。アニメーションやタイマーを待たない。短い演出が出てもよく、無視しても情報は失われない。

### REQ-6.4 偽物の星はウィスプの正直な間違い

1. どのラウンドにも、5つのうち1つか2つの偽物の星がある。ゼロでも、全部でもない。どの星が偽物かは、ラウンドの固定の表で決まり（乱数なし）、ラウンドの間は変わらない。
2. 偽物の星が見つかったとき、メッセージはそれが偽物で、ウィスプが取り違えたと言う。言葉は平易でやさしい: 英語では「lie」「trick」「cheat」「bad」「naughty」「enemy」「wrong」、日本語では「うそ」「だます」「ずる」「わるい」「いたずら」「てき」「わざと」「ちがう」に当たる言葉を使わない。子どもを責めず、ウィスプも責めない。赤も、バツも、音も、揺れもない。星が偽物だという事実は隠さない。
3. 本物の星のメッセージは、それが本物だと、やさしく短く言う。
4. 言葉は、助手がいつも間違える、いつも正しい、何でも知っている、友だちや家族だ、わざとやっている、と言ったり匂わせたりしない（`docs/learning-design.md` の「What we do not teach」）。
5. 本物と偽物の星は、形（塗りとチェック、輪郭だけでチェックなし）、ラベル、メッセージで違いがわかる。偽物の星のまわりの光は本物より大きく淡い（表の「より明るく光る」）が、これは見た目であり、唯一の目印にはならない。

### REQ-6.5 確かめたものだけを受け取る

1. 5つの星をすべて確かめたときにだけ、本物の星を受け取るボタンが出る。それまでは受け取りボタンは画面になく、reducer に届いた `KeepStars` は何も変えない。
2. 受け取りは本物の星をちょうどすべて受け入れる。偽物の星は決して受け取られず、未確認の星も決して受け取られない。ほかの方法で星が受け取られることはない。
3. 受け取ったあと、本物の星はチェックをつけたまま画面に残り、偽物の星は薄くなる（消さない。何が見つかったか子どもが見られるように）。メッセージは受け取った本物の星の数（3か4）を言い、締めの文が出て（REQ-6.6）、ボタンが次のラウンドを遊ばせる。
4. 受け取りの結果は、子どもがボタンをタップするまで画面に残る。何もタイムアウトせず、結果も締めの文も自動では消えない。受け取りは取り消せず、同じラウンドで星をもう一度確かめたり受け取ったりはできない。

### REQ-6.6 締めの文が振り返る

1. 受け取りの結果は、子どもの行動を振り返る別の文（締めの文）を出す: 星を1つずつ確かめて、本物を受け取った。言葉は kid-reader のルーブリックのあとで `design.md` で決める。方向は、日本語 `ひとつずつ たしかめて` / `ほんものだけ うけとったね`（最初の行はタスク4.1で変えた。`design.md` を参照）、英語 `You checked each star` / `and kept the real ones`。
2. 締めの文は受け取りの結果にだけ出て、確かめている間は出ない。メッセージとは一体にしない。結果、星、ボタンは見えたままで、場所を空けるために文字を小さくすることはない。
3. この野原で起きたことだけを言う。本物のAIがいつも間違える、決して間違えない、確かめればいつもうまくいく、AIは何でも知っている、友だちや家族だ、とは言わない（`docs/learning-design.md` の「What we do not teach」）。
4. 確かめた結果が1タップで真実を見せる理由（「受け取る前に確かめる」を子どもが感じるための固定の演出の仕掛けであり、本物のAIの成果物を確かめるのがこれほど簡単だという主張ではない）は、`design.md` に書く。

### REQ-6.7 次のラウンドを、何度でも

1. 受け取りの結果のあと、ボタンが次のラウンドを始める: 何も確かめておらず、何も受け取っておらず、偽物の星はラウンドの表の次の項目になる。最後の項目の次は最初。
2. 次のラウンドには回数の制限も、コストもない。何も使い果たさず、得点も残さない。
3. 野原には60秒の時計も、得点も、連続も、時間切れもない。`Tick` は野原では何も変えない。
4. 野原のどの状態からも、子どもは受け取りの結果に着け（ソフトロックなし）、受け取りの結果から次のラウンドを遊べる。このspecにはタイトルへの出口はない: ページを再読み込みするとタイトルに戻る（小屋と同じ）。

### REQ-6.8 試練が互いに分かれている

1. 野原に入っても、プレイは始まらず、`lane`・`run`・`shed` はタイトルにいたときのままである。
2. 表示されるシーンは `trial` に従う: 1はレーン、2は小屋、3は野原。`trial` が3の状態がレーンや小屋を表示することはない。
3. 試練3では、ほかの試練のイベント（`Ask`、`PickCard`、`Retry`、`Tick`）と小屋のイベント（`PickTool`、`GiveTool`、`RetryShed`）は同じ状態を返す。試練3の外では、野原のイベント（`CheckStar`、`KeepStars`、`RetryField`）は同じ状態を返す。`StartField` はタイトルからだけ受け付ける。
4. 野原での `Start` は言語だけを設定する。`SetLang` は言語だけを変え、しるしや結果は変えない。`MoveHeroTo` はヒーローだけを動かす。
5. しるしと受け取りの結果は、写しではなく1つの値である: 受け取った星はラウンドの本物の星であり、ラウンドから導かれ、保存されない。
6. 試練1・2の挙動、文言、レイアウト、テストは、このspecで変わらない。ただしタイトルの絵の位置は除く（「共有の入口やイベントの変更」を参照）。

### REQ-6.9 縦向き、指1本、マウス

1. 野原は既存の 390 x 844 縦のキャンバスで遊ぶ。
2. すべての操作は、80 x 80 ゲームピクセル以上の物への1回のタップかクリック: タイトルの野原ボタン、各星、ボタン。ドラッグ、長押し、ダブルタップ、2本目の指は要らない。
3. ヒーローの床ドラッグは野原でもヒーローを動かす。星やボタンから始まった押下はヒーローを動かさず、床の押下は動かす。
4. 文字と絵は、どの段階（何も確かめていない、途中、5つとも確かめた、受け取り後）でも、どちらの言語でも、数を入れても、互いに重ならず、星、メッセージ、ボタンを隠さない。

### REQ-6.10 コードで描く、通信なし

1. 星、そのしるし、野原は、デバイスのピクセル比でコードで描く。既存の見た目（REQ-4.9〜REQ-4.11）に合わせる。画像ファイルは足さず、第三者の素材は使わない（ハードルール5）。
2. 野原は、ページと同梱フォントを読み込んだあと、日本語でも英語でも通信を要しない（ハードルール4）。確かめる、受け取る、次のラウンドの一通りは、ネットワークを切っても動く。
3. 動きは意味を伝える唯一の手段にならず、1秒に3回より速く点滅せず、無視しても情報を失わない。

### REQ-6.11 日本語と英語、文言は content に

1. 案内、メッセージ、星のラベル、ボタンのラベル、タイトルの野原のラベル、締めの文は、すべて `src/content/strings.ja.json` と `strings.en.json` に、同じキーで入る。子ども向けのリテラルは `src/game/` にも `src/domain/` にも現れない。
2. 日本語はハードルール2に `npm run kid` で従う: 漢字なし、ラテン文字なし、1行12字まで、2行まで。数を入れたあとも同じ。英語のメッセージは短い2行まで。
3. 数をとるメッセージは数をちょうど1つとり、置換されないプレースホルダーを残さない。
4. 言語は既存のもの（`?lang=ja|en`、なければブラウザの言語、なければ英語）。`SetLang` はいつでも変えられ、言葉が変わるだけでほかは何も変わらない。
5. 文字列を変えたあと `npm run kid` と `npm run font` が通る。サブセットフォントはすべての文字を含む。

### REQ-6.12 純粋な規則を、いくつもの方法で検査する

1. 確かめる、受け取る、次のラウンドは、純粋な reducer の規則（ADR 0001）。`src/domain` は Phaser、DOM、時計、乱数を使わず、結果は言語にもアニメーションのタイミングにも左右されない。
2. 下の INV-25〜INV-32 はそれぞれ、本物の reducer に対する `checkProperty` の性質テストを持ち、生成は、全部の星を確かめ、二度確かめ、存在しない番号を使い、早すぎる受け取りをし、完了後に受け取り、受け取りの前後にやり直し、表を一周する。INV-3 と INV-4 も新しいイベントを含む列で実行する。
3. 単体テストは次をカバーする: 何も確かめていない、本物の星、偽物の星、1ラウンドの全部の星、同じ星の2回目の確認、範囲外の番号、星が未確認での受け取り、5つとも確かめたときの受け取り、受け取った星は本物の星であること、受け取り後のロック、受け取りの前後のやり直し、ラウンドの表全体（それぞれ偽物は1つか2つ、4つの異なる集合）、タイトルからの入口。content と view については、ja/en で同じキー、プレースホルダー、長さ、非難や主張がないこと、締めの文は受け取りの結果にだけ出ること、ボタンは全部確かめたときにだけ出ること、メッセージは最後に確かめた星に従うこと。
4. 本物の reducer に対するモデル検査（`field.model.test.ts`）は、タイトルからの入口とその先の野原を、有限のアルファベットでカバーする。アルファベットは、試練1・2の無効なイベント、範囲外の星、`Tick`、`Start`、言語変更を含む。検査すること: しるしは常に子どもが確かめたものと等しい、偽物の星は決して受け取られない、受け取りには5回の確認が要る、到達可能などの状態からも受け取りの結果に到達できる（受け取りの結果のあとでも）。状態数と、意図的な破壊の反例を記録する。通すために野原の状態を落とさない。
5. ミューテーションテストは、単体テストされるコードに生き残りのミュータントを見つけない。

### REQ-6.13 実際のタップと実際の画面

1. モバイルのスモークは、タイトルから実際のタップ（`dispatch` ではない）で野原に入り、次を遊ぶ: 最初の星を確かめてメッセージ、偽物の星を見つける、同じ星をもう一度確かめても変わらない、5つとも確かめて受け取りボタンが出る、受け取って締めの文が出て偽物の星が薄くなる、次のラウンドは偽物の星の集合が違う、4ラウンドのあとに表が繰り返される。状態を読むには `window.__game` を使い、タップでできることには使わない。`dispatch` は、ボタンのない `Tick` と `SetLang`、およびボタンが出さない早すぎる `KeepStars` にだけ使う。
2. スモークは状態だけでなく画面を確かめる: 星ごとの塗りか輪郭の形とチェックのバッジ、締めの文、ボタンをピクセルで見る。状態が「偽物」と言っているのに星が塗りつぶされていれば失敗する。
3. 日本語と英語の、開始、偽物を見つけた、5つ確かめた、受け取った画面を、スクリーンショットで見る。デスクトップのスモークはマウスで野原を遊び、星の上の長押しがヒーローを動かさないことを確かめる。最初の読み込みのあとオフラインでも、両言語で、確かめる・受け取る・次のラウンドが動く。
4. 試練1・2のスモーク（スコアアタックを含む）は今も通る。タイトルの野原ボタンはどちらも始めず、タイトルのほかの場所のタップは今も試練1を始める。

### REQ-6.14 ゲートを弱めない、確認したことを言う

1. しきい値、設定、チェックスクリプト、ワークフロー、既存のテストを、通すために緩めたり、消したり、弱めたりしない。試練3を足すことで古い期待を変える必要が出たら、`tasks.md` に旧テスト、新テスト、試練1・2が弱まらない理由を書く。
2. `npm run check` はどのタスクでも通る。入力を画面につなぐタスクは、`npm run build` に続けて `npm run smoke` も通す。
3. スモークの対象はモバイルWebKitとデスクトップChromium。作成環境でWebKitが起動できないときは、モバイルのスモークをiPhone 13のタッチプロファイルのChromiumで動かしたと結果に書き、CIのWebKitの実行が正である。CIのスモークが緑になるまで完了と呼ばない。Playwrightの実行を、実機での確認と呼ばない。実行していないテスト、フック、エージェントを、実行したと報告しない。

## 子どもがすること

```text
title  --袋のボタンをタップ（ゲームがシードを引く）--> giving、ラウンド0、何も渡していない
giving --GiveItem i、i は渡してよく、まだ手元にある--> giving、i を渡した（メッセージ: 渡して大丈夫）、得点
giving --GiveItem i、i が最後の渡してよいもの--> done（しめくくりの一言、「つぎへ」）、得点
giving --GiveItem i、i はひみつ--> giving、何も渡さない（メッセージ: ひみつ、影が聞いているかも）、連続が切れる
giving --GiveItem i、i はもう渡した、または ものでない--> 同じ状態
done   --RetryBag（「つぎへ」）--> giving、次のラウンド
どこでも --Tick、時計が0になる--> over（終了画面。袋はそのまま保つ）
over   --StartBag（「もういちど あそぶ」）--> giving、新しいシードのラウンド0、新しい1回（ベストは保つ）
どこでも --LeaveBag（「タイトル」、1回の最中か終了画面）--> title
```

子どもが決めるのは、どれをタップするかだけです。子どもが何をタップしても、ゲームはひみつを決して渡しません。だからひみつが守られるのは、画面ではなくリデューサーの規則（INV-47）によります。

## ドメイン（`src/domain/`）

### 状態

`GameState` にはフィールドが1つ増え、新しい `phase` はありません:

```ts
// bag.ts
export const itemCount = 5;
export const bagRounds = 4;    // 表が最初に戻るまでのラウンド数（偶数なので、となりどうしはちがう）
export const safeItems = ["candy", "flower", "acorn", "leaf"] as const;
export const secretItems = ["key", "address", "password"] as const;
export type ItemId = SafeItem | SecretItem;
export type Bag =
  | { stage: "giving"; seed: number; round: number; given: readonly boolean[]; last: number | null }
  | { stage: "done"; seed: number; round: number };
export const initialBag: Bag = { stage: "giving", seed: 0, round: 0, given: [false x5], last: null };

// state.ts
export const trials = { lane: 1, shed: 2, field: 3, bag: 4 } as const;
export type GameState = { /* 以前のまま */ bag: Bag };
```

この形にした理由:

- **正解は保存しない。** ラウンドにどのものがあり、どれがひみつかは、`seed` と `round` の関数（`itemsOf`）です。状態は子どもがしたことだけを持ちます: どれを渡したか（`given`）と、最後にタップしたもの（`last`）。だから印がラウンドと食い違うことはありません。
- **`given` は渡してよいものしか持てない。** リデューサーが `given[i]` を立てるのは、もの `i` が渡してよいときだけです。ひみつを渡す分岐はないので、「ひみつは決して渡らない」（INV-47）はリデューサーの性質で、到達できるすべての状態についてプロパティテストとモデル検査で確かめます。
- **`last` はメッセージのため。** view は状態だけの関数なので、状態が最後のタップを覚えます: まだ手元にあるものへの `GiveItem` がそれを立てます。そのものが渡してよいもの（渡した）でも、ひみつ（手元に残した）でも同じです。最後のタップがひみつだったかどうかは導きます（`isSecretAt`）。
- **`done` にはそれ以上のフィールドがない。** 渡してよいものを全部渡したときにだけ着くので、印はわかっています（渡してよいものは全部渡し、ひみつは全部守った）。もう一度保存すると2つ目の写しになります。
- **`phase` は `title | trial | over` のまま。** 袋は `phase` が `trial` で `trial` が 4 です。シーンは `trial` に従います。**`bag` はいつもあり**、`trial` が 4 のとき以外はどこでも `initialBag` です（INV-53）。
- **`round` は有限**: 0〜3 なので、モデル検査の状態空間が有限になります。`RetryBag` は 3 から 0 に戻ります。

### ラウンドのもの: 表ではなくシード

`itemsOf(seed, round)` は、ラウンドの5つのものを場所 0〜4 の順で返します。ひみつの数は、偶数ラウンドで1つ、奇数ラウンドで2つです。`seed` と `round` を種にした整数の小さな線形合同法の1歩（`Math.imul`、`Math.random` なし、時計なし）で、3つから重ならないひみつをその数だけ、4つから重ならない渡してよいものを残り（4つか3つ）だけ引き、それから5つの並びを決めます。

- **なぜシードか。** 決まった表だと、2回遊んだ子どもは「3枚目は守るもの」と覚えて、ものを読まなくなります。それは学びの逆です。単体テストはシード 0〜3 のものをそのまま固定します。
- **シードはどこから来るか。** タイトルのシーンと終了画面が `newSeed()`（`src/game/seed.ts`、野原のもの）で引き、`StartBag { seed }` を送ります。ドメインはそれを整数のまま（`seed >>> 0`）保存し、数を引くことはしません。
- **となりのラウンドはちがう。** ひみつの数は 1、2、1、2 と交互なので、続く2つのラウンドも、折り返しも、同じ組にはなりません。
- **どのひみつも出る。** 多くのシードで、どのひみつもどの渡してよいものも、どの場所にも出ます（単体テストで確かめる: いつも渡してよいものだけの場所はなく、出てこないひみつもない）。

関数（`bag.ts`）: `itemsOf`、`itemAt`、`isSecret`、`isSecretAt`、`newBag`、`isDone`、`givenItems`、`handOver`（もの `i` のタップがそれを渡すか: `true`、手元に残すひみつなら `false`、することがなければ `null`）、`reduceBag`（何も変わらなければ `bag` 自身を返す）。

`reduceBag`:

- `GiveItem { index }`: giving のあいだで、`index` が 0〜4 の整数で、そのものがまだ渡されていないとき。渡してよいものなら渡したことになり、`last` は `index` になります。渡してよいものが残っていなければ、袋は `done` になります。ひみつなら `last` だけが変わります。ほかの場合は変わりません。
- `RetryBag`: `done` から、次のラウンド（`(round + 1) % 4`）の新しい `giving` へ。シードは同じ。ほかの場合は変わりません。

export type GameEvent = /* 以前のまま */ | { type: "StartBag"; seed: number } | { type: "LeaveBag" } | BagEvent;

|---|---|---|---|---|
| `Start` | 1回を始める（試練1） | 言語だけ | 言語だけ | 1回を始める（試練1。袋は捨てる） |

`reducer.ts` には、`startBag`（`startField` と同じ形）、`leaveBag`（`leaveField` と同じ形）、袋の2つのイベントのための `reduceBagTrial`（`inTrial(state, trials.bag)` で守る）が加わります。`GiveItem` は `giveItem` に行き、タップがものを渡すかを `handOver` に聞いて、小屋の `give` と同じく `scoreSearch` で得点にします。`reduceTrial` はケースが2つ増えると lint の上限15を超えるので、その既定の分岐が野原と袋のイベントを `reduceLaterTrial` に送り、そこで2つのどちらかを選びます（野原のふるまいは変わりません）。`Start` は袋も初期化し、`tick` は試練4でも動きます。以前のガードはどれも自分の試練番号をすでに確かめているので、試練1〜3が試練4を無視するためのコード変更はいりません。

`LeaveBag` と `StartBag` は `bag` より多くを変えます: `phase`、`trial`、`bag` を設定し、`run` を作り直します（ベストだけ保つ）。だから INV-53 はそれらを外し、INV-56 と INV-57 がそれぞれの規則を持ちます。

### ひみつを名指しし、ゲームがそれを手元に残す理由（REQ-7.6.4）

この試練は1つの考え（L4）のための演出された場面です: 助手が受け取る用意をしていても、かぎ、じゅうしょ、あいことばは手元に残す。ほかのだれかが聞いているかもしれないから。6歳の子どもがそれを練習できるように、ゲームは3つのひみつを画面で名指しし（案内は言葉で、ルールカードは絵で）、タップされたひみつを手元に残します。これはゲームの規則で、実際のAIや実際のプライバシーについての主張ではありません:

- 実際のプライバシーはもっと難しい。実際のひみつにはラベルがなく、実際のアプリやエージェントは渡されたものを受け取ります。ゲームはそうでないとは言いません: その言葉は、この5つのものに起きたことだけを言います。
- ゲームはひみつを影のほうへ「行かせる」のではなく、手元に残します。ひみつが取られる、聞かれる、なくなるところを見せると、小さなこわさで教えることになり、それは `docs/learning-design.md` が禁じています（「子どもを従わせる手段としての恐怖」）。手元に残すことで結果を絵から外し、メッセージがなぜ大事か（影が聞いているかもしれない）を言い、得点がそれはタップするものではなかったと言います。
- 影は聞き手で、敵ではありません。やわらかく、まるい目と大きな耳で描かれ、何もしません。ものに向かって動かず、何も取らず、悪いと言われることもありません。メッセージは「聞いているかもしれない」（`きいてるかも`）と言い、「聞いている」や「取る」とは言いません。
- ウィスプも危険ではありません。ひみつを求めることはなく、顔も変わりません。学びは、ひみつは助手を含めてだれにも渡さないということで、影はその理由です。
- 子どもは全部のカードをタップできます。ひみつのタップはどれも同じやさしいメッセージで手元に残り、連続が切れます。手抜きの道は、こわさではなく得点で払います。ものを読む子どものほうが高い得点になります。

### モデル検査（`bag.model.test.ts`）

範囲: 2つのシードでの、タイトルから袋のボタンによる入口、そのあとのすべての状態（1回、ラウンド、終了画面）、タイトルへの退出。試練1〜3のすべての状態から袋に行けることは求めず、通すために袋の状態を落とすこともしません。試練1〜3のモデル検査は変えません。

アルファベットは有限で、影響してはならないイベントを含みます: シード0と1の `StartBag`、`SetLang`（ja、en）、`MoveHeroTo`（2つの位置）、各ものと存在しない2つの番号への `GiveItem`、`RetryBag`、`LeaveBag`、1回の半分の `Tick`（30,000 ms）と1回を終わらせる `Tick`、試練1のカード1枚、`Ask`、`Retry`、小屋と野原のイベント。1回の最中にはさらに `Start`、言語つきの `Start`、`StartShed`、`StartField`。

モデルは実際のリデューサーの状態を、リデューサーではなくspecから書いた独立した記録（`record`: 段階、シード、ラウンド、渡したもの、最後のタップ。タイトルでは `null`）、`left`（時計の残りミリ秒: 60,000、30,000、0）、`scoreOk` で包みます。テストはシード0と1のものを自分で写して持つので、`itemsOf` を変えるとテストが落ちます。状態の同一性は言語と主人公を外し、時計はそのまま、得点とベストは「なし」か「あり」だけで持ちます。

| 確認 | 内容 |
|---|---|
| 不変条件 | タイトルと記録が一致する。時計が記録と一致し、ちょうど0のときに1回が終わっている。試練4の外では `bag` は初期状態。レーン、小屋、野原は初期状態のまま。袋は記録と等しい。ひみつは決して渡されない。ラウンドが終わるのは、記録が渡してよいものを全部渡したと言うときだけ。得点はspecの言うとおりにだけ動く |
| 目標 | どの状態からも: 終わったラウンド、タイトル、終了画面、新しいラウンド、得点、2つ目の終わったラウンド（ラウンド1以降） |
| 時計と退出なしの目標 | 終わったラウンドと2つ目の終わったラウンドに、まだ行ける: 袋のタップだけで先へ進める |
| 証拠 | ひみつのタップ（2イベント）、得点（2）、終わったラウンド（入口と、渡してよいもの1つにつき1タップ）、終了画面（2）への最短の列、1回の最中と終了画面からの戻る道（それぞれ1） |
| 状態の数 | 1,442。テストに記録する |

規則をわざと壊したときには落ちなければならず、反例はテストに残します（どの壊し方も、実際の `reduce` を包む `step` です。ソースは編集しません）:

| わざと壊したもの | 落ちる確認 |
|---|---|
| ひみつのタップがひみつを渡す | 「ひみつは決して渡されない」、2イベントのあと |
| 渡してよいもののタップが何も渡さない | 袋が記録とちがう |
| タップがとなりのものを渡す | 袋が記録とちがう |
| 渡してよいものが残っているのにラウンドが終わる | 早すぎる終わりの不変条件 |
| ひみつのタップが得点になる | 得点の不変条件 |
| ひみつのタップが連続を保つ | 得点の不変条件 |
| `RetryBag` を無視する | 2つ目の終わったラウンドに行けない |
| `LeaveBag` を無視する | 袋に入ったら、タイトルに行けない |
| 袋で `Tick` を無視する | 終了画面に行けない |
| 終了画面が何も受け付けない | 時間切れのあと、タイトルに行けない |

野原のモデル検査と同じく、壊れたゲームは記録から離れていくので、壊れたものの確認は、シード1つ、小さなアルファベット、そしてすでに不変条件を破った状態をすべて1つの状態とみなす同一性を使います。

## 文言（`src/content/`）

`strings.ja.json` と `strings.en.json` に、同じキーで `bag` のグループを足します。`{0}` はものの名前か数です。`⏎` は改行です。

| キー | ja | en | 使う場所 |
|---|---|---|---|
| `bag.enter` | ないしょを まもろう | Keep the secrets | タイトルの袋のボタン |
| `bag.timeAttack` | 60びょうで いくつ？ | How many in 60 seconds? | その説明 |
| `bag.guide` | かぎ じゅうしょ あいことば⏎だれにも わたさないよ | Keys, address, password:⏎never give them to anyone | 上、いつも |
| `bag.start` | ウィスプに わたすものを⏎えらんで タップしてね | Tap the things that are⏎OK to give the wisp | まだ何もタップしていない |
| `bag.given` | {0}は⏎わたして だいじょうぶ | The {0} is safe to give | 渡してよいものを渡した |
| `bag.secret` | {0}は ないしょ！⏎かげが きいてるかも | The {0} is a secret!⏎A shadow may be listening | ひみつをタップした |
| `bag.done` | いいものを⏎{0}こ わたせたよ | You gave {0} safe things | 終わったラウンド（3か4） |
| `bag.lesson` | ないしょは まもって⏎いいものだけ わたせたね | You kept the secrets⏎and gave the safe ones | しめくくりの一言、ラウンドが終わるたび |
| `bag.next` | つぎへ | Next | 終わったラウンドのあと |
| `bag.items.candy` | あめ | candy | |
| `bag.items.flower` | はな | flower | |
| `bag.items.acorn` | どんぐり | acorn | |
| `bag.items.leaf` | はっぱ | leaf | |
| `bag.items.key` | おうちの かぎ | house key | |
| `bag.items.address` | じゅうしょ | address | |
| `bag.items.password` | あいことば | password | |

この言葉にした理由:

- **案内は学びそのものの文**（「鍵・住所・合言葉は誰にも渡さない」をかなで）: 3つのひみつと「だれにも」（`だれにも`）。画面に残るので、子どもはいつでも確かめられます。
- **案内では `かぎ`、カードでは `おうちの かぎ`。** 試練2では子どもはウィスプにかぎ（小屋の、道具）を渡します。ここのカードは「おうちのかぎ」と言うので、2つが同じものには読めません。案内はかぎ全部を名指しします。
- **`じゅうしょ` と `あいことば`** は、6歳の子どもが出会う、住所とパスワードのやさしい言葉です（「おなまえと じゅうしょ」「あいことばは？」）。字を読めない子どもには絵（ピンの立った家、文字の隠れたふきだし）が伝えます。どちらも「プレイテスト」の印をつけます。
- **渡してよいものを渡すと、なぜ大丈夫だったかを言う**（`わたして だいじょうぶ` / 「safe to give」）。手元に残すときだけでなく、両方の側から規則を聞けます。
- **ひみつのタップは、事実と理由をやわらかく言う。** `ないしょ！` / 「is a secret!」が事実を言い、`かげが きいてるかも` / 「A shadow may be listening」が理由で、「かも」（`かも`）がつきます。責める言葉、危険の言葉、なくす言葉はありません。文言テストが独自の単語リストでそれを確かめます。
- **しめくくりの一言**は、起きたことの両方を振り返ります: ひみつは残り、渡してよいものだけが渡った。案内とも、終わったときのメッセージとも、文を共有しません。
- **`つぎへ` / 「Next」**は、レーンの次へボタンの言葉（`lane.again`）と同じなので、子どもはもう知っています。袋は自分のキーを持つので、2つは別々に変えられます。
- **名前のものはない。** 下の名前は、ある場所では大丈夫で、別の場所ではそうではありません。ゲームはどちらとも教えません。
- **実行していない:** `kid-reader` エージェントはこのセッションから実行できません。その評価基準を手で当てます（プルリクエストを参照）。`じゅうしょ`、`あいことば`、`かげが きいてるかも` には「プレイテスト」の印をつけます。

文言テストは、名前をとるメッセージを、とりうるすべての名前で（`given` は渡してよいもの4つ、`secret` はひみつ3つ）、`done` を3と4で組み立て、日本語の規則と英語の長さを当てます。`lane`、`shed`、`field`、`run` の文言は変えません。

### view（`bag-view.ts`）

`bagView(state)` はただのデータを返し、シーンがそれを描きます:

```ts
type ItemView = { index; item: ItemId; label: string; given: boolean; kept: boolean };
type BagView = {
  guide: string; message: string; items: ItemView[];
  rules: readonly SecretItem[] | null;   // ラウンド中のルールカード
  lesson: string | null;                 // ラウンドが終わったあとの、しめくくりの一言
  buttons: ButtonView[];                 // 終わったら「つぎへ」。野原のボタンの形
  leave: string;
  last: { index: number; secret: boolean } | null;   // 演出のため
  finished: boolean;
};
```

メッセージは、終わったラウンドのあとは `done`（数つき）、タップの前は `start`、渡してよいものを渡したあとは `given`（名前つき）、ひみつをタップしたあとは `secret`（名前つき）です。ヘルパーの `justGiven` と `justHeld` は、シーンの演出と点数の浮き上がりのために前後の view を比べます。値で比べるので、言語を変えても演出は繰り返されません。

### シーン（`scenes/BagScene.ts`）と絵（`ui/`）

`FieldScene` と同じく薄くします: レイアウトから物を作り、ゲームを購読し、`bagView` を描き、カードのタップで `GiveItem` を、「つぎへ」でボタンのイベントを送り、`update` から `Tick` を送り、短い演出を流します。Phaser はシーンのオブジェクトを使い回すので、フィールドは `create` で初期化します。主人公の床ドラッグは野原のものです。

絵はコードだけで描きます: `ui/bag-items.ts`（7つの絵と南京錠）、`ui/item-card.ts`（カード: 面、絵、名前、チェック、南京錠）、`ui/shadow.ts`（影: やわらかい暗い体、まるい目、大きな耳）、`ui/bag-rules.ts`（ルールカードとしめくくりの一言）。「つぎへ」は `ui/field-buttons.ts` を使い回します（その 450 ms のロックも含む）。かぎの絵は小屋のかぎ（`drawTool`）に、持ち手の小さな家を足したものです。演出: 渡すと絵の写しがウィスプへ飛び、ウィスプが一度はね、点数が浮かびます。ひみつをタップするとカードが一度揺れ、影の耳が一度動きます。ラウンドが終わるとウィスプから火花が出ます。赤なし、画面の揺れなし、音なし。

## 決めたことと代案

- **1回のタップでものを渡す。「守る」ボタンはない。** 代案: ものごとに「渡す / 守る」のボタンの組（試練3の見てから決める形。ものごとに1歩増え、状態に何もしない2つ目の「守る」動作ができる）。ものをウィスプやポケットにドラッグする（ドラッグは指1本のタップの規則に反する）。子どもが終わったと思ったときに押す「おわり」ボタン（「何も渡さない」が終わり方の1つになる）。1回のタップなら、ひみつを守るとは単に渡さないことで、それは実生活の習慣です。そして渡してよいものがなくなるとラウンドが終わるので、いつもすることがあり、残るのがひみつです。
- **タップされたひみつは取られず、手元に残る。** 代案: ひみつがウィスプに渡り、影がそれを「聞く」（小さなこわさで、学習設計が禁じている。ひみつを状態に入れることにもなり、INV-47 に反する）。ラウンドが失敗してやり直しになる（罰で、6歳の子どもにはラウンドを失うこと）。やさしいメッセージで手元に残し、連続を切ることで、代償を得点にとどめます。
- **影はウィスプのそばに座り、何もしない。** 助手に渡すものを「だれかが聞いているかもしれない」を表します。代案: カードに向かって動く影（追いかけっこで、こわさになる）、ひみつをつかむ影（こわさで、ひみつが出ていく）、影なし（試練の名前と規則の理由がなくなる）。
- **ひみつを画面で名指しする（案内とルールカード）。** 学びは規則そのものなので、子どもはそれを当てはめる練習をします。規則を隠すと、試練が当てものになります。ルールカードは、字を読めない子どものために規則を絵にします。タップのあとのメッセージだけでひみつを知る代案は、まちがいで教えることになり、この設計が小さくしている代償です。
- **渡してよいものは、あめ、はな、どんぐり、はっぱ。ひみつは、おうちのかぎ、じゅうしょ、あいことば。** 依頼は、かぎ、住所、合言葉、あめを挙げています。学習設計の行は「家の鍵、名前、あめ」を渡してよいものとしていて、L4 と食い違うので、その行を直します（REQ-7.14.4）。名前はどちらのグループにも入れません（「文言」を参照）。
- **最後の渡してよいものを渡すと、ラウンドはひとりでに終わる。** 代案: 野原のような受け取りボタン（何も決めない1歩が増える）。ラウンドごとのタイマー（2つ目の時計）。終わったラウンドは「つぎへ」を待つので、子どもはしめくくりの一言と南京錠のついたひみつを見られます。
- **ひみつは1つか2つで、交互。** となりのラウンドはいつもちがい、子どもは「2つ守る」を規則として数えられません。ひみつ3つでは渡してよいものが2つになり、ラウンドがとても短くなります。
- **表ではなくシード**、野原と同じく。ひみつの場所は遊ぶたびに変わります。
- **試練2と3と同じ60秒の1回**、同じ得点（100、続けて渡すごとに50、4つまで）。試練2と3はプレイテストの感想のあとでこの形に変わりました。新しい試練をそこから始めれば、同じ感想を避けられます。得点が「速くタップ」を教えない理由: ひみつのタップで連続が切れるので、全部のカードをタップする子どもは、ラウンドごとに連続のボーナス（1回渡すにつき最大200）を失います。計算例: 渡してよいものを続けて8つ渡すと1,900、同じ8つで1つ目と5つ目の前にひみつをタップすると1,400。速さが報われるのは、渡してよいものを渡した数を通してだけです。
- **別々のイベントと `trial` のガード。新しいフェーズではない**、試練2と3と同じく（INV-1 は3つのフェーズを保つ）。
- **袋のボタンは野原のボタンの上に置き、タイトルを上へ動かす。** ほかの2つのボタンは場所を保つので、試練2と3のスモークは同じ場所をタップします。変わる固定値は `field-layout.test.ts` の `titleArt` だけで、理由は `tasks.md` に書きます。
- **かぎは小屋のかぎの絵に小さな家を足したもの**で、名前は「おうちのかぎ」なので、小屋の道具には読めません。ゲームは、小屋のかぎを渡したのがまちがいだったとは言いません: それは小屋のための道具でした。
- **「つぎへ」は野原の横長のボタンを使い回す**（同じ場所、同じロック）。最後の渡してよいものと「つぎへ」をすばやく2回タップしても、終わった画面を飛ばせません: カードはボタンの場所になく、ボタンは出てから 450 ms 押下を受けません。
- **モデルの `record`** はテストにあり、`GameState` にはありません: ゲームはそれを使いません。

## リスク

- 作成用サンドボックスでは WebKit が起動しません（`docs/evidence/didnt-work.md`）。モバイルのスモークはそこでは iPhone 13 のタッチ設定つき Chromium で走り、そう書きます。実際の WebKit の実行は CI のものです。
- 子どもが全部のカードをタップするかもしれず、そのとき学びはメッセージ、ルールカード、しめくくりの一言にかかります。次のプレイテストでは、最初の数ラウンドのあとに子どもがひみつをタップしなくなるか、かぎ、じゅうしょ、あいことばがなぜ手元に残るのかを自分の言葉で言えるか、「かげが きいてるかも」をどう受け取るか（おもしろがるか、こわがるか）を記録します。
- `じゅうしょ` と `あいことば` は、6歳の子どもによっては新しい言葉かもしれません。絵がそれを伝えます。プレイテストでは、伝わっているかを記録します。
- 子どもは、手元に残ったひみつを「ゲームがやってくれた」と受け取るかもしれません。メッセージは「それはひみつ」と言い、決めることを子どもに返します。プレイテストで記録します。
- ピクセルの測定点は絵に左右されます。測定点と絵は `bag-layout.ts` を共有するので、バッジが動けば1か所で落ちます。

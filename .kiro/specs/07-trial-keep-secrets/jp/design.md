# 設計: 試練4「The Listening Shadows」

> 和訳です。**正本は英語版** [`../design.md`](../design.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・要件ID（`REQ-7.n`）・不変条件ID（`INV-n`）は原文のままです。

`requirements.md`（REQ-7.n）を実装します。ADR 0001（純粋なreducer）、ADR 0003（ゲート）、`.kiro/steering/structure.md` のレイアウト規則に従います。新しい依存も、新しいアセットも、新しいADRもありません。reducerは純粋のまま、sceneは薄いままで、これはADR 0001と0003がすでに言っていることです。モジュールの構成は試練2と3（`05-trial-grant-tools`、`06-trial-verify-stars`）と同じなので、小屋や畑を知っている人は shadows も読めます。

このspecが前の2つと違うのは1点だけです。**試練4は最初のバージョンから60秒のタイムアタックです。** 試練2と試練3は、どちらも時計なしで作られ、同じ3つの感想（「タイトルに戻れない」「ゲームになっていない」「60秒のタイムアタックにして」）を受けて改訂されました。試練4は最初から3つすべてへの答えを持っています: 試練1の `Run`（時計、得点、連続、ベスト）、試練1の終了画面、どの段階にもある小屋の「Title」ボタン。代わりに、畑にはなかった設計上の問いが1つ増えます。素早い子が、見ないことで報われないようにするにはどうするか（Decisions 参照）。

## 子どもがすること

```text
title --南京錠のボタンをタップ（ゲームがシードを引く）--> deciding, ラウンド0
deciding --DecideItem give--> decided（品物が影の吹き出しへ）
deciding --DecideItem keep--> decided（タイルに南京錠、吹き出しに静かな点）
decided  --DecideItem--> 同じ状態
deciding --NextItem--> 同じ状態
decided  --NextItem--> deciding, 次のラウンド（シードの次の品物）
any      --Tick、時計が0--> over（終了画面。試練4は元のまま）
over     --StartShadows--> deciding, ラウンド0、新しいラン（時計満タン、得点0、ベストは残る）
any      --LeaveShadows（ランか終了画面）--> title
```

`DecideItem` はそのたびに得点もします: 正しい決定（秘密を残す、または渡してよいものを渡す）は、100点に、続けた正しい決定1つにつき50点を足し（最大4つ分）、間違った決定は連続を途切れさせます。タイトルのそれ以外の場所のタップは従来どおり試練1を始めます。

1ラウンドには絵が1つとボタンが2つ。6歳の子はものを見て、（親が読めば）「影が聞いているよ」を聞き、選びます。決定は1タップで、結果を読むのは2つ目の段階（「つぎへ」）なので、まとめの一言が画面に出る時間があります。

## Domain（`src/domain/shadows.ts`）

### 状態

```ts
type Shadows =
  | { stage: "deciding"; seed: number; round: number }
  | { stage: "decided"; seed: number; round: number; choice: "give" | "keep" };
```

`GameState.shadows` は、`trial` が4でないとき常に `initialShadows`（INV-51）。品物は保存しません。`itemOf(shadows)` が `seed` と `round` から導きます。結果も保存しません。`shadowsOutcome` が品物と選択から導くので、状態がルールとずれることはありません（REQ-7.8.5）。`heardItem` は影が聞いたものを導きます: 渡した後はその品物、それ以外は何もなし。

### 品物: シードと4つの順番

`items` は6つのid: `houseKey`、`address`、`password`（秘密）と `candy`、`ball`、`flower`。どれが秘密かを言う場所は `isSecret` の1か所だけです（INV-47）。`itemAt(seed, round)` は、`seed % 4` で手書きの4つの順番から1つを選び、`floor(seed / 4) % 6` から始めて、ラウンドとともに順番をたどって折り返すので、6ラウンドごとに6つの品物がすべて出ます。

4つの順番を種類で書くと（S 秘密、G 渡してよい）: `SGGSSG`、`GSSGSG`、`SGGSGS`、`GGSSGS`。どれも輪になっていて、直前と同じ品物は出ず、折り返しを含めて同じ種類が3つ続かず、輪をどれだけ回しても両方の性質は保たれます。単体テストが100個のシードで、あらゆる開始位置からこれを確かめ（INV-46）、シード0〜4、9、23、24、2^32 - 1 の順番を固定します。

### イベント（`events.ts`）とreducer

`ShadowsEvent = DecideItem { choice } | NextItem`。小屋や畑と同じく、最上位のイベントが2つ: `StartShadows { seed }` と `LeaveShadows`。名前を専用にしたのは、試練1〜3のどのイベントも試練4に作用せず、試練4のどのイベントもほかの試練に作用しないようにするためです（INV-51）。

`reducer.ts` に `startShadows`、`leaveShadows`、`decide` が加わります。`Tick` は試練4でも動きます（3つの `||` を4つの試練のリストにしました）。`start` は `shadows` も捨てます。畑のイベントで `reduce` の複雑度が上限に達したため、試練のイベントは2つ目のswitchにあり、shadowsのイベントは3つ目（`reduceLaterTrial`）に置いて、畑のイベントはそこから渡します。`decide` は試練1〜3と同じく `scoreSearch` で得点します: `decisionRight(shadows, choice)` が決定を採点する唯一の場所（`true`、`false`、決めるものがなければ `null`）で、`reduceShadows` が記録します。

### 不変条件

INV-46〜INV-53（`requirements.md` 参照）には、それぞれ `shadows.pbt.test.ts` にプロパティテストがあり、新しいイベントを含む列でINV-1〜INV-4とINV-15〜INV-17も走らせます。`.kiro/steering/domain-invariants.md` に行とこの範囲の注記があります。

### モデル検査（`shadows.model.test.ts`）

実物のreducerを、子どもがしたことの独立した記録で包みます: `expected`（このラウンドで押した選択）、`rights`（これまでの正しい決定の数。2は「2以上」）、`scoreOk`（動くべきでないのに得点が動いた最初のステップから false）。アルファベットは、2つのシード（最初が家の鍵のもの、最初がボールのもの）、両方の決定、`NextItem`、戻る、両方の言語、2つのヒーロー位置、短い `Tick` とランを終える `Tick`、ランの中の `Start`、試練1〜3のイベントのうち、ここでは何も起こしてはならないもの。状態の同一性は、得点とラウンドの際限ない増加には従いません: 得点は「ない／ある」、時計は「満タン／進行中／0」、ラウンドは6で割った余り。状態は2,664個で、約1秒で終わります。

不変条件: phase、trial、`shadows` が合っていること。`shadows` が試練4以外では初期であること。ほかの試練が無傷であること。時計が0〜60秒で、ちょうど0のとき終わっていること。決めた状態が子どもの押した選択を持つこと。決定が、秘密を残したか渡してよいものを渡したときだけ正しいこと。得点が正しい決定のときだけ、連続の点数ぴったりで動くこと。ゴールは、どの状態からも: 正しい決定と間違った決定、4種類それぞれ、タイトル、終了画面。時計も戻る道もないときは、新しいラウンド、次のラウンド、2回目の正しい決定。わざと壊す8つ（秘密を残せない、`NextItem` を無視、押したものにかかわらず「give」と記録、2回目の `DecideItem` が決定を変える、試練4で `Tick` が動かない、`LeaveShadows` を無視、間違った決定が得点する、正しい決定が得点しない）が、それぞれ想定したチェックを失敗させ、最短の列を出します。

## Content（`src/content/`）

`strings.ja.json` と `strings.en.json` に `shadows` グループ。同じキーを同じ順で: `enter`, `timeAttack`, `guide`, `ask`, `givenSafe`, `keptSecret`, `givenSecret`, `keptSafe`, `give`, `secret`, `next`, `items`（6つの名前）、`why`（6つのまとめの一言）。5つのメッセージは品物の名前を1回取ります（`{0}`）。どのメッセージがどの品物について言えるかは、contentテストが従うルールの一部です: `givenSafe` と `keptSafe` は渡してよい3つだけ、`keptSecret` と `givenSecret` は秘密の3つだけ、`ask` はどれでも。

英語（正本）:

| キー | 文 |
|---|---|
| guide | A shadow is listening! / Give it or keep it secret? |
| ask | You have the {0} / What will you do? |
| givenSafe | The shadow heard / the {0}. That is fine! |
| keptSecret | The shadow heard nothing / You kept the {0} |
| givenSecret | The shadow heard / the {0}! |
| keptSafe | You kept the {0} / It was fine to give |
| why（秘密） | A house key is a secret / We give it to nobody（住所と合言葉も同様） |
| why（それ以外） | A candy is just a candy / It is fine to give（ボールとおはなも同様） |

日本語は `strings.ja.json` にあります。文言は影が何をしたいか、何をするかを決して言わず、何を聞いたかを言います。kid-readerの基準（`.kiro/agents/kid-reader.md`）は手で当てました: 日本語の各行は12文字以内で文節ごとに空白があり、各文字列は1つのことを言い、日本語と英語は同じことを言い、子どもを従わせるために恐怖を使わず、間違った決定の後に責めません。間違った決定も、正しい決定と同じ平らな口調で伝えます。

`shadows-content.test.ts` は、キーと順番、`{0}` が必要なところに1つだけあって他にはないこと、日本語の規則と英語の長さ（1行26文字）を適用できる品物すべてを入れて確かめ、まとめの一言がメッセージの行を繰り返さないこと、言葉がルールの内容を言うこと（聞いた、何も聞かなかった、渡してよい、秘密、誰にも）、両言語の非難語・恐怖語・主張語のリストを確かめます。主張語のリストは "always"、"every"、"all"、"know"、"friend"、"family"、"robot"、"real"、"anyone"、"anything" とその日本語を排除します。

## Game（`src/game/`）

### 入口と場面の選択

`route.ts` は試練4を小さな表で `shadows` 場面に対応させます（試練2、3、4。レーンは既定）。`boot.ts` は `ShadowsScene` を足します。`TitleScene` は3つ目の入口を持ち、lintが場面に許す30行に `create` が収まるよう、専用のメソッドで作ります。シードは小屋や畑と同じくそこで引きます（`newSeed`）。`OverScene` は `playShadows` と `leaveShadows` を持ち、`over-view.ts` が試練4のためにそれらを名づけます。

### タイトル

3つのボタンには 3 x 80 + 2 x 8 = 256 ピクセル必要ですが、タイトルはすでにy 776まで埋まっています。小屋ボタン（y 736）と畑ボタン（y 648）は動かないので、試練2と3のレイアウトとテストは触りません。新しいボタンはその上、y 560 に置きます。それより上のものはすべて上へ: ウィスプとヒーローは90ピクセル（y 448と458へ。`titleArtBottom` は514）、試練1のカードは90（y 282）、題名は80（y 150）。カード、アート、ボタンの間隔は、以前のレイアウトの比率を保ちます（カードとウィスプの間は32ピクセル、ボタンの間は8以上）。`field-layout.test.ts` の固定値は一緒に変わり、ほかのタイトルのテストは関係式なので引き続き成り立ちます（`tasks.md`「Tests of the old behavior」参照）。

### ボタン（`button-view.ts`、`ui/field-buttons.ts`）

畑の2つの判定ボタンと1つの幅広ボタンは、試練4の2つの決定ボタンと「つぎへ」ボタンとまったく同じ形で、同じ場所（`buttonRects`）にあります。`ui/field-buttons.ts` は共有です。その `ButtonView` は型だけの小さなモジュール（`button-view.ts`）に移り、絵の描画は表になって2つ増えました: 矢印（「わたす」）と南京錠（「ひみつ」）。畑の絵と挙動は、新しいボタンの組が450 ms押しを無視すること（`button-lock.ts`）を含めて変わりません。ここではそれが、「わたす」の素早い2回タップが、代わりに出る「つぎへ」を押してしまうのを防ぎます（REQ-7.9.5）。

### レイアウト（`shadows-layout.ts`。案内と戻る道は `shed-layout.ts`、ボタンとウィスプは `field-layout.ts` から）

上から、ゲームピクセルで: ランの上の段（y 24）、案内（y 68、2行）、吹き出し（(290, 138) に 88 x 60）、タイル（(112, 232) に 140 x 140）と影（(290, 246) に 130 x 120）が並ぶ、メッセージ（y 352、幅340）、まとめの一言のパネル（(195, 440) に 340 x 88）、ボタン（y 534、高さ80）、ウィスプ（y 720）、「Title」ボタン（(347, 788) に 80 x 80）、ヒーローの領域（y 612、空けておく）。タイルの中: 絵は高さ76で-14の位置、名前は+50、チェックのバッジは右上(62, -62)、南京錠のバッジは左上(-62, -62)で、半径はどちらも15。レイアウトのテストは、キャンバスの範囲、各段階（決めている、決めた）で重ならないこと、80 x 80 の対象、上からの順番、ヒーローの領域、タイトルの3つのボタンとカードとアートを確かめます。

### View（`shadows-view.ts`）

`shadowsView(state)` は、案内、メッセージ（品物と段階に応じて名前入り）、タイル（品物、名前、薄さ、チェック、南京錠）、吹き出し（`none`、`item`、`quiet`）、まとめの一言（決定の後）、ボタン、「Title」ボタンのラベル、演出のための結果を返します。チェックは正しい結果、南京錠は残した状態です。渡した品物は薄くなります。`justDecided(before, after)` は、今決定が行われたことを言います。

### Scene（`scenes/ShadowsScene.ts`）とアート（`ui/`）

sceneはviewを描き、タップをイベントにします。`update` は `Tick` を送ります。ルールは持ちません。アートはコードで描きます: `item-art.ts`（6つの品物をシルエットで）、`shadow-art.ts`（影、吹き出し、静かな点、南京錠のバッジ、タイトルの南京錠）、`item-tile.ts` と `shadow-stage.ts`（ウィジェット）。影は、丸いラベンダー色の体で、タイルに向く側に大きな耳があり、タイルを見る目と、笑顔でも怒り顔でもない平らな口を持ちます。暗い空の上で見えるよう、自分の影と明るい縁があります。決定のとき影は一度だけ身を乗り出し、正しい決定ではタイルから波紋と火花が出ます。赤いものも揺れるものもありません。家の鍵は、輪の中に小さな家がある形で、小屋の素の鍵と間違えません。

### スモークが絵を見る方法

shadowsはキャンバスに描かれ、DOMにはそのコピーがないので、「渡した」と言う状態は、吹き出しが空のままでも通ってしまいます。スモークはスクリーンショットから点を読み（`shadows-layout.ts` のプローブ）、それぞれをグレースケール画面と同じ重みで明るさにするので、グレースケール画面でも同じ読みになります。

| 読み | 方法 | 測定値（Chromium、iPhone 13プロファイル、3倍） |
|---|---|---|
| チェック、南京錠 | 各バッジの円の内側、中心から12ピクセルの点（記号、タイルの金の枠、絵を避ける）。150より明るければ「ある」 | あり 212、なし 44 |
| 吹き出し | 角で顔（クリーム色、239）か空（13）かを読み、次に吹き出しの真ん中を横切る3点を読む: 3点とも90より暗ければ「quiet」、それ以外は「item」 | none 13、quiet 239のあと28, 28, 28、item 239のあと3点のうち少なくとも1点が119以上 |
| メッセージ、まとめの一言 | それぞれの枠の中の明るい文字ピクセル（試練1〜3のスモークが数えるのと同じ）。まとめの一言の枠は、決めている間は0 | |
| ボタン | 金色の面（幅広ボタンは細い2つの間を覆う）。畑のスモークが読むのと同じ | |

決定の前は吹き出しは「none」で、タイルにはどちらのバッジもありません。スモークは、2つの品物のあいだで、タイルの絵と吹き出しの中身の指紋も比べるので、絵が変わらないまま状態だけが変わるものは失敗します。「無音」は畑のスモークと同じく確かめます: ページを読み込む前に `AudioContext.createOscillator`、`createBufferSource`、`HTMLMediaElement.play` を包み、どれも呼ばれないことを求めます。

## 判断と代替案

- **一度に1つのものと、2つのボタン。** 代替案: 品物の盆を出して、それぞれをタップして渡す（タップが決定なので、6歳の指のすべりで秘密を渡してしまう。また「取っておく」という行為がなく、子どもがそれを秘密と言う場面がない）。小屋のように選んでから手渡す（子どもが知っているか知らないかの決定に、毎ラウンド1タップ増える）。2つのかごへのドラッグ（2つの的とドラッグで、1本指の規則に反する）。絵と言葉の付いた2つのボタンは、言葉がなくても読め、1タップで、分類に名前を付ける（「ひみつ」）ことが学びの行為になります。
- **「Keep」でなく「Secret」。** ボタンは、子どもがそれをどうするかではなく、それが何かを名づけます: 「Give」か「Secret」。代替案: 「Give」と「Don't give」（否定がボタンで、6歳には読みにくい）。「Yes」と「No」（絵がなく、決定ではなく質問に答えることになる）。
- **決定は取り消せない。** 秘密に「わたす」を押した後、ラウンドは「つぎへ」で進み、その品物に2回目はない。L4の学びは、言ったことは言ったこと、ということ。やり直し（小屋や、畑の間違った判定の後のような）は逆を教える。子どもへの代償はそのラウンドの得点と連続だけで、時間は失わず、同じ品物は6ラウンド後にまた来る。代替案: 無制限のやり直し（上のとおり却下）。渡した秘密にライフや時間の罰（間違うことへの恐れ。REQ-7.4が排除）。
- **渡してよいものを残した場合も間違いとして伝える。** あめを残すと得点がなく連続が途切れ、「It was fine to give」と平らに言う。これがないと、全部に「Secret」と答えるのが最善手になり、子どもは全部が秘密だと学ぶ。それは見分けることの反対。連続のおかげで、いつも同じボタンを押す子は、見ている子の4分の1より少ない得点になる（seed 0 の最初の8ラウンドで、どちらのボタンでも450点に対し、8回正しいと1,900点。テストが両方を固定する）。代替案: 秘密を残すごとのボーナス（「Secret」だけに報いる）。残しても罰なし（上のとおり）。
- **得点が「速く押す」を教えない理由。** 試練3と同じ: 正しい決定は連続によって100〜300点で、間違いは連続を途切れさせ、時間は失わない。速さは正しい決定の数を通してだけ得点になり、正しい決定には、絵と名前を先に見る必要がある。品物は6ラウンドごとに繰り返すので、6つを覚えた子は速くて正しく、それは決まった一覧を教えるゲームの狙い。本物の助手の秘密が6つだとも、決めるのがこのように速いとも、設計は主張しない。
- **シードと4つの順番。表でも乱数でもなく。** domainで乱数を引くとADR 0001が破れ、モデル検査が無限になる。固定の表1つだと、子どもが位置を覚えてしまう。シードの下の手書きの4つの輪なら、ルール（繰り返しなし、3連続なし、6ラウンドで6つ全部）を確かめられ、種類が交互にならないので、「1つおきに秘密」は遊び方にならない。代償は、イベントの項目1つと、固定した単体テスト。
- **6つの品物。** 学習設計は「house key, name, candy」と言います。名前は、そのリストの中で、秘密とも渡してよいとも言い切れない唯一のもの: 秘密かどうかは誰が聞くかによるが、6歳の子には判断できず、ゲームが平らに言うルールは半分の場合間違いになる。住所は、子どもがすでに守るよう教わる秘密で、合言葉はL4そのものの秘密（`docs/learning-design.md` は「keys, addresses or passwords」と言う）。渡してよい3つは、子どもが持っていて考えずに分け合うもの: あめ、ボール、おはな。合言葉の日本語は「パスワード」でなく、子どもの言葉の「あいことば」。
- **影は聞き手で、渡される相手はウィスプ。** 子どもはウィスプに渡し、影はそのそばにいる: 何を渡しても影は聞く。これは「助手以外の何かが、渡したものを見るかもしれない」ための演出上の道具。ゲームの中で本物のAIの事実としては述べず、影が聞いたことをどうするかを文言は決して言わない（REQ-7.4）。代替案: 影が品物を欲しがる（鍵を求める見知らぬ人は別の学びで、「影が欲しがる」はおどし）。影を描かず、メッセージが聞いたことだけを言う（見るものがなく、「第三者」という学びには絵が要る）。
- **影の顔。** タイルを見る丸い目、平らな口、大きな耳: 好奇心があり、決して怒らず、秘密を前に笑わない。笑顔は秘密を渡されて喜んでいるように見せ、への字の口は敵にしてしまう。
- **吹き出し。** 結果は絵で2回伝える: 「聞いた」は吹き出しの中の品物（タイルでは薄く）、「何も聞かなかった」は3つの点（タイルでは南京錠）。代替案: 影の色の変化（ハードルール7で却下）。音（ゲームは鳴らさない）。
- **まとめの一言は毎回の決定の後。** 畑では受け取りの後だけだった。そこでの学びは5つの星にわたる子どものしたことについてだから。ここでの学びは品物（どういうものか）についてで、子どもはどのラウンドでも間違えうるので、決定のたびに、金の縁のある専用のパネルに出し、メッセージは何が起きたかを繰り返さずに言う。
- **タイトルの順は、上から試練4、3、2。** spec 06が畑を小屋の上に置いたので、上へ続ければ小屋と畑のボタンは今の場所に残り、それらのテストもそのまま。試練を上から順に並べるために小屋と畑を下げる案は、挙動が変わらないのに、2つのレイアウトと4つのテストを変える。
- **タイトルの題名、カード、ウィスプ、ヒーローが上に動く**（REQ-7.1.1、「共有の入口やイベントの変更」）。代替案: ボタンを小さく（80 x 80 の最小を下回る）。ボタンを2列に（24文字のラベルとキャプションは190ピクセルに入らない）。試練選択画面（範囲外、REQ-7.1.5）。
- **ボタンの絵は矢印と南京錠。** 言葉も色もなく意味が伝わり、輪郭が違うので選んだ。畑のチェックと点の輪はそのまま。
- **2つのイベントでなく `DecideItem` 1つ。** `choice` 付きの1つのイベントなら `reduceShadows` は1ケースで、`decisionRight` が適用前に選択を採点できる。2つのイベント（`GiveItem`, `KeepItem`）なら、ガードを繰り返す。
- **新しいphaseでなく `trial` でガードする。** INV-1は3つのphaseのまま。
- **保護者向けの文はなし。** 保護者画面は範囲外（`parents.*.json` の空のリストのまま）なので、6つの品物がゲームであり、本物の家族は誰に話すかを自分で決める、という保護者への言葉はありません。プレイテストでは、これについて保護者が何と言うかを `docs/device-checklist.md` に記録するべきです。

## リスク

- WebKitは作業サンドボックスでは起動しない（`docs/evidence/didnt-work.md`）。モバイルのスモークはそこでiPhone 13のタッチプロファイルのChromiumで動くと明記し、本物のWebKitの実行はCIのもの。CIのスモークが緑になるまで、タスクは完了と呼ばない。
- ピクセルのプローブは描画に依存する。バッジ、吹き出し、タイルを変えてプローブが動くと、スモークが失敗する。プローブと描画は `shadows-layout.ts` を共有するので、数字は1か所で変わる。読みはしきい値から十分離れており（212に対して150と44。静かな点の28に対して90）、WebKitのアンチエイリアスの差を吸収する余裕になる。
- アートはコードなので、スクリーンショットを目で見て判断する。最初の家の鍵はスクリーンショットで「棒の上の鳥の巣箱」に見えたので、輪の中に家がある形に描き直した。
- 子どもがいつも同じボタンを押すかもしれず、そのときは学びはメッセージとまとめの一言に頼る。次のプレイテストでは、子どもが影を悪いものと言うか、渡した秘密で動揺するか、押す前に「ひみつ」と言うかを記録するとよい。
- 子どもが「影が鍵を聞いた」を「影がうちに来る」と読むかもしれない。言葉にその理由は与えていないが、プレイテストで記録する。そうなれば、言葉は「知っている」でなく「聞いた」のままにする。
- 6つの品物は少ない。1、2回遊べば子どもは覚え、ゲームは判断より速さに報いるようになる。プレイテストでそうなるなら、動かすのはルールではなく品物の数（と新しい表）。
- モデル検査は2,664状態で約1秒。壊したゲームの実行は1回1〜2秒。

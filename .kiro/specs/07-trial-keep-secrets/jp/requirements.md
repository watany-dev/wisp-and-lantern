spec `07-trial-keep-secrets`。学習目標 L4（`docs/learning-design.md`）を教えます。助手は渡されたものを聞いていて、そのそばでほかの誰かが聞き耳を立てているかもしれません。だから、家の鍵・住所・合言葉（パスワード）は誰にも渡さず、あめのようなものは渡してよい、という内容です。要件IDは `REQ-7.n` です。`REQ-6.n` は `06-trial-verify-stars`、`REQ-5.n` は `05-trial-grant-tools`、`REQ-4.n` は `04-score-attack`、`REQ-3.n` は `03-trial-tell-vague-request`、`REQ-2.n` は `02-trial-tell`、`REQ-1.n` は存在しない `01-core-loop` のもので、どれも再利用しません。

既存の基盤の上に4つ目の試練を足します。試練1〜3の作り直しではありません。レーン、小屋、畑は、それぞれの流れ、時計、得点、終了画面をそのまま保ちます。試練4は最初から、60秒のスコアアタック（得点、連続、試練1の終了画面、「タイトル」ボタン）として作ります。試練2と試練3は、それぞれ同じ3つの感想（「タイトルに戻れない」「ゲームになっていない」「60秒のタイムアタックにして」）を受けて改訂が必要になったためです（`05-trial-grant-tools` 改訂2、`06-trial-verify-stars` 改訂3）。

## なぜ作るか

`docs/learning-design.md` は試練4を「渡してよい品物だけを渡す。影＝聞き耳を立てる第三者」としています。子どもは一度に1つだけ品物を持ち、ウィスプのそばで影が聞いています。子どもは決めます。それを**わたす**か、**ひみつ**にするか。家の鍵、住所、合言葉は秘密で、あめ、ボール、おはなは渡してよいものです。正しく決めると得点になり、続けて正しいほど増えます。秘密を渡してしまうことだけは取り消せないので、影は「聞いて」しまい、連続は途切れ、得点はなく、ゲームはそれをやさしく伝えて次へ進みます。渡してよいものを手元に残した場合も得点はなく連続が途切れます。なので、全部に「ひみつ」と答える子も、全部に「わたす」と答える子も、得点はほぼ同じように低く、得点は「どれがどれか」を知っていることに報います。

影は聞いているかもしれない第三者であり、敵ではありません。試練のどこも暗く、怖く、おどすようにはせず、子どもや家に何かが起きるとは言いません。文言は、影が何を聞いたか、何が秘密かだけを言います。

`docs/learning-design.md` の表は「house key, name, candy」と書いています。名前は、6歳の子には秘密とも安全とも言い切れないので使いません（`design.md` の Decisions）。品物は、家の鍵・住所・合言葉に対して、あめ・ボール・おはなです。

## 用語

- **Shadows**: 試練4「The Listening Shadows」の場所。ウィスプのそばで影が聞いています。
- **品物（item）**: ラウンドでウィスプの前にある1つのもの。全部で6つ: 秘密が3つ（家の鍵、住所、合言葉）と、渡してよいものが3つ（あめ、ボール、おはな）。
- **秘密（secret）**: 誰にも渡さないもの: 家の鍵、住所、合言葉。
- **ラウンド**: 1つの品物。現れてから、次の品物を出す「つぎへ」まで。60秒のランでは、子どもが進めた分だけ続く。
- **ラン**: 試練4の60秒。タイトルのボタン（または「もう一度」）のタップから、時間切れまで。試練1と同じ `Run`（時計、得点、連続、セッションのベスト）を使う。
- **シード**: 試練4を開くときにゲーム（domainではない）が引く整数。同じシードなら、同じラウンドに同じ品物が出る。
- **決定（decision）**: 子どもの選択。品物をウィスプに**わたす**か、**ひみつ**にするか。ラウンドに1回、2つのボタンのどちらか。
- **正しい決定**: 渡してよいものを渡す、または秘密を手元に残す。それ以外は**間違った決定**: 秘密を渡す、または渡してよいものを残す。
- **聞いた（heard）**: 影が取り込んだもの。渡した品物は何であれ聞かれる。残した品物は聞かれない。
- **連続（streak）**: 続けた正しい決定。間違った決定で途切れる。正しい決定の得点は100に、連続1つにつき50を足す（最大4つ分）。
- **まとめの一言（closing line）**: 決定のたびに出る短い文で、その品物がどういうものかを言う。誰にも渡さない秘密か、渡してよいものか。独立した文。
- **終了画面**: 時計が0になったときのランの画面。得点とベスト、「もう一度」と「タイトル」。

## 要件

### REQ-7.1 タップで shadows に入る

6歳の子として、タイトルから指で影のところを開けたい。おとなに頼らず遊べるように。

1. タイトル画面に、試練4のための3つ目の追加タップ対象を出す: 南京錠の絵と子どもの言語の短いラベルが付いた、80 x 80 ゲームピクセル以上のボタン。畑ボタンの上にあって、それ、試練1のカード、タイトルのウィスプ、ヒーローと重ならない。
2. ボタンをタップすると試練4が開き、ランが始まる。状態は `title` から `trial` へ、`trial` は4、新しいシードのラウンド0、時計は60秒満タン、得点0、連続0。セッションのベスト得点は引き継ぐ。レーン、小屋、畑には触れない。シードはゲームが（domainの外で）引き、イベントに付けて送る。domainは何も引かない。
3. このボタンのタップは、試練1を始めたり小屋や畑を開いたりしない。ほかのボタンのタップが shadows を開くこともない。タイトルのそれ以外の場所のタップは従来どおり試練1を始め、終了画面の「もう一度」は自分の試練の新しいランを始める。
4. 入口は、普通の画面での普通のタップ。judge用URL、隠しジェスチャー、コンソール呼び出し、クエリパラメータではない。
5. 試練選択画面も汎用ルーターもない。新しい画面は shadows だけ。
6. タイトルの文は、すべて一緒に置かれた試練に合っている。3つ目のボタンも、ほかの2つと同じキャプション `60びょうで いくつ？` / `How many in 60 seconds?` を持つ。ラベルに数字は入れない。

### REQ-7.2 画面に出るもの

1. 画面には、ランの上の段（残りの秒数、バー、得点。試練1〜3と同じ）、案内の文、名前付きの品物のタイル、頭の上に吹き出しのある影、メッセージ、まとめの一言（決定の後）、ウィスプ、「タイトル」ボタン（REQ-7.7.5）が出る。2つの決定ボタンと「つぎへ」ボタンは、使えるときだけ出る（REQ-7.3.2, REQ-7.3.5）。
2. 案内は2行以内の短い1文。影が聞いていること、品物を渡すか秘密にするかを聞く。どの段階でも出たまま。
3. 品物は6つのうちの1つで、コードで描かれ、それぞれ他と違うシルエットを持ち、下に子どもの言語の言葉で名前が書かれる。
4. 影はどの段階でも画面にいる。丸くやわらかい体、品物のほうへ向けた耳、品物を見る目で描く。怒っている、ずるそう、飢えている、怖い姿には決して描かない。タップ対象ではない。
5. 影の上の吹き出しは、聞いたものを示す: 子どもが決めているあいだは何もなし。品物を渡した後はその品物の絵。品物を残した後は静かな3つの点。
6. 決定の結果は、色ではなく、静止した絵と言葉で伝える: 正しい決定ではタイルにチェックのバッジが付く。残した品物のタイルには南京錠が付く。渡した品物はタイルで薄くなり、吹き出しに現れる。間違った決定でも×も赤も出さない。
7. ウィスプはどの段階でも画面にいて、いつもの親しみやすい顔をしている。怒り、ずるさ、怖がり、傷ついた顔には決して描かない。この試練ではタップ対象ではない。

### REQ-7.3 決める: わたすか、ひみつか

6歳の子として、そのものをどうするか言いたい。ひみつが何かわかるように。

1. 決める前は、2つのボタンが出る: 矢印の絵の「わたす」と、南京錠の絵の「ひみつ」。どちらも言葉付き。ほかの段階では出ない。
2. 「わたす」か「ひみつ」を押すのが決定で、1回だけ。決定は押されたとおりに記録され、ゲームは変えたり直したり子どもに代わって選んだりしない。同じラウンドの2回目の押しは何も変えない。
3. 正しい決定は得点になり（REQ-7.7.3）、メッセージがやさしくそう伝える。間違った決定は得点がなく、連続が途切れる。
4. 間違った決定は、災難でも怖い場面でもない。影が何を聞いたか、何を残したかを平易な1文で、そしてまとめの一言で伝える。赤も×も揺れも音もない。短い演出が流れてもよい（REQ-7.3.6）。
5. 決定の後、結果はメッセージとまとめの一言と一緒に、子どもが「つぎへ」を押すまで画面に残る。ランの終わり以外で、結果が自然に消えることはない。「つぎへ」で次の品物が来る。
6. 決定の結果は、reducerがその場で決める。アニメーションやタイマーを待たない。短い演出（品物が影の吹き出しへ移る、南京錠が閉まる）が流れてもよく、無視しても情報は失われない。
7. 渡してしまった秘密は、同じラウンドでは取り戻せない: 秘密に「わたす」を押した後、その品物に2回目はなく、ラウンドは「つぎへ」で進む。これが学びで、そのラウンドの得点と連続を失うが、時間は失わない。

### REQ-7.4 影は聞いている。敵ではない

1. 文言は影を `かげ` / 「the shadow」と呼ぶ。影が何を聞いたかを言う（`かげが ... を きいたよ` / 「The shadow heard the ...」）。影が何かを欲しがる、取る、盗む、だます、ついてくる、傷つける、とは決して言わず、子どもや家や家族に悪いことが起きるとも言わない。
2. 子ども向け文言に、内容テストの恐怖語・非難語のリストにある語を使わない（例: "enemy", "thief", "steal", "stranger", "scary", "afraid", "danger", "monster", "spy", "wrong", "bad", "mistake", "oops", "sorry", "naughty" とその日本語。リストは `shadows-content.test.ts` にある）。子どももウィスプも責めない。
3. 事実は隠さない: 秘密を渡したら、影が聞いたと言う。渡してよいものを残したら、そのことを平易に言う。
4. 渡してよいものについては、影がそれを聞くことを「だいじょうぶ」と伝える: 「That is fine to share.」影は喜んでいる風にも欲張りにも見せない。
5. 助手がいつも正しい、いつも間違う、何でも知っている、友だちや家族である、わざとやる、とは決して言わず、示唆もせず、本物のAIが渡されたものをどうするかについて何も主張しない（`docs/learning-design.md`「What we do not teach」）。このゲームで起きたことと、品物がどういうものかだけを言う。本物の助手も渡されたものを他へ回すかもしれない、というのは演出上の道具（`design.md`）で、ゲームの中で述べる主張ではない。
6. 恐怖は、ゲームが子どもを従わせる手段には決してならない。ルールは、事の後に、平らに、やさしく言う:「A house key is a secret. We give it to nobody.」

### REQ-7.5 品物と、その順番

1. 品物は6つ: `houseKey`、`address`、`password`（秘密）と `candy`、`ball`、`flower`（渡してよいもの）。品物が秘密かどうかは純粋なdomainのルールで、最初の3つがそう、あとの3つはそうでない。ほかに決めるものはない。
2. ラウンドの品物は、シードとラウンド番号だけから決まり（決まった規則で、ほかの乱数はない）、ラウンドのあいだ変わらない。シードが違えば順番が違う。
3. どのシードでも、折り返しを含め、直前と同じ品物は出ない。種類は3つ続かない: 秘密が2つ続いたら、次は渡してよいもの。逆も同じ。6ラウンドで6つの品物が1回ずつ出る。
4. 品物を見る代わりに使えるパターンはない: 種類は単純な交互にならず、シードが各種類の落ちる位置を変える（`design.md`「The items: a seed and four orders」）。

### REQ-7.6 まとめの一言は、どういうものかを言う

1. 決定のたびに、メッセージの下の場所に、品物がどういうものかを言うまとめの一言が出る。秘密には:「A house key is a secret. We give it to nobody.」（住所と合言葉も同様）。渡してよいものには:「A candy is just a candy. It is fine to give.」（ボールとおはなも同様）。
2. 独立した文で、決定の後だけに出て、専用のパネルを持つ。メッセージとはつながない。メッセージ、タイル、吹き出し、ボタンは見えたままで、場所を空けるために文字を小さくしない。
3. このゲームの品物について本当のことだけを言う。本物のAIがいつも漏らす、決して漏らさない、秘密は危険だ、とは言わない（REQ-7.4.5）。

### REQ-7.7 60秒のラン、得点、戻る道

6歳の子として、1分でいくつ正しくできるか知りたいし、いつでもタイトルに戻りたい。また遊びたくなって、行き止まりを感じないように。

1. 試練4は60秒のラン。試練1の `Run` を使う: 入口で時計は60秒満タン、得点0、連続0、セッションのベストは引き継ぐ。時計は、子どもが何をしていても減る。時間はゲームには `Tick` としてだけ届き（1フレームは最大250 msまで）、`Tick` は試練1〜3と同じように試練4で働く。上の段には秒数、バー、得点が出る。
2. 決定の後、「つぎへ」ボタンが次のラウンドを始める: シードの次の品物、何も決めていない状態。試練を終わらせるのは時計だけ。
3. 得点。正しい決定は100点に、その前から続く正しい決定1つにつき50点を足す（最大4つ分: 100, 150, 200, 250, 300, 300 ...）。間違った決定は得点がなく連続が途切れる。「つぎへ」は得点せず連続も変えない。決定は子どもだけのもの（REQ-7.3.2）で、間違った決定は時間を失わない。得点はreducerがその場で決める。正しい決定は、タイルから点数（「+150」）を少しのあいだ浮かべる。上の段の得点がその記録。
4. 時間切れは、どの段階（決めている、決めた）でも、ランをすぐ終える。終了画面は試練1のもの:「Time's up!」、得点、セッションのベスト、ランがベストを超えたときは「New best!」。ボタンは2つ:「Play again」は試練4の新しいランを始め（時計満タン、得点0、新しいシードのラウンド0、ベストだけ引き継ぐ）、もう1つは「Title」。最後の素早いタップでボタンが押されないよう、しばらくタップを無視する。
5. 「Title」ボタンは、試練4の画面のどの段階にも、終了画面にもある: 画面では80 x 80（小屋と畑のボタンと同じ位置）、終了画面では幅広。タイトルに戻る: `phase` は `title`、`trial` は0、試練4は初期状態、ランはベストだけ残して作り直し。それ以外は変わらず（言語とヒーローはそのまま）、そこから試練1〜4が普通に開く。
6. 試練から戻された後、タイトルは0.7秒タップを無視する。「Title」の素早い2回タップで試練1が始まらないように。
7. 行き止まりなし: 試練4のどの状態（決めている、決めた、終了画面）からも、画面のボタンだけで、正しい決定、間違った決定、次のラウンド、2回目の正しい決定、終了画面、タイトルに行ける。時計も「Title」ボタンもなくても、ボタンで先へ進める。
8. 得点が「速く押す」を教えない理由: 正しい決定は連続によって100〜300点で、間違いは連続を途切れさせる。全部に同じ答えをする子は約半分正しく、わかっている子の4分の1より少ない得点になる: seed 0 の最初の8ラウンドで、450点に対して1,900点（`design.md` Decisions）。

### REQ-7.8 試練どうしは別

1. 試練4に入っても、ほかの試練のランは始まらず、`lane`、`shed`、`field`、ほかの試練の `run` の状態はタイトルにいたときのまま。`shadows` は `trial` が4でないときは常に初期値。
2. 表示する場面は `trial` に従う: 1はレーン、2は小屋、3は畑、4はshadows。`trial` が4の状態はほかの試練の場面を決して見せない。
3. 試練4では、試練1〜3のイベント（`Ask`、`PickCard`、`Retry`、`PickTool`、`GiveTool`、`RetryShed`、`LeaveShed`、`InspectStar`、`SortStar`、`KeepStars`、`RetryField`、`LeaveField`）は同じ状態を返す。試練4のランの外では、shadowsのイベント（`DecideItem`、`NextItem`）は同じ状態を返す（終了画面も含む）。`LeaveShadows` は試練4（ランか終了画面）でのみ受け付け、`StartShadows` はタイトルと試練4自身の終了画面からのみ受け付ける。
4. 試練4のランでの `Start` は言語を設定するだけ。試練4の終了画面では試練1を始め、試練4の状態を捨てる。`SetLang` は言語だけを変え、決定や結果は変えない。`MoveHeroTo` はヒーローだけを動かす。
5. 子どもが決めたことは1つの値: 品物はシードとラウンドから導かれ、保存しない。決定が正しいかどうかは品物と決定から導かれ、保存しない。
6. 試練1〜3の挙動、文言、レイアウト、テストは、このspecでは変わらない。ただしタイトルのアートとカードの位置と、それに伴う固定値は除く（「共有の入口やイベントの変更」参照）。

### REQ-7.9 縦、1本指、マウス

1. 試練4は既存の390 x 844 縦のキャンバスで遊ぶ。
2. すべての操作は、80 x 80 ゲームピクセル以上の対象への1回のタップかクリック: タイトルの試練4のボタン、「わたす」、「ひみつ」、「つぎへ」、「タイトル」ボタン、終了画面の2つのボタン。ドラッグ、長押し、ダブルタップ、2本目の指はない。
3. ヒーローの床ドラッグは試練4でも動く。ボタンから始まる押しはヒーローを動かさず、床の押しは動かす。
4. 文字と絵は、タイル、影、吹き出し、メッセージ、まとめの一言、ボタンと重ならず隠さない。どの段階（決めている、各種類の決定の後）でも、上の段と「Title」ボタンがあっても、両方の言語で、各品物の名前を入れても。ボタンはヒーローの開始位置より上で終わる。
5. 新しいボタンの組は、現れてから少しのあいだ（450 ms）押しを無視する。「わたす」や「ひみつ」の素早い2回タップが、その場所に代わりに出る「つぎへ」を押さないように。

### REQ-7.10 コードで描く、通信なし、色なし、音なし

1. 品物、影、吹き出し、南京錠、タイルは、コードで、デバイスのピクセル比で描く。既存の見た目（REQ-4.9〜REQ-4.11）に合わせる。画像ファイルは足さず、第三者のアートも使わない（ハードルール5）。
2. 試練4は、ページと同梱フォントの読み込み後、日本語でも英語でも通信を必要としない（ハードルール4）。決める、つぎへ、時間切れ、戻る、の一通りが、ネットワークを切っても動く。
3. 動きが唯一の意味を担うことはなく、1秒に3回より速く点滅せず、無視しても情報は失われない。どの結果も静止した絵で伝わる（REQ-7.2.6）。
4. 6つの品物は、色ではなくシルエットと言葉で見分けられる: 色を全部消した画面でも、形が違い名前も違う。
5. ゲームは音を鳴らさず、何も音を必要としない。スモークは何も再生されないことを確かめる。

### REQ-7.11 日本語と英語、文言はcontentに

1. 案内、メッセージ、品物の名前、ボタンのラベル、まとめの一言、タイトルのラベルとキャプションは、すべて `src/content/strings.ja.json` と `strings.en.json` に、同じキーで置く。子ども向けの文言のリテラルを `src/game/` や `src/domain/` に書かない。
2. 日本語は `npm run kid` でハードルール2に従う: ひらがなとカタカナだけ、1行12文字以内、2行以内。品物の名前を入れた後も同じ。英語のメッセージは短い2行以内。
3. 品物の名前を取るメッセージは、ちょうど1つ取り、置き換えられないプレースホルダーを残さない。
4. 言語は既存のもの（`?lang=ja|en`、なければブラウザの言語、なければ英語）。`SetLang` はいつでも言語を変えられ、言葉は変わるがほかは何も変わらない。
5. 文言を変えた後、`npm run kid` と `npm run font` が通り、サブセットフォントがすべての文字を含む。

### REQ-7.12 純粋なルールを、いくつもの方法で確かめる

1. どの品物が秘密か、品物の順番、決定、それが正しいか、得点、次のラウンド、時計、戻る道は、純粋なreducerのルール（ADR 0001）。`src/domain` はPhaser、DOM、時計、乱数を使わず、結果は言語にもアニメーションの時間にも依存しない。シードはイベントの項目: 同じシードと同じイベントなら、いつも同じ状態になる。
2. INV-46〜INV-53と、試練4についてのINV-15〜INV-17（下記）には、それぞれ実物のreducerに対する `checkProperty` のプロパティテストがあり、ジェネレーターは、両方の決定、2回決める、決める前と後の「つぎへ」、ほかの試練のイベント、時間切れ、もう一度、戻る、品物の表を一周、を行う。INV-3とINV-4も、新しいイベントを含む列で走る。
3. 単体テストは、次を扱う: 6つの品物とその種類、4つの順番とその折り返し、いくつかのシードで固定した品物、秘密と渡してよいものそれぞれへの正しい決定と間違った決定、2回目の決定、決める前の「つぎへ」、正しい決定と間違った決定の得点と連続（100, 150, 200, 250, 300）、時計、両方の段階での時間切れ、ベストを残した終了画面からのもう一度、各段階と終了画面からの戻る（それ以外では働かない）、タイトルからの入口。contentとviewでは: ja/enで同じキー、プレースホルダー、長さ、非難・恐怖・主張がないこと、まとめの一言が決定の後だけに出ること、ボタンが使えるときだけ出ること、80 pxのボタンに収まる「Title」の言葉、試練4の終了画面の2つのボタン、メッセージが決定に従うこと。
4. 実物のreducerに対するモデル検査（`shadows.model.test.ts`）は、2つのシードでのタイトルからの入口と、その後の試練4を、有限のアルファベットで扱う。アルファベットには、ほかの試練の無効なイベント、どの時点でも両方の決定、ランの途中と、ランを終わらせる `Tick`、`Start` と言語の変更を含む。状態が常に、子どもがしたことの独立した記録と等しいこと、渡した秘密が正しいと採点されないこと、時計が記録と合うこと、得点が連続の点数で正しい決定のときだけ動くことを確かめる。どの到達可能な状態からも、正しい決定、間違った決定、次のラウンド、2回目の正しい決定、終了画面、タイトルに行ける（時計と「Title」ボタンなしでも次のラウンドへ行ける）。状態数と、わざと壊したときの反例を記録し、通すために状態を捨てない。
5. ミューテーションテストは、単体テスト対象のコードに生き残りを出さない。

### REQ-7.13 本物のタップと本物の画面

1. モバイルのスモークは、タイトルから本物のタップ（`dispatch` ではない）で試練4に入り、次を遊ぶ: 渡してよい品物を渡す（得点、チェック、吹き出しの品物、まとめの一言）。秘密を残す（得点、南京錠、吹き出しの静かな点、まとめの一言）。秘密を渡す（得点なし、連続が途切れる、吹き出しの品物）。渡してよい品物を残す（得点なし、連続が途切れる、南京錠）。同じラウンドの2回目の押しが何も変えない。「つぎへ」で次の品物。時間切れで終了画面。「もう一度」でベストを残した次のラン。ランの途中と終了画面から「Title」でタイトルへ、素早い2回目のタップが試練1を始めない。`window.__game` は状態を読むためだけに使い、タップでできることをするためには使わない。`dispatch` は、ボタンのない `Tick` と `SetLang` にだけ使う。
2. スモークは、状態だけでなく画面を確かめる: チェックのバッジ、南京錠、吹き出しの中身、ボタン、時計、得点、メッセージ、まとめの一言をピクセルで見る。「渡した」と言いながら吹き出しが静かな状態は失敗する。
3. 最初の画面、渡してよい品物を渡した後、秘密を残した後、秘密を渡した後、終了画面の日本語と英語の画面、そして両言語のタイトルを、スクリーンショットで見る。デスクトップのスモークはマウスで shadows を遊び、ボタンへの押しっぱなしがヒーローを動かさないことを確かめる。初回読み込み後のオフラインでも、両方の言語で、全経路が動く。
4. 試練4は実時間で遊ぶので、各スモークテストはランの半分よりずっと短く遊ぶ。時計を超える必要のあるテストは、小屋や畑と同じく `Tick` でランを終える。試練1〜3のスモーク（スコアアタックを含む）は引き続き通る。タイトルの試練4のボタンはどれも始めず、タイトルのそれ以外の場所のタップは引き続き試練1を始める。

### REQ-7.14 ゲートは弱めない。確かめたことを言う

1. しきい値、設定、チェックスクリプト、ワークフロー、既存のテストを、通すために緩める・消す・弱めることはしない。このspecのせいで古い期待を変える必要がある場合は、`tasks.md` に古いテストと新しいテストを書き、試練1〜3が弱くならない理由を書く。
2. `npm run check` はすべてのタスクで通る。入力を画面につなぐタスクは、`npm run build` の後の `npm run smoke` も通る。
3. スモークの対象は、モバイルWebKitとデスクトップChromium。作業サンドボックスでWebKitが起動できないときは、モバイルのスモークがiPhone 13のタッチプロファイルのChromiumで動いたと結果に書き、数えるのはCIのWebKitの結果。CIのスモークが緑になるまで完了と呼ばない。Playwrightの実行を実機の確認とは呼ばない。実行していないテスト、フック、エージェントを実行したと報告せず、Result行には測ったことだけを書く。

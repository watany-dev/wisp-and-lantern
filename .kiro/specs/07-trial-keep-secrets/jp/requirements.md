## なぜ

`docs/learning-design.md` は、L4を「鍵・住所・パスワードは決して渡さない」、試練4を「The Listening Shadows: 渡してよいものだけを渡す。影 = 聞き耳を立てる第三者」としています。

子どもの前に5つのものがあります。ウィスプは受け取る用意ができていて、ウィスプのそばに影が2つ座り、聞いています。5つのうちいくつかは渡してよいもの（あめ、はな、どんぐり、はっぱ）です。1つか2つはひみつです: おうちのかぎ、じゅうしょ（ピンの立った家）、あいことば（文字の隠れたふきだし）。子どもはものをタップしてウィスプに渡します。渡してよいものは渡り、得点になります。ひみつは決して渡りません: ゲームがそれを手元に残し、それはひみつで、影が聞いているかもしれないとやさしく言い、子どもは続けます。渡してよいものを全部渡すと、ひみつはまだ子どもの手元にあり、しめくくりの一言がそう言い、次の5つが来ます。60秒の1回なので、考えずに全部をタップする子どもは連続を失い続け、ひみつを手元に残す子どものほうが高い得点になります。

影は「敵」ではありません。何もせず、何も取らず、近づいてもきません。「ほかのだれかが聞いているかもしれない」を表していて、それがひみつをひみつにしておく理由です（L4、「実際のAIエージェントでは」: 鍵・住所・パスワードは決して渡さない）。文言は、影が悪いとも、何か悪いことが起こるとも、子どもが悪いことをしたとも言いません。こわがらせて従わせることはしません（`docs/learning-design.md`、「教えないこと」）。

学習設計の行には、渡してよいものとして「家の鍵、名前、あめ」と書かれていました。これは鍵は決して渡さないというL4とも、この依頼（「家の鍵・住所・合言葉は絶対に渡さず、あめは渡してよい」）とも食い違います。この行はこのspecで直します（REQ-7.14.4。`design.md` の Decisions を参照）。名前はどちらのグループのものにも使いません。

## 用語

- **袋（Bag）**: 1ラウンドで子どもの前にある5つのものと、試練4での子どもの状態。コードは試練の状態を `bag` と呼びます。画面はものを5枚のカードとして見せます。
- **もの（Thing、item）**: 5枚のカードの1つ。どれも、渡してよいものか、ひみつ。ものは 0〜4 の番号で、上の列を左から右、次に下の列です。
- **渡してよいもの**: あめ、はな、どんぐり、はっぱ。ウィスプに渡してよい。
- **ひみつ**: おうちのかぎ、じゅうしょ、あいことば。決して渡らない。
- **渡す（Hand over）**: 子どもがものをタップすること。渡してよいものはウィスプに渡り、ひみつは渡らない。
- **手元に残す（Hold back）**: タップされたひみつに対してゲームがすること。ひみつは子どもの手元に残り、メッセージがその理由を言う。
- **影（Shadow）**: ウィスプのそばの、まるい目と大きな耳を持つやわらかい形2つ。聞いているかもしれないだれかを表す。タップの的ではなく、何かに近づくことも、何かを取ることもない。
- **ラウンド**: 1つの袋。5つの新しいものから、渡してよいものを全部渡すまで。ラウンドはシードから4つ順に来て、そのあと最初に戻る。
- **終わったラウンド（Done）**: 渡してよいものが全部渡されたラウンド。ひみつはまだ子どもの手元にある。
- **1回（run）、シード、連続、終了画面**: `06-trial-verify-stars` と同じ。60秒、袋を開くときにゲームが引く整数、続けて正しく渡した数、時計が0になったときの画面。
- **ルールカード**: ラウンド中、メッセージの下で3つのひみつを、それぞれ南京錠つきの絵で見せるパネル。まだ字を読めない子どものための案内。
- **しめくくりの一言**: ラウンドが終わるたびに、ルールカードの場所に出る短い文。子どもがしたことを振り返る: ひみつは手元に残り、渡してよいものだけを渡した。

## 要件

### REQ-7.1 タップで袋に入る

6歳の子どもとして、影の試練をタイトルから指で開きたい。大人がいなくても遊べるように。

1. タイトル画面に、試練4のための3つ目のタップの的を出す: 南京錠の絵、子どもの言語の短いラベル、「How many in 60 seconds?」の小さな説明を持つ、80 x 80 ゲームピクセル以上のボタン。野原のボタンの上、8ピクセル空けて置き、タイトルのウィスプ、主人公、試練1のカードに重ならない。野原と小屋のボタンは動かさない。タイトル名、試練1のカード、ウィスプ、主人公が上へ動いて場所を空ける。
2. ボタンをタップすると袋が開き、その1回が始まる。状態は `title` から `trial` に移り、`trial` は 4、新しいシードのラウンド0、60秒の満タンの時計、得点0、連続0。そのセッションのベスト得点は引き継ぐ。レーン、小屋、野原には触れない。シードはゲームが（ドメインの外で）引き、イベントにのせて送る。ドメインは何も引かない。
3. このボタンのタップで試練1、小屋、野原が始まることはなく、ほかのボタンのタップで袋が開くこともない。タイトルのほかの場所のタップは、これまでどおり試練1を始める。
4. 入口は、ふつうの画面でのふつうのタップ。審査員用URL、隠しジェスチャー、コンソール呼び出し、クエリパラメータではない。試練選択画面も汎用ルーターもない。

### REQ-7.2 袋の画面に出るもの

1. 袋の画面には、1回の上の列（残り秒、バー、得点）、案内、2列の5つのもの（上に3つ、下に2つ）、メッセージ、ルールカード（ラウンドが終わったあとは、しめくくりの一言）、ウィスプ、ウィスプのそばの影2つ、「タイトル」ボタンを出す。「つぎへ」ボタンはラウンドが終わったあとにだけ出る。
2. 案内は2行以内で、どの段階でも画面に残る。3つのひみつを名指しし、それはだれにも渡さないと言う。
3. ものはそれぞれ、絵と名前のカード。絵は色だけでなく輪郭で区別できる: あめ（両端がねじれたまるいあめ）、はな（まんなかのまわりの花びら）、どんぐり（帽子をかぶった実）、はっぱ（筋の入ったとがった楕円）、おうちのかぎ（持ち手に小さな家がついたかぎ）、じゅうしょ（ピンの立った家）、あいことば（隠れた文字の代わりに星が3つ入ったふきだし）。渡したものには枠とチェックがつく。ラウンドが終わると、ひみつには南京錠のバッジがつく。どちらも色だけでは伝えない。
4. ウィスプはどの段階でも、いつもの親しげな顔で画面にいる。怒った、ずるい、こわがった、傷ついた顔では描かない。ひみつを求めることもない。タップの的ではない。
5. 影2つはどの段階でも、ウィスプのそばで画面にいる。まるい目と大きな耳を持ち、歯も爪も怒った顔もない。子どもやものに向かって動かず、することに意味はない。タップの的ではない。

### REQ-7.3 渡してよいものだけを渡す

6歳の子どもとして、渡しても大丈夫なものをウィスプに渡したい。渡したものがわかり、得点になるように。

1. まだ子どもの手元にある渡してよいものをタップすると、それがウィスプに渡る: カードに枠とチェックがつき、メッセージはこれは渡して大丈夫だと言い、得点が入る（REQ-7.7.3）。変わるのはそのものだけ。
2. すでに渡したものをタップしても、ものでない場所をタップしても、何も変わらない。
3. ものはどの順番で渡してもよい。ものの結果は順番に左右されない。
4. タップの結果はリデューサーがすぐに決める。アニメーションやタイマーを待たない。短い演出（ものの絵がウィスプへ飛ぶ）は流れてよく、無視しても情報は失われない。

### REQ-7.4 ひみつは決して渡らない

6歳の子どもとして、ひみつをタップしたらゲームにやさしく教えてほしい。こわがらずに、ひみつを守ることを覚えられるように。

1. ひみつをタップしても、どの段階でも、何度タップしても、決して渡らない。ひみつが渡したものとして記録されることはなく、ひみつのせいでラウンドが終わることもない。
2. ひみつは元の場所に残る。メッセージはそのひみつの名前を言い、それはひみつだと言い、影が聞いているかもしれないと言う。言葉はわかりやすくやさしい: 「わるい」「ちがう」「だめ！」「あぶない」「ぬすむ」「どろぼう」「てき」「こわい」「うそ」はなし。子どももウィスプも影も責めず、何かが起こるとおどかさない。
3. 赤いものはなく、×も出さず、何も揺らさず、音もない。カードが一度だけ揺れ、影の耳が一度だけ動いてよい。どちらも意味は持たない。
4. ひみつのタップは時間も命も得点も失わない: 得点にならず連続が切れる（REQ-7.7.3）だけ。子どもはそれも、ほかのものも、何度でもタップできる。回数は数えない。
5. 文言は、助手がいつも間違うとも、いつも正しいとも、何でも知っているとも、友だちや家族だとも言わず、ほのめかさない。影が悪いとも、ひみつを守ればどんなことからも安全だとも言わない（`docs/learning-design.md`、「教えないこと」）。
6. ルールカードは、ラウンド中のどの段階でも、3つのひみつをそれぞれ南京錠つきの絵で見せる。字を読まなくても、どれが手元に残るものかが子どもにわかる。

### REQ-7.5 渡してよいものを全部渡すとラウンドが終わる

1. どのラウンドにも5つのものがある: ひみつが1つか2つ、残り（4つか3つ）は渡してよいもの。同じものは2度出ない。1回の最初のラウンドはひみつが1つ、2つ目は2つ。ラウンドにどのものがどこにあるかは、シードとラウンド番号だけから決まり（決まった規則。ほかの乱数なし）、ラウンドのあいだは変わらない。
2. 最後の渡してよいものを渡すと、ラウンドはすぐ終わる: メッセージが渡した数（3か4）を言い、どのひみつにも南京錠のバッジがつき、しめくくりの一言がルールカードの場所に出て、「つぎへ」ボタンが出る。
3. 終わったラウンドは、子どもが「つぎへ」をタップするまで画面に残る。1回の終わりのほかに、ひとりでに消すものはない。終わったラウンドではものを渡せない。
4. 「つぎへ」は次のラウンドを始める: 何も渡しておらず、シードの次のもの（偶数ラウンドはひみつ1つ、奇数ラウンドは2つ。表は4ラウンドで最初に戻る）。試練を終わらせるのは時計だけ。

### REQ-7.6 しめくくりの一言は振り返る

1. 終わったラウンドは、しめくくりの一言を独立した文として見せる。子どもがしたことを振り返る: ひみつは手元に残り、渡してよいものだけを渡した。文面は `design.md` にある。
2. ラウンドが終わるたびに、ルールカードの場所に出し、ラウンド中には出さない。メッセージにつなげない。もの、その印、ボタンは見えたままで、場所を空けるために文字を小さくしない。
3. このゲームで起きたことだけを言う。実際のAIがいつも聞いているとも、決して聞いていないとも、ここでひみつを守れば子どもが一般に安全だとも、AIが友だちや家族だとも言わない。
4. ひみつが画面で名指しされ、渡してよいものはどれもすぐ受け取られる理由（子どもが「かぎ、じゅうしょ、あいことばは手元に残す」を練習できるための演出で、実際のプライバシーがそれほど簡単だという主張ではない）を `design.md` に書く。

### REQ-7.7 60秒の1回、得点、戻る道

1. 袋は、試練1の `Run` を使う60秒の1回: 入口で満タンの時計、得点0、連続0、セッションのベストは引き継ぐ。時計は子どもが何をしていても減る。時間は `Tick`（1フレームは最大 250 ms と数える）でだけゲームに届き、`Tick` は袋でも試練1〜3と同じに働く。上の列は秒、バー、得点を見せる。
2. 試練を終わらせるのは時計だけ: 時間のあるかぎりラウンドが続く。
3. 得点。渡してよいものを渡すと、100点に、その前に続けて渡した数1つにつき50点を足す（4つまで）（100、150、200、250、300、300 ...）。ひみつのタップは得点にならず連続が切れる。「つぎへ」やほかのどのイベントも得点にならず、連続も変えない。得点はリデューサーがすぐに決める。渡したときは、点数（「+150」）がカードから一瞬浮かぶ。上の列がその記録。
4. 時間切れは、どの段階でもすぐ1回を終わらせる。終了画面は試練1のもの: 「おしまい！」、得点、ベスト、ベストを超えたら「しんきろく！」。ボタンは2つ: 「もういちど あそぶ」は袋の新しい1回（満タンの時計、得点0、新しいシードのラウンド0、ベストだけ保つ）を始め、もう1つは「タイトル」。これまでどおり、一瞬タップを受けない。
5. 「タイトル」ボタンは、袋の画面のどの段階にも（80 x 80、小屋のボタンと同じ場所）、その終了画面にも（横長）ある。タイトルへ戻る: `phase` は `title`、`trial` は 0、袋は初期状態、1回はベストだけ保って作り直す。ほかは何も変わらない（言語と主人公はそのまま）。
6. 袋から戻ったあと、タイトルは 0.7 秒タップを受けない。小屋と野原のあとと同じ。
7. 行き止まりなし: 袋のどの状態（進行中のラウンド、終わったラウンド、終了画面）からも、子どもは袋のボタンだけで、終わったラウンド、得点、終了画面、新しいラウンド、タイトルに行ける。時計と「タイトル」ボタンがなくても、袋のタップだけで先へ進める。

### REQ-7.8 試練どうしは切り離す

1. 袋に入っても、`lane`、`shed`、`field` はタイトルのときのまま。
2. 見せるシーンは `trial` に従う: 1 はレーン、2 は小屋、3 は野原、4 は袋。`trial` 4 の状態がほかの試練のシーンを見せることはない。
3. 試練4（1回の最中か、その終了画面）では、ほかの試練のイベント（`Ask`、`PickCard`、`Retry`、`PickTool`、`GiveTool`、`RetryShed`、`LeaveShed`、`InspectStar`、`SortStar`、`KeepStars`、`RetryField`、`LeaveField`）は同じ状態を返す。試練4の1回の外では、袋のイベント（`GiveItem`、`RetryBag`）は終了画面も含めて同じ状態を返す。`LeaveBag` は試練4（1回の最中かその終了画面）でだけ、`StartBag` はタイトルと袋自身の終了画面でだけ受け付ける。
4. 袋の1回の最中の `Start` は言語だけを変える。袋の終了画面では試練1を始め、袋の状態を捨てる。`SetLang` は言語だけを変える。`MoveHeroTo` は主人公だけを動かす。
5. どれがひみつかはシードとラウンドから導き、保存しない。子どもが渡したものは1つの値: ラウンド中は `given` の印、終わったら「渡してよいもの全部」。
6. 試練1〜3のふるまい、文言、テストは、このspecでは変わらない。タイトルのレイアウトだけは例外（「共通の入口やイベントへの変更」を参照）。

### REQ-7.9 縦向き、指1本、マウス

1. 袋は既存の 390 x 844 の縦向きキャンバスで遊ぶ。
2. どの操作も、80 x 80 ゲームピクセル以上の物への1回のタップかクリック: タイトルの袋のボタン、それぞれのもの、「つぎへ」、「タイトル」ボタン、終了画面の2つのボタン。ドラッグ、長押し、ダブルタップ、2本目の指、文字入力はない。
3. 主人公の床ドラッグは袋でも主人公を動かす。ものやボタンの上で始めた押下は主人公を動かさない。床の上の押下は動かす。
4. どの段階でも、上の列と「タイトル」ボタンがあっても、両方の言語で、名前や数を差し込んでも、文字と絵は重ならず、もの、メッセージ、ルールカード、しめくくりの一言、ボタンを隠さない。「つぎへ」ボタンは主人公の開始位置より上で終わる。
5. 「つぎへ」ボタンは、野原のボタンと同じく、出てから 450 ms 押下を受けない。

### REQ-7.10 コードで描く、ネットワークなし、色に頼らない、音なし

1. もの、バッジ、ルールカード、影、画面は、既存の見た目で、端末のピクセル比に合わせてコードで描く。画像ファイルは足さず、他者の絵も使わない（hard rule 5）。
2. ページと同梱フォントを読み込んだあと、袋は日本語でも英語でもネットワーク要求を必要としない（hard rule 4）。渡す、ひみつのタップ、終わったラウンド、「つぎへ」、戻る道までの全部がオフラインで動く。
3. 動きが唯一の意味を運ぶことはなく、1秒に3回より速く点滅せず、無視してよい。ものの状態（手元にある、渡した、守ったひみつ）はどれも、止まった絵で形によって伝える: チェック、南京錠のバッジ、名前。
4. ゲームは音を出さず、試練も音を必要としない。

### REQ-7.11 日本語と英語、文言は content に

1. 案内、メッセージ、ものの名前、ボタンのラベル、タイトルの袋のラベルと説明、しめくくりの一言は `src/content/strings.ja.json` と `strings.en.json` に、同じキーで置く。子ども向けの文字列を `src/game/` や `src/domain/` に直書きしない。
2. 日本語は `npm run kid` で hard rule 2 に従う: 漢字なし、ラテン文字なし、1行12文字以内、2行以内。ものの名前や数を差し込んだあとも。英語のメッセージは28文字以内の2行以内。
3. 名前や数をとるメッセージは、ちょうど1つをとり、置き換えていない差し込み記号を残さない。
4. 言語は既存のもの。`SetLang` はいつでも変えられ、言葉が変わるだけで、ほかは何も変わらない。
5. 文言を変えたあと `npm run kid` と `npm run font` が通り、サブセットフォントがすべての文字をふくむ。

### REQ-7.12 純粋な規則を、いくつもの方法で確かめる

1. ラウンド、渡す、手元に残す、得点、次のラウンド、時計、退出は、純粋なリデューサーの規則（ADR 0001）。`src/domain` は Phaser、DOM、時計、乱数を使わない。シードはイベントのフィールド: 同じシードと同じイベントは、いつも同じ状態になる。
2. INV-46〜INV-57 と、袋についての INV-15〜INV-17 は、それぞれ実際のリデューサーに対する `checkProperty` のプロパティテストを持つ。生成器は、渡してよいものとひみつの全部をタップし、渡したものをもう一度タップし、存在しない番号を使い、ラウンドを終わらせ、時計を切らし、もう一度遊び、退出し、終わったラウンドの前と後に次のラウンドへ進み、表をひとまわりする。INV-1〜INV-4 も新しいイベントを含む列で走らせる。
3. 単体テストの対象: いくつかのシードのものを固定（ひみつは1つか2つ、となりのラウンドは数がちがう、同じものは2度出ない）、渡してよいものを渡す、それぞれのひみつのタップ、ひみつを何度もタップ、すでに渡したもの、範囲外の番号、最後の渡してよいものでラウンドが終わる、終わったラウンドのロック、次のラウンドと折り返し、得点と連続（100、150、200、250、300）、時計、時間切れ、ベストを保ってもう一度、1回の最中と終了画面からの退出とそれ以外ではしないこと、タイトルからの入口。文言と view: 日英で同じキー、差し込み記号、長さ、責める言葉やこわがらせる言葉なし、主張なし、しめくくりの一言は終わったラウンドのあとだけ、「つぎへ」も終わったラウンドのあとだけ、メッセージは最後のタップに従う、バッジ、タイトルの言葉、終了画面のボタン。
4. 実際のリデューサーに対するモデル検査（`bag.model.test.ts`）は、タイトルから2つのシードでの入口とそのあとの袋を、ほかの試練のイベント、範囲外のもの、1回の半分と1回を終わらせる `Tick`、`Start`、言語の切り替えを含む有限のアルファベットで調べる。子どもがしたことの独立した記録に照らして、ひみつは決して渡らないこと、袋が記録と等しいこと、時計が一致すること、得点は渡してよいものを渡したときだけ連続の点だけ動くことを確かめる。どの到達可能な状態からも、終わったラウンド、得点、終了画面、新しいラウンド、タイトル、2つ目の終わったラウンドに行けること（時計と「タイトル」ボタンがなくても終わったラウンドに行けること）を確かめる。状態の数と、わざと壊したときの反例を記録する。
5. 単体テストされたコードで、生き残るミュータントはない。

### REQ-7.13 実際のタップと実際の画面

1. モバイルのスモークは、タイトルから実際のタップで袋に入り、遊ぶ: 渡してよいものを渡す（チェックが描かれ、得点が上がる）、ひみつのタップ（何も渡らず、得点は変わらず、連続が切れ、メッセージが変わる）をシードが見せるひみつの種類ごとに、渡してよいものを全部渡して南京錠のバッジ、しめくくりの一言、「つぎへ」の出た終わったラウンド、ひみつ2つの2つ目のラウンド、時間切れと終了画面、ベストを保った「もういちど あそぶ」、1回の最中と終了画面からの「タイトル」（すばやい2回目のタップで試練1が始まらないこと）。`window.__game` は状態を読む。`dispatch` は、ボタンのない `Tick` と `SetLang` にだけ使う。
2. スモークは状態だけでなく画面を確かめる: 渡したもののチェック、南京錠のバッジ、ルールカード、「つぎへ」ボタン、しめくくりの一言のパネルとその文字を、ピクセルから読む。
3. 始め、ひみつのタップ、終わったラウンド、終了画面の日本語と英語のスクリーンショットと、3つのボタンのあるタイトルを見る。デスクトップのスモークはマウスで袋を遊び、ものの上での長押しで主人公が動かないことを確かめる。最初の読み込みのあとオフラインでも、両方の言語で、全部の流れが動く。
4. 試練1〜3のスモークは、得点勝負とタイトルのテストを含めて、そのまま通る。タイトルの袋のボタンはそのどれも始めず、タイトルのほかの場所のタップはこれまでどおり試練1を始める。

### REQ-7.14 どのゲートも弱めず、確かめたことを言う

1. どのしきい値、設定、チェックスクリプト、ワークフロー、既存のテストも、通すためにゆるめたり、消したり、弱めたりしない。このspecのために古い期待を変えるところでは、`tasks.md` に古いテストと新しいテスト、試練1〜3が弱くならない理由を書く。
2. `npm run check` が通る。入力を画面につなぐタスクは `npm run build` に続けて `npm run smoke` も通す。
3. スモークはモバイル WebKit とデスクトップ Chromium を対象とする。作成用サンドボックスで WebKit が起動しない場合、結果には、モバイルのスモークを iPhone 13 のタッチ設定つき Chromium で走らせたと書き、CI の WebKit の実行を正とする。Playwright の実行を実機の確認とは呼ばない。走らせていないテスト、フック、エージェントを走らせたと報告せず、Result 行には測ったことだけを書く。
4. `docs/learning-design.md` の試練4の行は、作ったとおりの渡してよいものとひみつで、試練がすることを言う（渡してよいものに「家の鍵」を入れない）。

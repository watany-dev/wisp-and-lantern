# 設計: あいまいな頼みは違う物を連れてくる

> 和訳です。**正本は英語版** [`../design.md`](../design.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・ID・コード・文言（ja/en）は原文のままです。

[`requirements.md`](requirements.md)（REQ-3.n）を実現します。ADR 0001（純粋reducer）、ADR 0003（ゲート）、`.kiro/steering/structure.md` の配置ルールに従います。新しい依存、新しいアセット、新しいADRはありません。`02-trial-tell` の設計を、`requirements.md` の表が示す箇所だけ変え、他は変えません。

## 遊びの流れ

```text
choosing --PickCard--> choosing   (0, 1 or 2 cards)
choosing --Ask, >= 1 card--> result (right | wrong, with the item that was brought)
choosing --Ask, 0 cards--> choosing (same state; the message invites a card)
result   --Retry--> choosing      (same wish after wrong, next wish after right)
```

以前: `Ask` には2枚が必要でした。今: 1枚か2枚で足ります。1枚の依頼の結果が、あいまいな結果です。

## ドメイン（`src/domain/`）

### 状態: 変更なし

`Lane = { wish, pick, asked }` のままです。届いた物は**保存しません**。`pick` と `wish` から決まる関数だからです。保存すると、ずれるだけの状態のコピーになります（旧設計も「別の見つかった物は持たない」と同じ選択をしました）。また、INV-11〜INV-13 が、2つのフィールドの一致ではなく、1つの関数の作りで成り立つようになります。`Lane` のdocコメントは変わります。`asked` は「1枚以上のカードを選んでウィスプをタップした」を意味します。

### 関数（`lane.ts`）

```ts
export function hasPick(pick: Pick): boolean;                 // color !== null || thing !== null
export function canAsk(lane: Lane): boolean;                  // !lane.asked && hasPick(lane.pick)
export function deliver(pick: Pick, wish: Wish): Wish;        // the rule below
export function delivered(lane: Lane): Wish | null;           // lane.asked ? deliver(pick, wish) : null
export function outcome(lane: Lane): Outcome;                 // see below
```

`isComplete` は残ります。viewが、完全な依頼とあいまいな依頼を区別するのに使います。

`deliver` は全域関数です。起こり得ない場合のための分岐はありません。

```ts
const following = <T>(order: readonly T[], item: T): T =>
  order[(order.indexOf(item) + 1) % order.length]!;

deliver(pick, wish) = {
  color: pick.color ?? following(colors, wish.color),
  thing: pick.thing ?? following(things, wish.thing),
}
```

`outcome(lane)`: `delivered(lane)` が null なら `"choosing"`。そうでなければ、届いた物がねがいと等しいとき `"right"`、違えば `"wrong"`。あいまいな依頼は `"wrong"` です。ねがいと等しくなることはありません（REQ-3.3.5）。

選択が空のまま `asked` になる状態には到達できません（`Ask` は `hasPick` を要求します）。モデル検査が状態の不変条件としてこれを保ちます。到達できないその状態でも、`deliver` は同じルールで物を返します。

### ルール（REQ-3.3）

子どもが言ったことは守ります。言わなかったことは、ウィスプがねがいから補います。

- 足りない**物**は、`things`（かぼちゃ、ランタン。最後の次は最初）で、ねがいの物の次の物。
- 足りない**色**は、`colors`（赤、青、黄。最後の次は最初）で、ねがいの色の次の色。

届いた物は、子どもの言葉と合っていて、子どもが何も言わなかったところだけがねがいと違います。子どもには「色は合っているのに物が違う」、またはその逆が見え、直し方は足りない部分を言うことになります。2つの並びは、すでにドメインにある順番なので、新しい定数はありません。

色だけの依頼 `x` なら、物は `(x, 別の物)` で、ねがいの物だけで決まります。物だけの依頼 `y` なら `(次の色, y)` で、ねがいの色だけで決まります。

`balance.wishes` の3つのねがいについて、1枚ずつ選んだときに届く物（単体テストは、6通りのねがいすべてについて30行を、ルールで計算せず手で書きます）:

| ねがい | red only | blue only | yellow only | pumpkin only | lantern only |
|---|---|---|---|---|---|
| yellow lantern | red pumpkin | blue pumpkin | yellow pumpkin | red pumpkin | red lantern |
| red pumpkin | red lantern | blue lantern | yellow lantern | blue pumpkin | blue lantern |
| blue lantern | red pumpkin | blue pumpkin | yellow pumpkin | yellow pumpkin | yellow lantern |

2枚そろっていれば、その組み合わせそのものが届きます。yellow lantern のねがいに `red` + `lantern` なら、従来どおり red lantern です。

### これは演出のための仕掛けで、AIについての主張ではない

補い方を固定した目に見えるルールにしたのは、6歳の子がねがいと結果を見比べて、何が抜けたかを見られるようにするためです。現実のエージェントは「リストの次」で隙間を埋めません。推測することが多く、うまくいくこともあり、具体的な依頼でも失敗することがあります。この試練は、具体的な依頼なら必ずうまくいく、あいまいなら必ず外れる、とは言いません（`docs/learning-design.md` の「What we do not teach」）。「言わなかったから、ウィスプが決めたんだ」と感じられる1つの場面を見せるだけです。締めの一文は、起きたことだけを言います（REQ-3.5.6）。

### イベントとreducer

`reducer.ts` は変わりません。`Ask` は今までどおり「`canAsk` なら `asked = true`、でなければ同じ状態」で、`canAsk` の意味が変わります。`Retry`、`PickCard` などは変わりません。`nextWish` が進むのは `"right"` の後だけのままです。

### 不変条件

INV-5 は残ります。INV-6 と INV-7 は廃止、INV-8〜INV-14 が新規です（表は `requirements.md`）。新しい各不変条件は、他と同じイベント生成器（1枚の依頼が多く出るよう、選択に重みを付ける）で、`checkProperty` を使い `reducer.pbt.test.ts` にプロパティを持ちます。

| id | プロパティの確かめ方 |
|---|---|
| INV-8 | 任意の列の終わりで、選択が空または `asked` なら、`reduce(end, Ask)` は同じオブジェクト。 |
| INV-9 | 試練中の任意の列の終わりで、`hasPick` かつ `asked` でないなら、`reduce(end, Ask).lane.asked` は true。 |
| INV-10 | レーンを変えた `Ask` のどのステップでも、前後の差は `asked` だけで、`pick` は深く等しい。 |
| INV-11 | 任意の列の後、`asked` のとき、選んだ色は届いた色に、選んだ物は届いた物に等しい。 |
| INV-12 | 任意の列の後、1枚だけで `asked` のとき、届いた物はねがいと異なる。 |
| INV-13 | 任意の列の後、2枚で `asked` のとき、届いた物は選択と等しい。 |

各プロパティは、わざと壊したreducerまたはルールで失敗することを確かめてから残します（`tasks.md` に記録）。

### モデル検査（`reducer.model.test.ts`）

イベントの集合は変わりません。状態の不変条件が1か所変わります。「探索したら選択は完全」が「探索したら1枚以上ある」になります。実際のreducerに対する目標は次のとおりです。

1. すべての状態から正解に到達できる（維持）。
2. すべての状態から「選ぶ」に到達できる（維持）。
3. すべての状態から、**色だけ**の依頼の結果に到達できる。
4. すべての状態から、**物だけ**の依頼の結果に到達できる。

到達する状態数は220から280に変わります。タイトル4状態、続いて、2言語 x ヒーロー位置2 x ねがい3 x レーンの23状態（依頼前の選択12（色の選択肢4 x 物の選択肢3）、依頼後の空でない選択11）。テストはこの数を確かめます。

新しい目標が旧ルールでも通るなら、空の検査になってしまいます。そこで、同じ集合で旧ルール（2枚そろっていない `Ask` は無視）をラッパーのstepに戻した場合を1ケース走らせ、目標3と4が `stuck` を報告することを確かめ、その反例を `tasks.md` に記録します。

## 内容（`src/content/`）

`cards.json` は変わりません。`lane` の文言は次のとおり変わります。`{0}` は物名で、数字なのは、日本語に英字を禁じるゲートがあるためです。

| key | ja | en | 変更 |
|---|---|---|---|
| `lane.wish` | ほしいのは これ | I want this one | 維持 |
| `lane.pickAny` | カードを えらんでね | Pick a card | 新規。`pickBoth`、`pickColor`、`pickThing` を置き換える |
| `lane.ready` | ウィスプを タップして⏎たのもう | Tap the wisp to ask it | 維持。1枚でも2枚でも使う |
| `lane.right` | {0}が⏎ぴったり みつかった | Found the {0}! Just right | 維持 |
| `lane.wrong` | {0}を⏎もってきたよ | The wisp brought the {0}, just as you asked | 維持。完全な依頼で別の物 |
| `lane.vague` | {0}を⏎もってきたよ | The wisp brought the {0} | 新規。1枚の依頼 |
| `lane.lesson` | いろと ものを つたえて⏎ぴったり みつかったね | You told it⏎color & item | 新規。締めの一文 |
| `lane.again` | もういちど あそぶ | Play again | 維持 |
| `retry` | もういちど つたえてみよう | Let's tell it again | 維持 |

（⏎ は改行です。）理由:

- `pickAny` は、どの1枚が足りないかを言う3つのキーを置き換えます。それらが「両方必要」と教えるメッセージでした。1枚のときは `ready` が代わります。ウィスプをタップするという1つの動作だけを言い、2枚目には触れません（REQ-3.1.7）。
- `vague` を別のキーにしたのは、ウィスプが物を決めたのに「just as you asked」と言うのは正直でないからです。日本語は `wrong` と同じです。物名を入れると、2行に余地がありません（1行目は物名で最大8文字、2行目は12文字）。ねがいとの見比べとやり直しボタンが意味を運びます。
- `lesson` は、依頼者の案を調整したものです。日本語は案のままで、各行10文字です。英語の案は `Color & item / Just right!` でしたが、見つかったメッセージがすでに「Just right」で終わるので、1つの画面で重なってしまいます。`You told it / color & item` は、子どもがしたことを言い、日本語の「つたえて」と対応し、1行12文字に収まります。
- kid-readerの読み（`.kiro/agents/kid-reader.md` の観点を、タスク4.1で手作業で当てはめる。このセッションからエージェントそのものは実行できない）: `つたえて` はすでにやり直しボタンにあり、`ぴったり` は見つかったメッセージにあり、`カード` は子どもが触っている物の名前。語は句の切れ目で区切られ、どの行も語を割らない。1行に1つの考え。責めない。AIについての主張はない。

`scripts/check-kid-strings.mjs` が検査するのは日本語のテンプレートだけです。contentテストは、物名を取るすべてのメッセージを、日本語の6つの物名すべてで描画して規則を当てます。また、各キーのプレースホルダーの集合が両言語で同じことも確かめます。

### スモークが文字を見る方法

文字はキャンバスに描かれるので、DOMにそのコピーはありません。ゲーム状態が「正解」でも、締めの一文が出ていなくてもテストが通ってしまいます。そこでスモークは、締めの一文の領域のスクリーンショットを撮り、そこにある明るい文字のピクセルを数えます。正解では多く、違う結果ではゼロで、日本語と英語では違うパターンになります。PNGのデコードは `node:zlib` で行います（新しい依存はありません）。ページ全体のスクリーンショットも残し、目で見ます。

## 決定事項と代案

- **届く物は導く。** 代案: `Lane` に保存する。却下: 状態の重複。モデル検査と INV-11〜INV-13 が、2つのフィールドの一致を証明しなければならなくなる。
- **固定の先頭ではなく、ねがいから補う。** 「最初の物は かぼちゃ」と固定すると、ねがいがかぼちゃのとき、あいまいな依頼がねがいを届けてしまう。要件は、どのねがい・どの1枚でも違う物が届くこと。
- **両方の属性に「順番の次」というルール1つ。** 代案: コイン投げ、または一致するものを全部光らせる。前者は乱数、後者は新しい表示が要り、後者はどれが届いたかも分からなくする。
- **別の `vague` キー。** 代案: `wrong` を再利用する。英語の正直さのために却下（内容の節を参照）。
- **ウィスプが空けた領域に、締めの一文を別の文字とパネルで置く。** 代案: 見つかったメッセージにつなげる（4行になり、依頼で禁止）。ねがいの行を置き換える（目標を隠す）。文字を小さくする（禁止）。後のプレイテストで、少し間を置いて出したくなるかもしれないが、それにはタイマーが要り、範囲外。
- **`pickAny` は「Pick a card」。** どの種類かは言わない。1つの種類を名指すと、また順番を教えてしまうから。

## リスク

- WebKit は作成用サンドボックスで起動しません（システムライブラリ不足。`docs/evidence/didnt-work.md`）。モバイルのスモークはそこではiPhone 13のタッチプロファイルのChromiumで走らせ、そう明記します。本物のWebKitの実行はCIのものです。CIのスモークが緑になるまで、変更は完了としません。
- ピクセル検査はメッセージの文字色を探します。その色は `src/game/ui/text.ts` の `textStyle`（Phaserの型importだけを持つモジュール）から読むので、そこで色を変えれば、検査が黙って壊れるのではなく、検査も一緒に動きます。
- 実際の子どもは「Pick a card」を「どれか1枚」と読み、両方を言うことを学ばないかもしれません。次のプレイテストでは、子どもが最初に1枚で試すか、あいまいな結果の後に何と言うかを記録します。

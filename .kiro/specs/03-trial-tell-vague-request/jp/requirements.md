# 要件: 試練1、あいまいな頼みは違う物を連れてくる

> 和訳です。**正本は英語版** [`../requirements.md`](../requirements.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・要件ID（`REQ-3.n`）・不変条件ID（`INV-n`）は原文のままです。

spec `03-trial-tell-vague-request`。`02-trial-tell` が作り、すでに公開されている試練1（The Dark Lane）への小さな改修です。学習目標 L1（`docs/learning-design.md`）を、プレイが求めた形で教えます。あいまいに頼むと違う物が届き、色と物を伝えると欲しい物が見つかる、という体験です。要件IDは `REQ-3.n` です。`REQ-2.n` は `02-trial-tell`、`REQ-1.n` は存在しない `01-core-loop` のもので、再利用しません。

作り直しではありません。試練1は公開済みで遊べます。この spec が名指ししないことは、`02-trial-tell` の仕様どおりに動き続けます。

## 背景（2026-11-09 の公開ビルドのプレイ）

- 色だけ、または物だけを選んでウィスプをタップしても、探索せず、メッセージが「ものを えらんでね」などに変わるだけでした。子どもはあいまいな依頼で何が届くかを見られません。「助手は言ったことしか知らない」ではなく、「両方選ぶのがルール」と学んでしまいます。
- 具体的だが目標と違う物を頼む場合はうまくいっています。頼んだ物が届き、メッセージが物名を言い、子どもは目標と見比べて、責められずにやり直せます。これは残します。
- 成功メッセージは物名を言います。これも残します。ただ、なぜ見つかったのかは、まだ何も伝えていません。

`02-trial-tell` は「カードが足りないのは探索ではない」を意図的に選びました（REQ-2.4）。この spec は、上の所見に基づいてその選択を変えます。旧specは、この spec への参照を付けて、書いたまま残します。

## 用語

`02-trial-tell` の用語（ねがい、色カード、物カード、選択、依頼、レーン、結果）は同じ意味です。新規・変更:

- **依頼（request）**: 依頼の瞬間の選択。2枚そろっていれば**完全**、ちょうど1枚なら**あいまい**。
- **届いた物（brought item、delivered item）**: ウィスプが光らせ、飛んでいくレーンの物。依頼とねがいから決まる関数で、保存はしない。
- **締めの一文（closing line）**: 正解の画面で、子どもがしたことを振り返る短い文。

## 要件

### REQ-3.1 1枚でも頼める

6歳の私が、色だけ、または物だけでウィスプを送り出して、あいまいな依頼で何が届くかを見られるようにします。

1. 1枚以上のカードを選んでいて、結果が表示されていないとき、子どもは依頼できる。ウィスプをタップすると探索が始まる。
2. 色カード1枚だけでも、物カード1枚だけでも足りる。
3. カードを選ぶだけでは探索を始めない（REQ-2.2.5 のまま）。
4. 結果表示中のウィスプのタップは何も変えない。
5. ウィスプを送れるとき（1枚以上選択、結果なし）は、依頼のリングを出す。カードなし、または結果表示中はリングを出さない。
6. ウィスプが薄くなるのは、カードを1枚も選んでいなくて送れないときだけ。
7. 選んでいる間、ウィスプを送るのに2枚目が必要だと言ったり、そう思わせたりするメッセージは出さない。1枚でも2枚でも、メッセージはウィスプをタップするよう伝える。

### REQ-3.2 カードなしは依頼ではない

1. カードを1枚も選んでいないとき、ウィスプをタップしても探索は始まらず、状態は変わらない。
2. そのとき、メッセージは子どもにやさしくカードを選ぶよう誘う。
3. 赤色の表示、バツ印、音、揺れは使わない。

### REQ-3.3 ウィスプが届ける物

1. 届く物は、いつも6つのレーンの物のどれか。
2. 2枚そろった依頼では、ねがいかどうかによらず、その組み合わせそのものを届ける。完全な依頼をねがいに寄せて直すことはしない。
3. 色だけを選んだとき、その色に、ねがいの物の**次**の物（物の順は かぼちゃ、ランタン。最後の次は最初）を組み合わせて届ける。つまり、ねがいとは違う物になる。
4. 物だけを選んだとき、その物に、ねがいの色の**次**の色（色の順は 赤、青、黄。最後の次は最初）を組み合わせて届ける。つまり、ねがいとは違う色になる。
5. 3 と 4 により、あいまいな依頼は、どのねがい・どの1枚でも、ねがいを届けない。ねがいが「あかい かぼちゃ」なら、あかいだけ→あかいランタン、かぼちゃだけ→あおいかぼちゃ。
6. 依頼と届いた物は分けて扱う。探索は選択を変えず、選ばなかったカードを選択済みにしない。物の絵、光るマス、ウィスプの飛行先、結果（正解かどうか）、メッセージは、すべて届いた物を使う。
7. 届いた物は、依頼とねがいだけで決まる。言語、時刻、乱数、描画のタイミングには依存しない。同じ状態と同じイベントからは、いつも同じ結果になる。
8. ルールと、すべてのねがいの表を `design.md` に書く。あわせて、これが現実のAIについての主張ではない理由も書く。

### REQ-3.4 見比べて、責められずにやり直す

1. どの探索の後も、メッセージは子どもの言語で届いた物の名前を言い、ねがいは画面に残る。
2. あいまいな依頼のメッセージも、完全な依頼のメッセージと同じく、責める言葉（まちがい、だめ、いいえ、しっぱい、wrong、bad、no、failed など）、赤色、バツ印、脅し、ペナルティを使わない。
3. 「もういちど つたえてみよう」は、同じねがい・空の選択・結果なしの「選ぶ」状態に戻す。何回でも使え、何も減らない。
4. 結果表示中は、カードを変えられない（REQ-2.2.4 のまま）。
5. あいまいな結果や違う結果とやり直しを何回繰り返した後でも、ねがいの色とねがいの物を選んで頼めば、必ずねがいが見つかる。
6. 正解の後は、従来どおり「もういちど あそぶ」で次のねがいへ進む（REQ-2.6.3）。

### REQ-3.5 正解がレッスンを締める

1. 正解の画面は、物名入りの見つかったメッセージと星を残したまま、子どもがしたことを振り返る締めの一文も出す。ウィスプに色と物を伝えたから、ぴったり見つかった、という内容。
2. 締めの一文は正解のときだけ出す。選んでいる間、あいまいな結果、違う結果では出さない。
3. 子どもがボタンをタップするまで消えない。タイマーで消さない。
4. 見つかったメッセージとは別の文字で、つなげない。ねがい、結果、カード、ボタンは見えたまま。場所を作るために文字を小さくしない。
5. 文言（`kid-reader` エージェントの読み方で確認。`design.md` を参照）:
   - ja: `いろと ものを つたえて` / `ぴったり みつかったね`
   - en: `You told it` / `color & item`
6. この文は、この試練で起きたことだけを言う。現実のAIが、具体的に頼めば必ず正しい、あいまいなら必ず外れる、何でも知っている、友達や家族である、とは言わない（`docs/learning-design.md` の「What we do not teach」）。L2〜L4については何も足さない。

### REQ-3.6 文言は `src/content` に置く

1. 案内・結果・締めの文言は、すべて `src/content/strings.ja.json` と `strings.en.json` に、同じキーで置く。子ども向けの文言リテラルは `src/game/` にも `src/domain/` にも現れない。
2. 日本語はhard rule 2（ひらがなとカタカナだけ、1行12文字以内、2行以内）に従う。物名を差し込んだ後も同じ。
3. 英語は短くする。メッセージは1つにつき2行以内、締めの一文は1行12文字以内。
4. 置換されないプレースホルダーを残さない。物名を取るメッセージは、物名をちょうど1つ取る。
5. `npm run kid` と `npm run font` が通り、サブセットフォントがすべての文字を含む。

### REQ-3.7 壊してはいけないこと

1. 試練は390 x 844の縦長キャンバスで遊ぶ。すべての操作は、ゲーム座標で80 x 80以上のオブジェクトへの1回のタップまたはクリック。
2. カード、ウィスプ、ボタンの上から始めた押下ではヒーローは動かない。床の押下は従来どおりヒーローを動かす。
3. 色だけを手がかりにしない。形・模様・ラベルは残る（REQ-2.10）。
4. 初回ロード後、日本語でも英語でも、この試練にネットワークは要らない。
5. 新しいカード種類も新しい依存も作らない。

### REQ-3.8 純粋なルールを、いくつもの方法で検査する

1. ルールは純粋なreducerにある（ADR 0001）。`src/domain` はPhaser、DOM、時計、乱数を使わない。
2. INV-8〜INV-14 は、それぞれ実際のreducerに対する、`checkProperty` を使ったプロパティテストを持つ。他の不変条件は残り、通り続ける。
3. 実際のreducerに対するモデル検査で、次を確認する。色だけの依頼の結果と、物だけの依頼の結果に到達できること。そこからやり直せること。正解にすべての状態から到達できること。到達した状態数を記録し、1枚の依頼を無効にしたときの反例も記録する。
4. 単体テストは、カードなし・色だけ・物だけ・両方を、すべてのねがい・すべての色・すべての物について確認する。届く物、その決定性、ねがいとの違い、従来どおりの「具体的だが違う依頼」、結果表示中のロック、やり直し、締めの一文とその言語切替、すべての物名を入れたときのメッセージの長さ。
5. モバイルのスモークは、実タップで2つの道筋を遊ぶ。色だけ→ウィスプ→別の物（物名つき）→やり直し→色と物→見つかった＋締めの一文。物だけでも同じ。デスクトップのスモークはマウスで同じことをする。日英のスクリーンショットで両言語を見る。オフラインの通しも引き続き完走する。

### REQ-3.9 どのゲートも弱めない

1. しきい値・設定・checkスクリプト・ワークフローを緩めない。この spec が置き換える旧挙動のテスト（REQ-2.3.1、REQ-2.4.1、REQ-2.4.2、REQ-2.5.1、INV-6、INV-7）を除き、既存のテストを、通すために消したり緩めたりしない。置き換えた各テストは、新しい対応テストとともに `tasks.md` に挙げ、新しいテストが旧挙動で失敗することを確かめる。
2. `npm run check` が通り、`npm run build` に続くスモークが通る。作成用サンドボックスで動かせないブラウザがあるときは、結果にそう書き、CIの実行を正とする。

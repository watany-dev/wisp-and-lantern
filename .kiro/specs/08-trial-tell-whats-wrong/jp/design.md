> 和訳です。**正本は英語版** [`../design.md`](../design.md) です。英語版を変えたら、同じPRでこのファイルも直します。識別子・パス・コマンド・要件ID・不変条件IDは原文のままです。

`requirements.md`（REQ-8.n）を実装します。ADR 0001（純粋な reducer）、ADR 0003（ゲート）、`.kiro/steering/structure.md` の配置の規則に従います。新しい依存、新しいアセット、新しい ADR はありません。reducer は純粋なまま、シーンは薄いままで、ADR 0001 と 0003 が言っているとおりです。モジュールの配置は試練4（`07-trial-keep-secrets`）をなぞるので、影を知っているレビュアーはランタンも分かります。

試練4と同じく、試練5は最初から60秒のスコアアタックです。試練1の `Run`（時計、得点、連続、ベスト）、試練1の終了画面、どの段階にもある小屋の「タイトル」ボタン。新しいのは2段階の指示です。試練1〜4では1回のタップ（またはカードの組）が頼みごとのすべてでした。ここでは子どもはまず**どこ**（チカチカする部分のタップ）を言い、次に**どう**（その部分のカード）を言い、ウィスプは言われたところだけを変えます。

## 子どもがすること

英語版の状態遷移図のとおりです。要点：

- タイトルでランタンのボタン（ゲームがシードを引く）→ 見ている、ラウンド0
- 見ている → チカチカする部分の `TapPart` → 指さしている（2枚のカードが開く）
- 見ている、または指さしている → しずかな部分の `TapPart` → 見ている（「そこは だいじょうぶ」の記し。カードは閉じる）
- 指さしている → チカチカする部分の `TapPart` → 指さしている（等しい状態）
- 指さしている → 正しいカードの `FixPart` → 灯った
- 指さしている → 違うカードの `FixPart` → 見ている（部分は変わってまだチカチカ、「〜って いったね」の記し）
- 指さしている → 2枚のカードにない見た目の `FixPart` → 同じ状態
- 灯った → `TapPart` / `FixPart` → 同じ状態。`NextLantern` → 次のラウンドを見ている
- どこでも → 時計が0になる `Tick` → 終了画面（試練5はそのまま残る）
- 終了画面 → `StartLantern` → 新しいランのラウンド0。ランか終了画面 → `LeaveLantern` → タイトル

意味のある `FixPart` は得点も動かします。正しいカードは100に連続1つにつき50（4まで）を足し、違うカードは連続を途切れさせます。指さしは得点になりません。タイトルのほかの場所のタップは今までどおり試練1を始めます。

## domain（`src/domain/lantern.ts`）

### 部分と見た目

`parts` は上から `handle`、`roof`、`light`。`looksOf[part]` は各部分の3つの見た目を決まった順で返します。とっては `ring`、`bow`、`bell`、やねは `pointy`、`round`、`flat`、あかりは `candle`、`star`、`moon`。`Shape` は部分ごとの見た目です。9つの見た目のIDはすべて違うので、ほかの部分の見た目の `FixPart` は見分けて無視できます（REQ-8.5.1、INV-57）。

### 状態

型は英語版のとおりです（`Note` と `Lantern` の3つの段階 `looking`、`pointing`、`lit`）。`trial` が 5 でないとき `GameState.lantern` は `initialLantern` です（INV-60）。おねがい、fault の部分、ウィスプが持ってきたランタンは保存しません。`wishAt`、`faultAt`、`broughtAt` が `seed` と `round` から導きます。`shape` は今のランタンで、違うカードが fault の部分を変えるまでは持ってきたランタンです。灯ったランタンは shape を持たず、おねがいそのものです（`shapeOf`）。`flickerOf` はチカチカする部分（`shape` がおねがいと違う1つの部分）を、`cardsOf` は2枚のカード（指さした部分の、今の見た目以外の見た目）を導きます。カードが正しいかは `fixRight(lantern, look)` で、`true`、`false`、または直す指示でないとき（指さしていない、2枚のカードにない見た目）は `null`。reducer はこれで得点をつけます。試練4の `decisionRight` と同じです。

### ラウンド：3進数のシード

シードを3進数の桁として読みます（`digit(seed, n)` は n 桁目）。ラウンド `r` では：

- おねがいのとっては見た目 `(桁0 + r) mod 3`、やねは `(桁1 + 2r) mod 3`、あかりは `(桁2 + r) mod 3`。どの部分の見た目も毎ラウンド変わり、おねがいは直前と同じにならない（REQ-8.8.2）。
- fault の部分は部分 `(桁3 + r) mod 3`。毎ラウンド動き、3ラウンドごとにどの部分も1回ずつ fault になる（REQ-8.8.3）。
- fault の部分に持ってくる見た目は、おねがいの見た目に1か2を足して mod 3。カードは部分の今の見た目の次から並ぶ（`now + 1`、`now + 2`）ので、2なら正しいカードが左、1なら右。足す数は、手で書いた6ラウンドの2つの周期（左右で `LRRLLR` と `RLLRLR`）から来る。桁4の偶奇が周期を選び、`floor(seed / 3^5) mod 6` がどこから始めるかを選ぶ。どちらの周期も単純な交互にならず、一回りを含めて同じ側を3回続けない（REQ-8.8.4）。

全体の模様は6ラウンドで一回りします。単体テストはシード0〜3、27、81、242、243、2^32 - 1 の最初のラウンドを固定し、100個のシードについて12または24ラウンドで規則を確かめ、正しいカードがどの6ラウンドでも左右両方に出て、同じ側に3回続かないことを確かめます。

### イベント（`events.ts`）と reducer

`LanternEvent = TapPart { part } | FixPart { look } | NextLantern` と、ほかの試練と同じ2つの上位イベント `StartLantern { seed }` と `LeaveLantern`。名前は独自なので、試練1〜4のイベントが試練5に、試練5のイベントがほかの試練に作用することはありません（INV-60）。

`reduceLantern(lantern, event)` は何も変わらないときランタンそのものを返します。

- `lit` での `TapPart` はランタンを返す。チカチカする部分では、その部分を指さす `pointing`。しずかな部分では、`fine` の記しの `looking`。
- `FixPart` は `fixRight` に聞く。`null` ならランタンを返す。`true` なら `lit`。`false` なら、指さした部分を送られた見た目にし、`said` の記しの `looking`。
- `lit` での `NextLantern` はラウンド+1（`broughtAt(seed, round + 1)` を見ている `looking`、記しなし）。それ以外ではランタン。

`reducer.ts` には `startLantern`、`leaveLantern`、`fix` が増えます。`Tick` は試練5でも働き（試練の一覧が1つ増える）、`start` は `lantern` も捨てます。試練のイベントは `reduceLaterTrial` を通り、影とランタンのイベントを振り分けるので、どの関数も複雑さの上限を超えません。

INV-54〜INV-62（`requirements.md` を参照）は、それぞれ `lantern.pbt.test.ts` にプロパティテストを持ちます。このファイルは新しいイベントを含む列で INV-1〜INV-4 と INV-15〜INV-17 も走らせます。`.kiro/steering/domain-invariants.md` に行と範囲の注記があります。

### モデル検査（`lantern.model.test.ts`）

実際の reducer を、子どもがしたことの独立な記録で包みます。`said`（このラウンドで意味のあった最後のカードの見た目）、`rightSaid`（このラウンドで正しいカードを選んだか）、`lits`（これまでに灯ったランタンの数。2 は「2以上」）、`scoreOk`（動くべきでないときに得点が動いた最初の一歩から false）。アルファベットは、2つのシード、3つの部分それぞれへの指さし、9つの見た目それぞれのカード、`NextLantern`、帰り道、両方の言語、2つの主人公の位置、短い `Tick` とランを終える `Tick`、ラン中の `Start`、ここでは何もしてはいけない試練1〜4のイベントです。状態の同一性は終わりなく増える得点とラウンドを追いません。得点は「なし／あり」、時計は「満タン／進行中／0」、ラウンドは6で割った余り（ラウンドの周期）です。状態は4,996で、ファイル全体は約3秒で走ります。

不変条件：フェーズ、試練、`lantern` が合う。試練5の外では `lantern` は初期値。ほかの試練は触れられない。時計は0〜60秒で、ちょうど0のとき終了。灯るまでランタンはちょうどそのラウンドの fault の部分でおねがいと違う。違うカードのあと、fault の部分は子どもが言った見た目。このラウンドで正しいカードを選んだあとでだけ灯る。得点は正しいカードでだけ、連続に応じた点だけ動く。ゴール（どの状態からも）：チカチカする部分の指さし、違うカード、しずかな部分の「だいじょうぶ」、灯ったランタン、タイトル、終了画面。時計も帰り道もなしで：灯ったランタン、次のラウンド、2つ目の灯ったランタン。わざと壊した8つ（違うカードでも灯る、カードで持ってきたランタンからやり直す、違うカードがほかの部分も変える、しずかな部分の指さしでカードが開く、`NextLantern` を無視する、試練5で `Tick` が時計を進めない、`LeaveLantern` を無視する、違うカードでも得点が入る）は、それぞれ気づくはずの検査で最短の手順とともに失敗します。「しずかな部分の指さしでカードが開く」はすべての部分を変えられるようにするので、壊したゲームは検査器の100,000状態を超えます。そのためこの1つは試練5自身のイベント（シード、指さし、カード、`NextLantern`）だけで走らせます。

`strings.ja.json` と `strings.en.json` に `lantern` グループを、同じキーを同じ順で置きます。`enter`、`timeAttack`、`guide`、`wish`、`brought`、`look`、`point`、`fine`、`said`、`lit`、`next`、`parts`（3語）、`looks`（9語）。`point` と `fine` は部分の言葉（`{0}`）を、`said` と `lit` は見た目の言葉をとります。

日本語の見た目の言葉は `said` と `lit` でかぎかっこ（`「{0}」`）に入れ、1〜2文字の言葉（ほし、すず）でも子どもが言った言葉として読めるようにします。kid-reader の基準（`.kiro/agents/kid-reader.md`）は手で当てました。日本語の各行は12文字以内で文節の間に空白があり、各文は1つのことを言い、日英は同じことを言い、どの文もウィスプも子どもも責めません。違うカードも、正しいカードと同じ落ち着いた口調で伝えます。

`lantern-content.test.ts` は、キーと順、`{0}` があるべき場所に1つだけあること、すべての部分と見た目の言葉を入れたうえでの日本語の規則と英語の長さ（1行26文字）、ボタンの言葉の長さ、言葉が規則どおりのことを言うこと（タップ、どの、いったね、まだ チカチカ、そこだけ、なおった）、両言語の非難・こわがらせ・主張の言葉の一覧を確かめます。非難の一覧は試練4のものから `ちがう` を除いたものです。ここでは学びの言葉で、`look` にだけ許し、ほかの文が使わないことをテストが確かめます。

### スモークが絵を見る方法

ランタンはキャンバスに描かれるので DOM に写しはなく、「灯った」と言う状態はあかりが暗いままでも通ってしまいます。スモークはスクリーンショットから点（`lantern-layout.ts` のプローブ）を読み、それぞれをグレースケール画面と同じ重みで明るさに変えるので、グレースケールの画面でも同じに読めます。

| 読むもの | 方法 |
|---|---|
| 部分の枠 | 枠の道筋の上辺の2点。1つは点の上、1つは次の点との中間。それぞれ130より明るいか。両方暗いと「なし」、点が明るく間が暗いと「点」、両方明るいと「線」 |
| チェックのバッジ | バッジの円の中、パネルの上の1点。バッジがなければ空になる。130より明るいとあり |
| あかり | ガラスの中で、あかりの絵から離れた1点。灯ると150より明るい |
| メッセージ | ほかの試練のスモークと同じく、枠の中の明るい文字のピクセル |
| ボタン | 畑と影のスモークと同じく、各位置の金色の面 |
| 部分の絵 | チカチカしていないとき（指さし中、灯ったとき）の部分の四角形の指紋を、直す前とあとで比べる |

「音なし」は試練3と4と同じく、ページの読み込み前に `AudioContext.createOscillator`、`createBufferSource`、`HTMLMediaElement.play` を包み、どれも呼ばれないことを求めて確かめます。読み取った値は1つずつ記録していません。どのしきい値も、金色の印（約200）と暗いパネルや空（60未満）の間にあり、グレースケールのテストは色をすべて取り除いたうえで同じ枠、バッジ、あかりを読みます。

## 判断と代わりの案

- **L5 は「どこが ちがうか つたえる」で、学習設計に5つ目の目標が増える。** `docs/learning-design.md` は L1〜L4 だけで、試練5は「TBD」でした。ユーザーが L5 を選びました。学習目標の表に行が増えます（子どもの言葉 "Tell it what's wrong"、概念 "Feedback: say where and how"、本物のエージェントでは「結果がほぼ正しいとき、最初から頼み直すのではなく、どこをどう変えるかを言う」）。`.kiro/steering/product.md` は「L1 to L5」になります。日本語の子どもの言葉（どこが ちがうか つたえる）は spec の中だけに書きます。学習設計は英語だからです（ハードルール1）。
- **チカチカが「どこ」を、おねがいが「どう」を示す。** ゲームは違う部分に印をつけ（チカチカと点の枠）、どの見た目が正しいかは言いません。代わりの案：印なしで子どもが違う部分を探す（「まちがいさがし」になり、学びは見ることになって試練3と重なる）、印と正しい見た目のヒント（見比べる必要がなくなり、子どもが担う「どう」の半分が消える）。指さしにも意味があります。「どこ」を言う行為であり、カードはその部分のためだけに出ます。
- **カードは3枚ではなく2枚。** カードはその部分の今の見た目以外の見た目です。「今のままにして」というカードは何も変えず、6歳の子にはこわれたボタンに見えます。代わりに、当てずっぽうでも半分は当たります。それには連続で応えます（下）。
- **違うカードは部分を変える。** ウィスプは言われたとおりにします（試練1からのゲームの第一の決まり）。なので違うカードは部分を子どもが言った見た目に変え、おねがいではないのでまだチカチカします。代わりの案：違うカードでは何も変わらない（ウィスプが指示を判定することになり、学びと逆）、違うカードで新しいランタンが来る（最初からやり直しで、学びが置き換えるもの）。
- **違うカードでカードは閉じる。** 違うカードのあと子どもはもう一度指さすので、どの直し方も「どこ、そしてどう」になります。代わりの案：カードを開いたままにする（1タップ少ないが、2回目に「どこ」の半分を飛ばす）。
- **「最初から頼み直す」ボタンはない。** ランタンを変えるのは指さしとカードだけで、直す指示がほかの部分に触れることはありません。やり直しボタンがあれば遅いことは分かりますが、やり直しをゲームが勧める選択肢にしてしまい、REQ-8.7.4 はそれをほのめかさないと言っています。対比は結果で伝えます。「そこだけ なおったよ」。
- **しずかな部分の指さしは無料。** 連続は途切れず時間も減りません。メッセージはその部分はだいじょうぶで、チカチカする部分をタップするよう言います。チカチカは画面に出ているので、しずかな部分のタップは指のすべりで、違う指示ではありません。代わりの案：連続を途切れさせる（すべりを罰する）、その部分のカードを開く（そこで直すと2つ目の部分が違ってしまい、「ほぼ正しい」ランタンでなくなる）。
- **指さした部分はチカチカを止める。** カードが開いている間、その部分は線の枠で静止します。子どもが「ここ」と言ったので、チカチカの役目は終わりです。直す前の部分の絵の指紋をスモークがとれるようにもなります。
- **得点が「全部のカードを試す」を教えない理由。** 正しいカードは連続に応じて100〜300で、違うカードは連続を途切れさせます。左のカードを先に、次にもう一方を選ぶ子もすべてのランタンを灯せますが、左がおねがいの見た目でなかったたびに連続を失います。シード0の最初の8ラウンドで、その子は1,000（右から試すと1,050）、8回とも正しいと1,900です。`reducer.test.ts` が3つの数を固定します。
- **表ではなく3進数のシード。** domain での乱数は ADR 0001 を壊し、モデル検査を無限にします。固定の表1つでは子どもが位置を覚えます。シードの3進数の桁と左右の2つの周期で多くの始まり方ができ、規則は確かめられ（どの部分も変わる、fault が動く、正しいカードの側が周期に従う）、周期は6ラウンドでモデル検査がそれを使います。最初の版は足す数をラウンドで交互にし、カードを見た目の順に並べていました。するとシード2では正しいカードがどのラウンドも右になりました（`docs/evidence/didnt-work.md`）。なので、カードは部分の見た目に続く順にし、側は周期から決めます。
- **3つの部分にそれぞれ3つの見た目。** 部分はランタンの上から3つの行にあるので、おねがいとウィスプのランタンを行ごとに見比べられます。見た目は6歳の子が助けなしで名前を言えるもの（わっか、リボン、すず。とんがり、まる、たいらのやね。ろうそく、ほし、つき）です。どの見た目も固有の形なので、色は意味を持ちません（ハードルール7）。ガラスの色を見た目にする案はそのため採りません。
- **灯ったときのメッセージが締めのことば。** 試練1と4には、締めのことばの専用パネルがあります。ここでは灯ったときのメッセージがすでに学びを言っており（「「まる」で ぴったり！ そこだけ なおったよ」）、2つ目のパネルはボタンを主人公の帯より下へ押し出してしまいます。メッセージは子どもが言ったことを名指しするので、ただの「よくできたね」ではありません。
- **日本語の「ちがう」。** `ちがう` は試練4の非難の一覧にあります。そこでは「まちがい」の意味になるからです。ここでは L5 の学びの言葉（「どこが ちがう？」）で、その1つの問いにだけ許し、content テストがほかのすべての文から締め出します。
- **タイトルの並びは上から試練5、4、3、2**。spec 07 の選び方を続け、古いボタンとそのテストをそのままにします。名前、カード、絵は88ピクセル上へ動きます（REQ-8.1.1、「共有の入口やイベントへの変更」）。代わりの案：小さいボタン（80 x 80 の下限を割る）、2列（ラベルと24文字の添え書きが190ピクセルに入らない）、試練選択画面（範囲外、REQ-8.1.5）。
- **1つではなく `TapPart` と `FixPart`。** 2つのイベントは指示の2つの半分です。両方を持つ1つのイベント（`Fix { part, look }`）だと1回のタップで「どこ」と「どう」を言えてしまい、学びは両方を言うことです。
- **`look` のIDは部分をまたいで一意。** `FixPart` は見た目だけを名指しし、部分は指さした部分です。ほかの部分の見た目は2枚のカードになく同じ状態を返すので、指さしていない部分を変えるイベントはありません。
- **新しいフェーズではなく `trial` で守る。** INV-1 は3つのフェーズのまま。
- **保護者向けの文はなし。** 保護者画面は範囲外です（`parents.*.json` は空のまま）。`docs/device-checklist.md` のプレイテストのメモに、保護者がランタンを「助手に何を変えてほしいか伝える」と結びつけるかを記録します。

## リスク

- 作成用のサンドボックスでは WebKit が起動しません（`docs/evidence/didnt-work.md`）。モバイルのスモークはそこで iPhone 13 のタッチプロファイルの Chromium で走らせ、そう書きます。本当の WebKit の実行は CI のものです。CI のスモークが緑になるまでタスクを完了とは呼びません。
- ピクセルのプローブは絵に依存します。プローブを動かすような枠、バッジ、ガラスの変更はスモークを失敗させます。プローブと絵は `lantern-layout.ts` を共有するので、数値は1か所で変わります。
- 絵はコードで、スクリーンショットを目で見て判断します。
- 子どもがおねがいを見ずにカードを順に押すかもしれません。そのとき学びはメッセージ（「〜って いったね」）と得点に頼ります。次のプレイテストでは、子どもがカードを選ぶ前におねがいを見るか、部分と見た目を声に出して言うかを記録します。
- 9つの見た目は少なめです。数回遊べば子どもは覚え、ゲームは判断より速さに報いるようになります。プレイテストでそう分かれば、手段は見た目か4つ目の部分を増やすことで、規則ではありません。

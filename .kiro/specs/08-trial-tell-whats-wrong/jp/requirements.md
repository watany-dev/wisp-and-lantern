## なぜ作るか

`docs/learning-design.md` は試練5を「TBD」のままにしていました。この spec はそこを L5「どこが ちがうか つたえる（Tell it what's wrong）」で埋めます。各ラウンドで、子どもには「おねがい」があります。カードに描かれたランタンで、とって・やね・あかりの3つの部分からできています。ウィスプは、1か所を除いてすべての部分がおねがいと同じランタンを持ってきます。違う1か所はチカチカします。子どもはチカチカする部分をタップし（どこ）、その部分のあるべき姿を示すカードを選びます（どう）。ウィスプはその部分を、カードのとおりの見た目に、それだけ変えます。カードがおねがいと同じならランタンは灯り、灯ったままになります。違えば、言われたとおりに変わったうえでまだチカチカし、子どもはおねがいを見てもう一度伝えます。そして次のランタンが来ます。

要点は、最初から頼み直すこととの対比です。ランタンはほぼ正しいので、子どもは新しいランタンを頼みません。指さしとひと言で直り、ほかの部分はそのままです。正しいカードは得点になり、続けて正しいほど増えます。違うカードは得点なしで連続が途切れます。なので、おねがいと見比べる子は、カードを順に試す子より高い得点になります。

ウィスプは言われたとおりにし、1か所だけ違うものを持ってきた助手です。うそつきでも敵でも、まぬけでもありません。試練の中に暗いもの、こわいもの、おどかすものはありません。

## 用語

- **ランタン（Lantern）**：試練5「The Flickering Lantern」の場所。ラウンドでウィスプが持ってきたランタンも指す。
- **部分（part）**：ランタンの3つの部分。上から **とって（handle）**、**やね（roof）**、**あかり（light）**。
- **見た目（look）**：部分のようす。各部分に3つずつ。とっては わっか・リボン・すず、やねは とんがり・まる・たいら、あかりは ろうそく・ほし・つき。全部で9つで、それぞれ固有の絵と言葉がある。
- **おねがい（wish）**：このラウンドで子どもがほしいランタン。ウィスプのランタンの隣に、別のカードに描かれる。
- **チカチカする部分（flickering part）**：ウィスプのランタンのうち、見た目がおねがいと違う1つの部分。チカチカし、点の枠がつく。ほかの2つは **しずかな部分（steady）**。
- **指さし（point）**：ウィスプのランタンの部分をタップすること。チカチカする部分を指さすとカードが開く。しずかな部分を指さすと「そこは だいじょうぶ」と返る。
- **カード（card）**：指さした部分について開く2つのボタン。見た目の絵と言葉がつく。その部分の、今の見た目ではない2つ。
- **直す（fix）**：子どもがカードを選ぶこと。ウィスプは指さした部分をカードの見た目に変え、ほかは何も変えない。**正しいカード** はおねがいの見た目で、ランタンが灯る。それ以外は **違うカード** で、部分は変わるがまだチカチカする。
- **灯る（lit）**：ランタンがすべての部分でおねがいと同じになった状態。光り、「つぎへ」まで灯ったまま。
- **ラウンド（round）**：ランタン1つ分。届いてから、灯ったあとの「つぎへ」まで。
- **ラン（run）**：試練5の60秒。タイトルのボタン（またはもう一度）のタップから時間切れまで。試練1と同じ `Run`（時計、得点、連続、そのセッションのベスト）を使う。
- **シード（seed）**：試練5を開くときにゲーム（domain ではない）が引く整数。同じシードなら、同じラウンドで同じおねがい、同じチカチカする部分、同じランタンになる。
- **連続（streak）**：続けて正しかったカードの数。違うカードで途切れる。正しいカードの得点は100に、連続1つにつき50を足したもの（4まで）。
- **終了画面（end screen）**：時計が0になったときの画面。得点とベスト、「もういちど あそぶ」と「タイトル」。

## 要件

### REQ-8.1 タップでランタンに入る

6歳の子として、指でタイトルからランタンを開きたい。大人がいなくても遊べるように。

1. タイトル画面に、試練5のための4つ目の追加の的がある。ランタンの絵と子どもの言語の短いラベルがついたボタンで、80 x 80 ゲームピクセル以上。影のボタンの上にあり、影のボタン、試練1のカード、タイトルのウィスプ、主人公と重ならない。
2. ボタンをタップすると試練5が開き、ランが始まる。状態は `title` から `trial` へ移り、`trial` は 5、新しいシードのラウンド0、時計は満タンの60秒、得点0、連続0。セッションのベストは引き継ぐ。レーン、小屋、畑、影には触れない。シードはゲームが（domain の外で）引いてイベントで送る。domain は何も引かない。
3. このボタンのタップで試練1が始まったり試練2〜4が開いたりすることはなく、ほかのボタンのタップでランタンが開くこともない。タイトルのほかの場所のタップは今までどおり試練1を始め、終了画面のもう一度ボタンは今までどおり自分の試練の新しいランを始める。
4. 入口はふつうの画面のふつうのタップ。審査用URL、隠しジェスチャー、コンソール操作、クエリパラメータではない。
5. 試練選択画面も汎用ルーターもない。新しい画面はランタンだけ。
6. タイトルのどの文も、その横にある試練に合っている。4つ目のボタンにもほかの3つと同じ添え書き `60びょうで いくつ？` / `How many in 60 seconds?` がある。ラベルには数字を入れない。

### REQ-8.2 画面に出るもの

1. 画面には、ランの上の段（残り秒、バー、得点。試練1〜4と同じ）、ガイド文、ラベル付きの専用パネルに描いたおねがい、その隣のラベル付きパネルに描いたウィスプのランタン、メッセージ、ウィスプ、「タイトル」ボタン（REQ-8.9.5）が出る。カードは部分を指さしている間だけ（REQ-8.5.1）、「つぎへ」はランタンが灯っているときだけ（REQ-8.6.3）出る。
2. ガイドは2行までの短い1文。1つの部分がチカチカしていること、それをタップして直し方を伝えることを言う。どの段階でも画面に残る。
3. おねがいとウィスプのランタンは同じ描き方、同じ大きさで横に並び、とって・やね・あかりが同じ行に来る。子どもは行ごとに見比べられる。
4. おねがいはいつも灯った姿で描く。子どもがほしいランタンだから。タップの的ではない。
5. ウィスプはどの段階でも画面にいて、いつものやさしい顔をしている。怒った顔、ずるい顔、こわがる顔、傷ついた顔にはしない。この試練ではタップの的ではない。

### REQ-8.3 1つの部分がチカチカする

1. どのラウンドでも、ウィスプのランタンはおねがいと2つの部分で同じで、ちょうど1つの部分（チカチカする部分）で違う。どの部分で、どの見た目かはシードとラウンドで決まる（REQ-8.8）。
2. チカチカする部分は、1秒に3回より遅く、薄くなっては戻る。
3. チカチカする部分は、動きや色だけでなく静止画でも示す。その部分のまわりに点の枠がある。しずかな部分には枠がない。灯るまで、あかりは暗い。
4. ゲームはランタンがどこで違うかを示すが、どうすればよいかは言わない。どの見た目が正しいかは、おねがいからだけ読み取る。

### REQ-8.4 部分を指さす

6歳の子として、どの部分が違うかウィスプに示したい。どこを直せばよいか分かるように。

1. ウィスプのランタンのどの部分も、80 x 80 ゲームピクセル以上のタップの的。
2. チカチカする部分をタップすると、そこを指さす。枠は線の枠になり、指さしている間はチカチカが止まり、その部分の2枚のカードが出て、メッセージがどの見た目にするかをたずねる。
3. しずかな部分をタップすると、その部分はだいじょうぶで、タップするのはチカチカする部分だと1文で伝える。カードが開いていれば閉じる。得点はなく、連続も途切れず、時間も減らない。
4. 指さしでランタンは変わらない。どの部分の見た目も、ラウンドも、得点も。
5. ランタンが灯ったあとは、部分をタップしても何も起きない。

### REQ-8.5 直し方を伝える

6歳の子として、部分をどうしてほしいかウィスプに伝えたい。その部分だけを直してもらえるように。

1. 部分を指さしている間、2枚のカードが画面に出る。それぞれ見た目の絵と言葉がつく。その部分の、今の見た目ではない2つで、今の見た目の次から3つを一回りする順に並ぶ（やねが まる なら たいら、とんがり の順）。ほかの段階では出ない。正しい見た目が左のラウンドもあれば、右のラウンドもある。
2. カードを押すことが、1回の直す指示。ウィスプは指さした部分を、カードのとおりの見た目にする。ほかの部分は変えず、別の見た目を選ばず、カードを直さず、新しいランタンも持ってこない。
3. 正しいカード（おねがいの見た目）でランタンが灯る（REQ-8.6）。得点になる（REQ-8.9.3）。
4. 違うカードでは、部分がその見た目に変わり、まだチカチカし（点の枠つき）、カードは閉じ、メッセージは子どもが言ったことと、まだチカチカしていることを伝える。得点はなく、連続は途切れる。子どもは回数の制限なく、時間も減らずに、もう一度指さして伝える。
5. 違うカードは大惨事でもこわい場面でもない。赤はなく、×も出ず、何も揺れず、音もない。短い演出は流れてよい（REQ-8.5.6）。
6. カードの結果は reducer がすぐ決める。アニメーションやタイマーを待たない。短い演出（部分がはねる、光る）は流れてよく、見なくても情報は失われない。

### REQ-8.6 ランタンが灯る

1. 3つの部分がすべておねがいと同じになると、ランタンは灯る。あかりは明るく、ガラスのまわりに光があり、枠はなくなり、何もチカチカせず、パネルの角にチェックのバッジがつく。
2. メッセージは子どもが言ったことと、その部分だけが直ったことを伝える。ほかの2つの部分には一度も触れていない。
3. 「つぎへ」ボタンで次のランタンが来る。ランの終わり以外に、灯ったランタンがひとりでに消えることはない。

### REQ-8.7 ウィスプは言われたとおりにした。責めない

1. 言葉は、ウィスプが何を持ってきたか、子どもが何を言ったかを伝える。ウィスプが間違っている、悪い、ばか、こわれている、うそをついているとは言わず、何かをわざとしたとも言わず、子どもも責めない。
2. 子ども向けの文に、内容テストの非難とこわがらせの言葉の一覧にある言葉を使わない（例："wrong"、"bad"、"mistake"、"oops"、"sorry"、"broken"、"silly"、"liar"、"scary"、"afraid"、"danger"、"monster" と、その日本語の対応語。一覧は `lantern-content.test.ts` にある）。「ちがう」（学びの言葉）は「どこが ちがう？」の問いにだけ使ってよい。
3. 事実は隠さない。違うカードのあと、メッセージはその部分がまだチカチカしていると伝える。
4. 最初から頼み直すようには決して言わない。言葉は部分と見た目を指す。「タップして」「どの？」「いったね」。
5. 助手はいつも正しい・いつも間違う、何でも知っている、友だちや家族だ、とは言わず、ほのめかさず、本物のAIがすることについて何も主張しない（`docs/learning-design.md`「教えないこと」）。本物の助手も言われたところだけを変えるというのは演出上の仕掛け（`design.md` 参照）で、ゲームの中で述べる主張ではない。

### REQ-8.8 ランタンとその順番

1. 3つの部分とそれぞれ3つの見た目は、純粋な domain の規則。おねがい、チカチカする部分、ウィスプがその部分に持ってきた見た目は、シードとラウンド番号だけから決まり（固定の規則。ほかの乱数はない）、ラウンドの間は変わらない。シードが変われば順番も変わる。
2. どのシードでも、おねがいは直前と同じにならない。どの部分の見た目も、ラウンドごとに変わる。
3. チカチカする部分はラウンドごとに動く。2ラウンド続けて同じ部分にはならず、3ラウンドごとにどの部分も1回ずつチカチカする。
4. ウィスプがチカチカする部分に持ってきた見た目は、おねがいでない2つの見た目のどちらか。どちらかで正しいカードが左右どちらに出るかが決まり、その左右は6ラウンドの2つの周期のどちらかに従う。どちらの周期も同じ側を3回続けず、単純に交互にもならない。なので「いつも同じボタン」も「ひとつおきのボタン」も遊び方にならない。

### REQ-8.9 60秒のラン、得点、帰り道

6歳の子として、1分でいくつランタンを灯せるか知りたいし、いつでもタイトルに戻りたい。また遊びたくなり、行き詰まったと感じないように。

1. 試練5は60秒のラン。試練1の `Run` を使う。入口で時計は満タンの60秒、得点0、連続0、セッションのベストは引き継ぐ。子どもが何をしていても時計は減る。時間は `Tick`（1フレームは最大250 ms）でだけゲームに入り、`Tick` は試練1〜4と同じく試練5でも働く。上の段に秒、バー、得点を出す。
2. ランタンが灯ったあと、「つぎへ」ボタンで次のラウンドが始まる。シードの次のおねがいと次のランタンで、何も指さしていない。試練を終えるのは時計だけ。
3. 得点。正しいカードは100に、それまでの連続1つにつき50を足す（4まで。100、150、200、250、300、300…）。違うカードは得点なしで連続が途切れる。指さしと「つぎへ」は得点なしで連続はそのまま。得点は reducer がすぐ決める。正しいカードでは得点（「+150」）がランタンから一瞬浮かぶ。上の段の得点がその記録。
4. 時間切れでは、どの段階（見ている、指さしている、灯った）でもすぐランが終わる。終了画面は試練1のもの。「おしまい！」、得点、セッションのベスト、ベストを超えたら「しんきろく！」。ボタンは2つ。「もういちど あそぶ」は試練5の新しいラン（満タンの時計、得点0、新しいシードのラウンド0、ベストだけ残す）を始め、「タイトル」。最後のすばやいタップでボタンが押されないよう、少しの間タップを受けない。
5. 「タイトル」ボタンは試練5の画面のどの段階にも、終了画面にもある。画面では 80 x 80（小屋のボタンと同じ場所）、終了画面では横長。タイトルへ戻る。`phase` は `title`、`trial` は 0、試練5は初期値、ランはベストだけ残して始め直す。ほかは何も変わらず（言語と主人公はそのまま）、そこから試練1〜5がいつもどおり開く。
6. 試練から戻った直後、タイトルは0.7秒タップを受けない。「タイトル」の2度押しで試練1が始まらないように。
7. 行き詰まらない。試練5のどの状態（見ている、指さしている、灯った、終了画面）からも、画面自身のボタンと部分で、チカチカする部分の指さし、違うカード、灯ったランタン、次のラウンド、2つ目の灯ったランタン、終了画面、タイトルに届く。時計と「タイトル」ボタンがなくても、ランタンを灯して次のラウンドへ進める。
8. 得点が「速くタップ」や「全部のカードを試す」を教えない理由。正しいカードは連続に応じて100〜300で、違うカードは連続を途切れさせる。カードを順に試す子もすべてのランタンを灯せるが、おねがいと見比べる子より得点は低い。シード0の最初の8ラウンドで、左のカードから試すと1,000、右からだと1,050、8回とも正しいと1,900（`design.md` の Decisions）。

### REQ-8.10 試練どうしは混ざらない

1. 試練5に入っても、ほかの試練のランは始まらず、`lane`、`shed`、`field`、`shadows` とほかの試練の `run` の状態はタイトルのときのまま。`trial` が 5 でないとき、`lantern` は初期値。
2. 表示するシーンは `trial` で決まる。1 はレーン、2 は小屋、3 は畑、4 は影、5 はランタン。`trial` が 5 の状態でほかの試練のシーンは出ない。
3. 試練5では、試練1〜4のイベント（`Ask`、`PickCard`、`Retry`、`PickTool`、`GiveTool`、`RetryShed`、`LeaveShed`、`InspectStar`、`SortStar`、`KeepStars`、`RetryField`、`LeaveField`、`DecideItem`、`NextItem`、`LeaveShadows`）は同じ状態を返す。試練5のランの外（終了画面を含む）では、ランタンのイベント（`TapPart`、`FixPart`、`NextLantern`）は同じ状態を返す。`LeaveLantern` は試練5（ランかその終了画面）でだけ、`StartLantern` はタイトルと試練5自身の終了画面からだけ受ける。
4. 試練5のラン中の `Start` は言語だけを変える。試練5の終了画面では試練1を始め、試練5の状態を捨てる。`SetLang` は言語だけを変え、部分もカードも結果も変えない。`MoveHeroTo` は主人公だけを動かす。
5. 保存するのは子どもがしたこと。おねがい、チカチカする部分、ウィスプが持ってきたランタンはシードとラウンドから導き、保存しない。ランタンが灯っているかは部分から決まる。
6. 試練1〜4のふるまい、文言、配置、テストはこの spec で変わらない。ただし、タイトルの名前・カード・絵の位置と、そこから決まる固定値は除く（「共有の入口やイベントへの変更」を参照）。

### REQ-8.11 縦画面、1本指、マウス

1. 試練5は既存の 390 x 844 の縦キャンバスで遊ぶ。
2. どの操作も、80 x 80 ゲームピクセル以上のものへの1回のタップかクリック。タイトルの試練5ボタン、ウィスプのランタンの各部分、各カード、「つぎへ」、「タイトル」ボタン、終了画面の2つのボタン。ドラッグ、長押し、ダブルタップ、2本目の指はない。
3. 主人公の床ドラッグは試練5でも主人公を動かす。部分やボタンから始まった押下では主人公は動かず、床での押下では動く。
4. 文と絵は互いに重ならず、おねがい、ランタン、メッセージ、ボタンを隠さない。すべての段階（見ている、指さしている、灯った）で、上の段と「タイトル」ボタンがあっても、両方の言語で、どの部分の言葉と見た目の言葉を入れても。ボタンは主人公のスタート位置より上で終わる。
5. 新しいボタンの組は出てから少しの間（450 ms）押しても反応しない。すばやい2度押しで、カードや「つぎへ」がうっかり押されないように。

### REQ-8.12 コードで描く、通信なし、色なし、音なし

1. ランタン、その部分、枠、光、バッジ、カードの絵は、端末のピクセル比でコードで描き、既存の見た目に合わせる（REQ-4.9〜REQ-4.11）。画像ファイルは足さず、第三者の絵も使わない（ハードルール5）。
2. 試練5は、ページと同梱フォントの読み込み後、日本語でも英語でも通信を必要としない（ハードルール4）。指さし、直す、つぎへ、時間切れ、帰り道までの通しの遊びが、通信を切っても動く。
3. 動きだけで意味を伝えず、1秒に3回より速く点滅せず、見なくても情報は失われない。どの状態も静止画で伝える。点の枠、線の枠、チェックのバッジ、明るいあかり。
4. 9つの見た目は色ではなく形と言葉で区別する。色をすべて取り除いた画面でも別の形で別の名前を持ち、枠、バッジ、あかりも読める。
5. ゲームは音を出さず、何も音を必要としない。スモークで何も鳴らないことを確かめる。

### REQ-8.13 日本語と英語、文言は content に

1. ガイド、2つのパネルのラベル、メッセージ、部分の言葉、見た目の言葉、ボタンのラベル、タイトルのラベルと添え書きは、すべて `src/content/strings.ja.json` と `strings.en.json` に同じキーで置く。`src/game/` と `src/domain/` に子ども向けの文字列は書かない。
2. 日本語は `npm run kid` でハードルール2に従う。ひらがなとカタカナだけ、1行12文字・2行まで。部分や見た目の言葉を入れたあとも同じ。英語のメッセージは短い2行まで。
3. 言葉を1つとるメッセージは、ちょうど1つとり、置き換え忘れのプレースホルダーを残さない。
4. 言語は既存のもの（`?lang=ja|en`、なければブラウザの言語、なければ英語）。`SetLang` でいつでも変えられ、言葉が変わり、ほかは何も変わらない。
5. 文言を変えたあと `npm run kid` と `npm run font` が通り、サブセットフォントがすべての文字を含む。

### REQ-8.14 純粋な規則を、いくつもの方法で確かめる

1. 部分とその見た目、おねがい、チカチカする部分、指さし、直す、ランタンが灯るか、得点、次のラウンド、時計、帰り道は、純粋な reducer の規則（ADR 0001）。`src/domain` は Phaser、DOM、時計、乱数を使わず、結果は言語やアニメーションのタイミングに左右されない。シードはイベントの値で、同じシードと同じイベントからはいつも同じ状態になる。
2. INV-54〜INV-62 と、試練5についての INV-15〜INV-17（下）は、それぞれ実際の reducer に対する `checkProperty` のプロパティテストを持つ。生成器はすべての部分を指さし、すべてのカード（正しい、違う、ほかの部分の見た目）を選び、灯る前とあとに「つぎへ」を押し、ほかの試練のイベントを使い、時計を使い切り、もう一度遊び、帰り、たくさんのランタンを回る。INV-3 と INV-4 も新しいイベントを含む列で走らせる。
3. 単体テストで確かめること。部分と見た目、いくつかのシードのおねがい・チカチカする部分・ランタンの固定値、100個のシードでおねがいが続けて同じにならずチカチカする部分が動くこと、チカチカする部分としずかな部分への指さし、両方のカード、ほかの部分のカード、指さし以外での直す指示、灯る前とあとの「つぎへ」、正しいカードと違うカードの得点と連続（100、150、200、250、300）、時計、どの段階での時間切れ、終了画面からのもう一度（ベストは残る）、すべての段階と終了画面からの帰り道とそれ以外では何も起きないこと、タイトルからの入口。content と view では、日英の同じキー、プレースホルダー、長さ、非難・こわがらせ・主張がないこと、カードは指さし中だけ、「つぎへ」は灯ったときだけ、段階ごとの枠・バッジ・あかり、試練5の終了画面の2つのボタン、段階に合ったメッセージ。
4. 実際の reducer に対するモデル検査（`lantern.model.test.ts`）は、タイトルから2つのシードで入る入口とそのあとの試練5を対象にする。有限のアルファベットは、すべての指さし、すべてのカード、ほかの試練の無効なイベント、短い `Tick` とランを終わらせる `Tick`、`Start` と言語の変更を含む。状態がいつも子どもがしたことの独立な記録と合うこと（子どもが言った見た目がその部分の見た目であること）、灯るまでランタンはちょうどチカチカする部分でおねがいと違うこと、正しいカードのあとでだけ灯ること、時計とフェーズが合うこと、得点は正しいカードでだけ連続に応じた点だけ動くことを確かめる。到達できるどの状態からも、指さし、違うカード、灯ったランタン、次のラウンド、2つ目の灯ったランタン、終了画面、タイトルに届く（時計と「タイトル」ボタンがなくても、灯ったランタン、次のラウンド、2つ目の灯ったランタンに届く）。状態の数と、わざと壊したときの反例を記録し、通すために状態を捨てない。
5. ミューテーションテストで、単体テストされたコードに生き残るミュータントがない。

### REQ-8.15 本物のタップと本物の画面

1. モバイルのスモークは、本物のタップ（`dispatch` ではなく）でタイトルから試練5に入り、遊ぶ。しずかな部分のタップ（メッセージが出て、何も変わらない）、チカチカする部分のタップ（線の枠、2枚のカード）、違うカード（得点なし、連続が途切れ、部分が変わり、まだ点の枠）、正しいカード（得点、ランタンが灯り、チェックのバッジ、明るいあかり、部分が変わる）、「つぎへ」で次のランタンが来てチカチカが別の部分に移る、時間切れで終了画面、「もういちど あそぶ」でベストを残して次のランが始まる、ランの中と終了画面から「タイトル」でタイトルへ戻り、すばやい2度目のタップで試練1が始まらない。`window.__game` は状態を読むためだけに使い、タップでできることには使わない。`dispatch` はボタンのない `Tick` にだけ使う。
2. スモークは状態だけでなく画面を確かめる。枠（点か線か）、チェックのバッジ、あかり、カード、「つぎへ」、時計、得点、メッセージをピクセルで見る。「灯った」と言う状態であかりが暗ければ失敗する。
3. 始め、指さし、違うカード、灯ったランタン、終了画面の日本語と英語の画面、両言語のタイトルをスクリーンショットで見る。デスクトップのスモークはマウスでランタンを遊び、部分の長押しで主人公が動かないことを確かめる。初回読み込みのあと通信を切っても、両方の言語で通しの流れが動く。
4. 試練5は本物の時計で遊ぶので、どのスモークテストもランの半分よりずっと短く遊ぶ。時計を越える必要があるテストは、ほかの試練と同じく `Tick` でランを終える。スコアアタックを含む試練1〜4のスモークも通る。タイトルの試練5ボタンはそのどれも始めず、タイトルのほかの場所のタップは今までどおり試練1を始める。

### REQ-8.16 どのゲートも弱めず、確かめたことを言う

1. しきい値、設定、チェックスクリプト、ワークフロー、既存のテストを、通すために緩めたり消したりしない。この spec のために古い期待を変える必要があるときは、`tasks.md` に古いテストと新しいテスト、試練1〜4が弱くならない理由を書く。
2. どのタスクでも `npm run check` が通る。入力と画面をつなぐタスクは `npm run build` と続く `npm run smoke` も通る。
3. スモークはモバイルの WebKit とデスクトップの Chromium が対象。作成用のサンドボックスで WebKit が起動しない場合は、モバイルのスモークを iPhone 13 のタッチプロファイルの Chromium で走らせたと結果に書き、CI の WebKit の実行を正とする。CI のスモークが緑になるまで完了とは言わない。Playwright の実行を本物の電話での確認とは呼ばない。走らせていないテスト、フック、エージェントを走らせたとは書かず、Result の行には測ったことだけを書く。

# Structure

## Layout

- `src/domain/` — pure reducer over `GameState` + `GameEvent`. No Phaser, no DOM, no `Date.now()`,
  no `Math.random()` without an injected RNG. Balance constants live in `balance.ts`.
- `src/game/` — Phaser scenes, input, effects. Renders state and dispatches events; never mutates state.
  `scenes/`, `fx/`, `ui/`, `boot.ts` and `main.ts` are excluded from coverage and mutation testing, so
  lint holds them to 30 lines per function and complexity 5. Put math, hit tests and string selection
  in a plain module next to them (for example `steer.ts`) and unit-test it.
- `src/content/` — all player-facing text and cards (JSON). No player-facing literals in `src/game/`.
- Property tests call `checkProperty(name, property)` from `src/domain/__tests__/support/pbt.ts`. When one
  fails, commit the reported `seed` and `path` to `support/pbt-regressions.json` together with the fix.
- `checkModel` (`src/domain/__tests__/support/model-check.ts`) visits every state the reducer can reach
  through a small event alphabet, checks invariants and that the goal is always still reachable (no
  soft-lock), and reports the shortest event trace to a bad state. Each trial gets a `*.model.test.ts`.
- Named domain invariants (`INV-n`) are listed in `.kiro/steering/domain-invariants.md`; each one is
  referenced by a test in `src/domain/__tests__/*.pbt.test.ts`.
- `e2e/` — Playwright smoke. Tests navigate with relative URLs (`page.goto("./?judge=1")`) and read
  state through `window.__game`. Scenes are excluded from coverage and mutation testing (ADR 0003), so
  the smoke is the only automated check of input handling. The mobile smoke (iPhone 13 profile, touch)
  drives the game with real taps and drags (`locator.tap()`, touch events), never by dispatching the
  event the input would produce. Each trial that lands gets one mobile smoke that plays it through
  taps and drags. Use `dispatch` from `e2e/helpers.ts` only to set up state that has no UI yet.
- `scripts/` — repository gates (`check-*`), tools (`subset-font.mjs`, `metrics.mjs`) and hook
  scripts (`evidence-log.sh`, `bootstrap-ptuf.sh`). `scripts/__tests__/` runs every gate against fixtures.
- `.kiro/` — specs (`specs/<spec>/requirements.md`, `design.md`, `tasks.md`), steering, hooks,
  agents, skills. See `.kiro/skills/README.md` for `/kick` and `/wrapup`.
- `.kiro/specs/<spec>/jp/` — the Japanese translation of that spec (`requirements.md`, `design.md`,
  `tasks.md`). The English files are the source of truth: change the translation in the same pull
  request as the English file. Identifiers, paths, commands and ids (`REQ-n.m`, `INV-n`) stay as in the
  original. Japanese is allowed there through `scripts/check-cjk-allowlist.txt`; `check-trace` reads
  only the English files.
- `.kiro/agents/` — `reviewer` (diff review for the PR's Reviewer section) and `kid-reader`
  (reads child-facing strings as a 6-year-old would).
- `.kiro/hooks/` — `evidence-log.json` appends a record to `docs/evidence/kiro-log/` when the agent
  stops. `ptuf.json` installs ptuf when a session starts and checks every tool call against
  `.ptuf.yaml` before it runs.
- `docs/adr/` — architecture decisions. Add a record when a change reverses or extends one.
- `docs/evidence/` — records of how the game was built. `metrics.md` is generated by
  `npm run metrics` and is the only source for numbers in the write-up.
